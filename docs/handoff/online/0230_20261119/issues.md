# 운영 점검에서 관찰한 문제

심각도는 온라인 점검 세션의 **전달 우선순위**다. 구현 티켓의 최종 판정은 평가 세션이 한다. 모든 재현은 배포 `32d9c485bc04ef0487fc4c6a32a91c9d39d29948`에서 수행했다. 원본 사건 문구·Drive 식별자는 공개하지 않는다.

## I-1. Drive 일부 페이지가 읽히지 않은 채 동기화가 부분 완료됨 — P2

- 재현: 서면9 개발 자료(3쪽)를 새 프로젝트에 업로드하고 같은 SHA에서 3회 분석한다. 새로 만든 합성 기능 서면(432자), 모순 서면(253자), 대용량 서면(35,674자)에서도 결과 상태를 본다.
- 기대: 참고자료 색인이 완독되어 건강 명세 `H-REF`가 충족되고 분석이 완료 상태가 된다.
- 실제: 서면9 3회 모두 `PARTIAL_COMPLETED`, `H-REF` 미충족. 첫 실행은 색인 35/41, Drive 읽기 시간 초과와 동기화 예산 소진·파일 보류가 있었다. 두 번째와 세 번째는 41/41개 색인됐지만 7개 자료에 `REFERENCE_PARTIALLY_READ`가 남았다(해당 자료의 보고된 합계 2,636쪽 중 2,599쪽 읽음). 합성 3개 실행도 부분 완료였다.
- 영향·원인 확인: 일부 참고자료의 검색 범위가 누락될 수 있다. 이번 결과만으로는 Drive API, 파서, 실행 예산 중 어느 것이 주원인인지 확정할 수 없다. 페이지별 재시도·체크포인트·색인 완독 판정을 분리해 원인을 측정할 필요가 있다.

## I-2. 관련 지지 자료가 선별됐으나 지지 의견이 생성되지 않음 — P2

- 재현: 같은 3쪽 서면9 자료를 동일 배포에서 3회 분석하고 `case9_state_compensation_rag_controls_online.json`의 5항목을 대조한다. 입력 규모는 PDF 3쪽, Drive 조회 대상 41개다.
- 기대: 관련 지지 자료가 선별되고 그 자료와 입력 주장 사이에 최소 한 건의 `SUPPORTS` 의견이 생성된다.
- 실제: 세 번 모두 `RAGC-S1`(선별)은 충족, `RAGC-S3`(지지 의견)은 미충족이었다. 무관 자료 선별 금지와 거짓 모순 금지 항목은 충족했다. 전체 RAG 의견에는 `SUPPORTS`가 있을 수 있으나 **목표 지지 자료와 목표 주장**의 관계로 나오지 않았다.
- 영향·원인 확인: 사용자가 기대하는 지지 근거가 빠진다. 선별 이후의 주장 연결, 발췌 범위, 관계 생성 단계를 로그로 분리해야 한다. I-1의 자료 부분 읽기가 원인인지 이번 결과만으로 단정하지 않는다.

## I-3. 법리 서술의 날짜가 Time Table에 포함됨 — P2

- 재현: `docs/handoff/online/materials/v1/synthetic_features.docx`(본문 432자와 합성 표)를 새 프로젝트에서 분석하고 Time Table 첫 행을 확인한다.
- 기대: 당사자 사실관계의 날짜만 표에 표시되고 법리·선례 설명에만 나온 날짜는 제외된다.
- 실제: 합성 법리 설명 문장의 선례 선고일이 Time Table 1행으로 표시됐다. 당사자 사실관계의 날짜 행도 표시됐다. [합성 화면 캡처](captures/tk206_timeline_features.png).
- 영향: 사건 연표에 법리 참고 시점이 섞여 사용자에게 사실 사건으로 보일 수 있다.

## I-4. 공식 Source 실연동의 정확 사건 조회 실패 — P2

- 재현: `main`의 동일 SHA에서 `live-source-check.yml`을 `with_llm=true`, `strict=true`로 실행하고 정확 사건번호 조회 항목을 본다. 이 시험은 온라인 서면 입력과 별도의 GitHub Actions 실연동이다.
- 기대: 시험 명세의 정확 사건 1건이 공식 DB에서 일치 기록으로 돌아온다.
- 실제: 응답 상태는 `READY`였으나 정확 일치 0건이었다. 다른 사건을 대용으로 채택하지 않았다. [실행 로그](https://github.com/stevelee0119/ACASia_LAW/actions/runs/44396919559).
- 영향·원인 확인: 실재하는 판례를 공식 DB 미확인으로 남길 수 있다. 소스 색인 범위·검색 파라미터·일시적 응답 문제를 나누어 재측정해야 한다. 서면9의 일반 공식 DB 조회 21건·재시도 실패 0건과는 다른 세부 사례다.

## I-5. 실연동 워크플로의 비기본 구형 Gemini 시험 2건이 HTTP 404 — P3

- 재현: I-4와 같은 GitHub Actions 실행의 모델별 시험을 확인한다.
- 기대: 워크플로의 선택 모델 시험이 사용 가능한 모델만 호출하거나, 사용할 수 없는 구형 모델을 별도 호환성 경고로 분리한다.
- 실제: `gemini-2.5-flash`, `gemini-2.5-flash-lite` 두 시험이 HTTP 404였다. 현재 운영 기본 `gemini-4-hydrogen`과 다른 모델이다. 운영 서면9의 Gemini 호출 실패는 관찰되지 않았다. 워크플로 strict 결과는 실패다.
- 영향: 비기본 모델 점검으로 전체 strict 점검이 실패하며 실제 운영 기본 모델 상태를 해석하기 어렵다.

## I-6. Semantic Scholar 외부 호출 rate limit — P3

- 재현: I-4와 같은 GitHub Actions 실연동 실행에서 공개 학술 소스 항목을 본다.
- 기대: 외부 출처가 응답하거나 속도 제한을 받았을 때 재시도·유보를 구분해 표시한다.
- 실제: 자동 재조회 후에도 `RATE_LIMITED`였다. 운영 서비스의 사용자 화면에서 이 소스의 효과는 별도로 확인하지 않았다.
- 영향: 해당 외부 출처의 근거가 일시적으로 확보되지 않을 수 있다.

## I-7. 반복 실행 중 참고자료 라이브러리 상태 변화 — P3

- 재현: 서면9를 3회 실행하고 `scripts/ai_repeat_summary.py`로 조건 해시를 비교한다.
- 기대: 같은 조건 반복 시험에서는 참고자료 라이브러리 해시가 같고 비교 가능 일치율이 계산된다.
- 실제: 세 판정 모두 `AI_PARTIAL_GENERATION`이지만 도구가 `reference_library` 차이로 `condition_status=DIFFERENT`, `comparable_agreement=null`을 냈다. 첫 실행 35/41개 색인, 이후 41/41개 색인과 부합한다.
- 영향: 3/3의 외형상 동일 판정을 같은 조건의 안정성 성적으로 쓰지 못한다. 다음 반복 시험은 Drive 스냅샷과 색인 완료 상태를 먼저 고정해야 한다.
