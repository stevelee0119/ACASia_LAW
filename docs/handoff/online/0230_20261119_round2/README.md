## 이번 회차의 핵심 근거

- **TK75:** 운영 API prompt는 OFF 상태에서 `v0.2`, 세 서면9 보고서의 worker `korean_law_review_profile=false`였다. ON 상태의 prompt는 `v0.2+kr2`, worker 설정은 `true`였다. 설정 변경 중 시작한 사전 실행 1건은 `EXECUTION_SETTINGS_CHANGED`로 실패해 점검 점수에서 제외했다. OFF 3회와 ON 2회는 같은 `reference_library` 해시를 썼지만 라이브러리 상태는 `PARTIAL`이다. 첫 ON의 RAG 단계가 `OperationalError`로 끝나 21/23이었다. 정상 완료된 ON 재실행은 23/23이고 OFF와 항목 차이 0이다. [23항목별 참·거짓과 조건](result.json).
- **입력 문서 보호:** 서면9 표준 명세의 위장 지시문 항목 `INJ-1`은 OFF 세 회차 모두 충족했다. 기존 0.22.0의 본문·메타데이터·숨김·인코딩 네 형식 공격 전체를 이번 회차에서 다시 실행한 것은 아니다.
- **TK-208:** 첫 사전 동기화는 40/41개, 두 번째는 41/41개 색인됐다. 최종 집계는 총 8,823쪽 중 8,807쪽 완료, 실행 미완료 16쪽(예산 11·OCR 저품질 5)이다. 확인된 빈 쪽 146쪽은 완료로 분류됐다. 7개 부분 읽기 자료의 미완독 16쪽은 두 번째 동기화에서도 그대로였다. 두 번째에 이 7개가 모두 재사용되어 해당 자료의 쪽 단위 이어 읽기는 관찰되지 않았다. 자료별 쪽 수·사유는 식별자를 뺀 [쪽별 집계](tk208_per_reference.json)에 있다. 서버 임시 캐시의 완료 후 삭제는 API에서 확인할 수 없었다.
- **TK-209:** 목표 자료의 주장별 발췌는 각 회차에 4번, `387/387자`, 오프셋 `0–387`로 전달됐다. 목표 자료에 대해 모델 원응답은 `SUPPORTS` 0건이며 `CONTEXT` 또는 `INSUFFICIENT`였다. 따라서 목표 지지 의견이 화면에서만 사라진 것으로 볼 근거는 없다. 본문·파일명·ID가 없는 [3단계 진단](tk209_diagnostics.json)에 건수와 오프셋을 보존했다.
- **TK-206:** 합성 서면에서 선례 날짜는 Time Table에서 빠지고 당사자 사실 날짜는 6행 남았다. [합성 화면](captures/tk206_timeline_preflight_synthetic.png). 실제 서면9 세 실행은 각각 3행으로 재판행위 날짜 행 0, 사고 종류 행 1이었다. 다만 법률 시행일 서술 형태의 비사실형 행 후보 1개가 남아, 사실관계 중심 Time Table 전체가 해결됐다고 보기는 어렵다. 별도 실제 서면의 운영 화면은 1행, 재판행위 날짜 행 0이었다. 실제 서면의 행 문구·사건 값은 공개하지 않는다.
- **TK-198:** [소형 화면](captures/tk198_scope_preflight_synthetic.png)과 [대용량 화면](captures/tk198_scope_large_synthetic.png)에 규칙·모델 범위가 표시됐다. 대용량 보고서의 `coverage` 필드도 모델 `24000/35771`, 규칙 `35771/35771`, 표본 방식 `head_middle_tail`, 모델 실행 `true`와 일치한다. 검증한 화면 상태는 전수·표본 두 종류이며, 모델 미실행 상태의 범위 표시는 이번에 측정하지 않았다.
- **TK-210:** 동일 main에서 읽기 전용 `live-source-check.yml` 1회([실행](https://github.com/stevelee0119/ACASia_LAW/actions/runs/44464122735)). strict 종료 코드 1, 치명 실패 1(기존 공식 사건 정확 조회), 공개 Source 경고 2, 구형 비기본 모델 참고 경고 2. 운영 기본 공급자 직접 호출 3건과 cascade 4건은 성공했다.
