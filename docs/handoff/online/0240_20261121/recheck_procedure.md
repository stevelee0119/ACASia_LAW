# 0.24.0 신규 기능 미측정 경로 재점검

2026-11-21 운영 main `684f3469028dc38e539345501191cc7c9832b13a`에서 추가로 실행했다. 수치와 입력·보고서 해시는 [재점검 JSON](recheck_result.json)에 있다. 전용 시험 프로젝트 2개는 원본 증거를 비공개 ZIP에 보관하고 휴지통 이동을 확인했다.

## 다음 평가의 실행 조건과 합격 기준

1. **Legal NLI assist.** 공식 DB가 판결문 본문을 반환하는 공개 판례 1건을 먼저 확보하고 본문 해시·인용 구간 오프셋·조회 상태를 기록한다. 같은 공식 문구의 정확 인용, 부정 반전 인용, 상대방 전언을 각각 한 문서로 만든다. 운영 기본 `shadow`에서 기존 판정을 유지하고 Stage2가 실행됐는지 본 뒤, 별도 승인된 시험 배포의 `assist`에서 의도한 반전만 판정이 달라지는지 비교한다. 공식 본문이 없거나 Stage2 실행 기록이 없으면 품질 점수를 내지 않는다.
2. **적응형 OCR 폴백.** 동일 내용의 깨끗한 스캔과 저품질 스캔을 두고 1차·폴백 엔진의 설치·유효 설정을 배포 진단에서 확인한다. 엔진판, 페이지별 신뢰도, 폴백 호출·채택·거부 사유를 보고서에 남긴다. 저품질 쪽에서 품질이 실제로 개선되고 정상 쪽에서는 폴백이 불필요하게 채택되지 않아야 한다. 이번 저품질 입력의 `OCR_LOW_QUALITY`를 폴백 성공으로 계산하지 않는다.
3. **로컬 모델.** 전용 시험 환경에서 접근 가능한 로컬 추론 서버와 모델을 등록하고 진단에 로컬 공급자가 표시되는지 확인한다. JSON Schema 준수, 잘림·오류, 토큰 계측, 동일 입력의 응답과 비용을 실제 호출로 기록한다. 클라우드 공급자로 자동 대체된 실행은 로컬 모델 성공에서 제외한다.
4. **카세트 운영 경로.** 공식 Source의 비식별 공개 질의로 `LIVE`·`RECORD`·`REPLAY`를 각각 실행한다. 같은 요청의 본문 해시 일치, 재생 중 네트워크 호출 0, 카세트 미스·해시 변조·만료의 차단, 인증정보·개인정보가 저장되지 않았는지 확인한다. 운영 서비스에서 모드를 바꾸는 시험은 서비스 사용자에게 영향을 주므로 별도 시험 배포나 명시된 운영 변경 창에서 진행한다.

매 기능의 사전 점검표에 **필수 입력 존재, 유효한 실행 설정, 실제 경로 호출 건수, 양성·음성 대조, 공개 가능한 근거 해시, 프로젝트 정리**를 넣는다. 필수 조건을 만족하지 못하면 실행 전에 `미측정` 사유를 기록하고 해당 항목의 성공 점수를 만들지 않는다. API와 worker 설정의 유효값을 비밀값 없이 노출하는 진단 필드가 없으면 운영 측의 설정 추정도 성공 근거가 될 수 없다.
