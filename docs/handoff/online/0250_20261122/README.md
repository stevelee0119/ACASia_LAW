## 신규 기능과 설정 효과

- **Legal NLI `assist`:** 운영 진단과 worker 실행 기록 모두 `assist`였다. `case9`의 인용에는 공식 전문이 없어 Stage 2 실행은 0건이다. 별도 합성 입력 3개에서는 공개 판례 전문 30,211자를 실제 확보해 Stage 2가 각각 1회 실행됐다. 정확 인용은 Stage 2 `SUPPORTED`·최종 `VERIFIED`였다. 의미를 뒤집은 인용은 최종 1차 대조가 `CONTRADICTED`로 잡았지만 Stage 2는 `SUPPORTED`로 잘못 분류했다. `assisted_count`는 0이다. 따라서 `assist`의 증분 정확도 향상은 입증되지 않았고 반전 인용 오분류를 수정해야 한다.
- **절 정규화·근거 그래프:** `case9`에서 정규화 46절, 그래프 노드 114개·연결 70개를 관찰했다. 0.24.0과 수치가 같다. 이 수치는 실행 여부이며 법률적 정확도 점수가 아니다.
- **적응형 OCR:** 정상 스캔은 Tesseract 신뢰도 0.89로 채택됐다. 저품질 스캔은 0.611로 분류됐으나 `FALLBACK_NOT_CONFIGURED`여서 폴백 시도·채택 0건이다. 결정 사유 기록은 작동하지만 저품질 복구는 운영에서 실행되지 않았다.
- **Hybrid RAG·로컬 모델:** 운영 진단의 실제 검색 모드는 `LEXICAL_ONLY`, 로컬 모델 등록은 0개다. 임베딩·재순위 서버가 준비돼 있어도 현재 코드는 주소 환경변수를 실제 어댑터 생성에 쓰지 않고, 로컬 공급자는 기본 설정에서 비활성이다. 품질·속도 개선으로 계산하지 않았다.
- **공식 Source:** 같은 SHA의 GitHub strict 실연동 점검에서 사건번호 정확 조회 1건은 공급자 원응답 3건을 받았으나 일치 후보 0건으로 남았다. 학술 1건은 `RATE_LIMITED`다. 그 워크플로의 기본 모델 직접 호출 3/3, 연쇄 호출 4/4, 합성 통합 항목 7/7은 성공했다.
- **입력 문서 보호:** `case9`의 `INJ-1`은 4회 모두 충족됐다. Drive 자료는 검증 판단의 기준 자료로 사용했다. 0.24.0의 별도 공격 4형식 결과는 이번 실행에서 재측정하지 않았으므로 이번 점수에 합산하지 않았다.

## 다음 조치

[결함·개선 요청](issues.md)의 RAG 검색 중단과 NLI 반전 오분류를 우선 처리한다. OCR 폴백 패키지 설치, Dense·Reranker 실제 연결, 로컬 모델 등록은 환경변수 설정만으로 완료되지 않는다. 보완 뒤에는 같은 서면·Drive 해시·환경 모드에서 표준 23항목과 RAG 5항목을 3회 연속 재측정하고, NLI 정확·반전 쌍과 OCR 정상·저품질 쌍을 다시 실행한다.

평가 전용 프로젝트 7개는 원본 보고서·입력을 비공개 ZIP에 보관하고 무결성을 확인한 뒤 모두 휴지통으로 옮겼다. 활성 목록 제외와 휴지통의 삭제 시각을 전수 확인했다. 영구 삭제는 수행하지 않았다. 비공개 ZIP SHA-256은 `4e2fac5c0f29196045ee690d5aafd7d3698411b604282b4da67ef70f3865ec16`이다.
