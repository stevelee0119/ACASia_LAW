# 0.25.0 운영 점검 결함·개선 요청

이 문서는 운영 관측과 저장소 코드 읽기로 확인한 범위만 기록한다. 제품 수정과 최종 수용 판정은 담당 세션에서 수행한다. 입력 원문·Drive 식별자·인증정보는 포함하지 않는다.

## I-1 · P1 · RAG 검색 제한 초과가 문서 대조 전체를 중단

- **재현:** 같은 공개 합성 서면, 같은 Drive 스냅샷(`11922706a8a6…`), 41/41 색인 상태에서 검증을 네 번 실행했다. 두 회차는 `reference_review` 약 5.1초에 `OperationalError: interrupted`, 두 회차는 약 265초·312초에 완료됐다. 한 실패 회차는 재배포를 가로질렀고, 다른 한 실패 회차는 안정된 배포에서 발생했다.
- **기대:** 검색 한 단계가 제한 시간을 넘더라도 가능한 근거를 제한된 범위에서 재검색하거나, 미완료 범위를 명시해 결과에 남긴다. 전체 RAG 대조가 예외 하나로 빠지지 않아야 한다.
- **실제 사용자 영향:** 실패 회차는 표준 21/23(`RAG-1`, `RAG-2` 실패), RAG 대조 3/5, 건강 5/6(`H-ENGINE` 실패)였다. 근거 자료가 존재해도 모순·지지 검토가 제공되지 않는다.
- **원인 범위:** `packages/rag_engine/library.py`의 SQLite 조회에는 5초·3초 progress handler 제한이 있고, 예외가 `packages/verification_engine/pipeline.py`의 문서 RAG 단계까지 전파된다. 보고서의 실제 예외 메시지가 `interrupted`이고 실패 시간도 약 5초다. 어느 개별 조회가 제한을 넘었는지는 운영 로그에 없어 확정하지 못했다.
- **보완 수용 기준:** 제한 초과의 조회 종류·소요 시간·후보 건수를 개인정보 없이 기록한다. 동일 입력·동일 스냅샷에서 3회 연속 `H-ENGINE` 및 `RAG-1/2` 통과, RAG 대조 5/5를 확인한다. 검색 예산 초과나 재시도 실패 시에는 검토 미완료 사유가 결과와 화면에 남아야 한다. 입력 문서의 지시문 탐지는 유지한다.

## I-2 · P2 · Legal NLI Stage 2가 의미 반전 인용을 `SUPPORTED`로 분류

- **재현:** 공식 전문 30,211자가 조회되는 공개 판례를 이용해 정확 인용과 부정 방향을 뒤집은 인용을 각각 합성 서면으로 검증한다. `LV_LEGAL_NLI_MODE=assist`에서 두 실행 모두 Stage 2 1건이다.
- **기대:** 정확 인용은 `SUPPORTED`, 뒤집은 인용은 공식 구간과 구조적 반전이 확인되면 `CONTRADICTED` 또는 확인 불충분이면 `PENDING_REVIEW`다.
- **실제:** 정확 인용은 Stage 2 `SUPPORTED`·최종 `VERIFIED`였다. 반전 인용도 Stage 2가 `SUPPORTED`(중첩 0.9508)라고 답했다. 최종 판정은 기존 1차 대조가 `CONTRADICTED`로 잡아 사용자에게 잘못된 최종 결론은 나가지 않았다. `assisted_count=0`이므로 `assist`의 증분 효과는 확인되지 않았다.
- **원인 범위:** 반전 인용의 선택된 원문 구간은 437자로 정확 인용의 201자보다 길었다. `stage2_nli`에는 변경 1건이 있었지만 구조적 반전 사유는 0건이다. `packages/legal_engine/nli_verifier.py`는 선택된 창 전체의 부정 표지와 어휘 중첩을 계산하므로, 부정 표현의 적용 절과 인용문이 어긋날 가능성이 있다. 이 가설은 추가 진단으로 확인해야 한다.
- **보완 수용 기준:** 같은 공식 전문과 합성 정확·반전 쌍에서 Stage 2가 방향을 구별하고, 공식 전문 미확보 시 `INSUFFICIENT`를 유지한다. 원문 대응 오프셋·선택 구간 길이·구조 변화 이유를 기록한다. 최종 1차 인용 대조의 기존 정답과 오탐은 악화되지 않아야 한다.

## I-3 · P2 · 운영 OCR 폴백 엔진 부재

- **재현:** 정상 스캔과 저품질 스캔을 각각 업로드한다. 정상 쪽은 1차 신뢰도 0.89, 저품질 쪽은 0.611이다.
- **실제:** 정상 쪽은 1차 OCR 채택. 저품질 쪽은 `FALLBACK_NOT_CONFIGURED`, 폴백 시도·채택 0건이다. `/api/diagnostics`도 엔진 `none`, 사용 불가를 보고한다.
- **원인:** 코드가 받는 엔진 값은 `rapidocr`·`paddleocr`지만 배포 의존성 목록에는 두 패키지가 없다. 환경변수만 추가해서는 사용할 수 없다.
- **보완 수용 기준:** 실제 배포 이미지에서 선택한 엔진이 사용 가능하다고 진단되고, 저품질 쪽에서만 폴백이 시도된다. 채택 시 읽을 수 있는 본문/쪽 수가 증가하고 정상 쪽은 불필요하게 재처리하지 않는다. Drive 저품질 16쪽도 교체·재색인 전후에 별도로 센다.

## I-4 · P2 · Dense·Reranker와 로컬 모델 서버가 운영 검색·라우팅에 연결되지 않음

- **관측:** 운영 RAG 실제 모드 `LEXICAL_ONLY`, 로컬 공급자 등록 0개. `LV_RAG_EMBEDDING_ENDPOINT`·`LV_RAG_RERANKER_ENDPOINT` 등은 현재 `environment.py`의 진단 표시에서만 읽힌다. 실제 검색에는 어댑터가 전달되지 않는다. `config/providers.json`의 로컬 공급자는 `enabled=false`다.
- **사용자 영향:** 준비된 서버가 있어도 검색 품질·속도 또는 모델 다양성의 운영 효과를 측정하거나 얻을 수 없다. 주소 값만 넣으면 실제 호출 없이 진단의 `HYBRID` 표시가 바뀔 가능성이 있다.
- **보완 수용 기준:** 안전한 설정으로 어댑터를 실제 생성·호출하고, 요청 수·성공/실패·폴백 이유로 `effective_mode`를 산출한다. 고정된 지지·무관 자료에서 Dense·Reranker ON/OFF의 정답 청크 순위와 오탐을 비교한다. 로컬 공급자도 별도 등록·라우팅·실제 호출 확인 뒤 사용한다. 기준 자료의 신뢰 역할과 입력 문서의 지시문 탐지는 유지한다.

## I-5 · P2 · 공식 Source 정확 조회와 학술 호출 제한 지속

- **관측:** 같은 SHA의 GitHub strict 실연동에서 공식 조회 5/6, 학술 조회 3/4다. 공식 미일치 1건은 공급자 원응답 3건을 받았으나 사건번호 일치 후보 0건으로 끝났다. 학술 미완료 1건은 `RATE_LIMITED`다. 그 워크플로의 기본 모델 직접 호출은 3/3, 연쇄 검토는 4/4였다.
- **사용자 영향:** 실재하는 자료도 공식 DB 미확인으로 남거나 학술 근거 조회가 일시적으로 빠질 수 있다.
- **보완 수용 기준:** 공급자 원응답 수·정규화 후 후보 수·탈락 사유를 구분한 상태로 정확 조회 원인을 확인한다. 호출 제한은 재시도 정책과 미확인 표시를 검증한다. 미확인을 근거 없는 존재/부존재 확정으로 바꾸지 않는다.

## I-6 · P3 · 운영 평가에서 아직 효능을 판정하지 못한 경로

- Drive는 41/41 자료가 색인돼도 OCR 저품질 16쪽의 본문이 없다. 자료 교체 또는 OCR 개선 후 동일 자료의 읽힌 쪽과 검색 가능 쪽을 비교해야 한다.
- 카세트 `RECORD/REPLAY`는 운영 모드가 `LIVE`이고 전용 재생 자료가 없어 미측정이다. 공식 DB 실연동 점수와 혼합하지 말고 격리 시험에서 요청 일치·누락·유효기간을 점검한다.
- 근거 그래프는 노드·연결 수만 관찰했다. 실제 근거 누락·정상 연결에 대한 독립 라벨이 없어 법률 판단 정확도는 미측정이다.
