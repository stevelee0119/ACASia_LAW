# TK-215 시험 삭제 승인이 적용 범위에 한정되지 않아 뒤의 삭제까지 통과시킨다 (평가 측 게이트 자산)

- 발견일: 2026-11-19 (평가 세션, PR #345 사후 검토 지적)
- 종류: **평가 측 게이트 자산 결함.** 제품 결함이 아니다
- 상태: open

## 문제

`scripts/check_test_edits.py`의 `approved_marks()`는 승인을 **(경로::시험, 표시) 쌍**으로만 읽는다.

    def approved_marks() -> set:
        """평가 측이 승인한 (경로::시험, 표시) 쌍. 파일을 마지막으로 바꾼 커밋이 평가 측일 때만 믿는다."""

어느 변경·어느 커밋 범위에 대한 승인인지 한정하지 않는다. 그래서 **한 번 삭제 승인을 받은 시험
이름이 나중에 다시 만들어진 뒤 또 지워지면 새 검토 없이 게이트를 통과한다.**

`docs/scorecards/approved_test_marks.json`의 각 항목에는 `ticket`·`approved`(날짜)·`reason`이
있으나 **게이트가 그 값을 대조에 쓰지 않는다.** 기록으로만 남는다.

## 왜 문제인가

이 게이트의 목적은 '기존 시험을 조용히 지우는 것'을 막는 것이다. 승인이 이름에만 걸리면 그 목적이
한 번만 지켜진다. 같은 이름을 다시 쓰는 일은 실제로 일어난다 — TK-208에서 1차 커밋의 시험을 2차에서
교체했고, 그때 승인한 세 이름은 앞으로도 영구히 삭제가 허용된 상태로 남는다.

## 고칠 방향

1. 승인 항목에 **적용 범위**를 넣는다. 기준 SHA(그 삭제가 일어난 base)나 PR 번호가 적합하다.
2. `approved_marks()`가 그 범위를 대조해 **범위 안의 삭제에만** 승인을 적용한다.
3. 기존 승인 40여 건에 범위를 **소급해 넣을지**, 범위 없는 항목을 어떻게 다룰지(경과 조치)를 함께
   정한다. 소급하지 않으면 옛 항목은 계속 이름만으로 통과한다.
4. 범위를 벗어난 삭제를 만났을 때의 메시지에 **왜 거부하는지와 무엇을 올려야 하는지**를 적는다.

## 수용 기준

1. 범위를 벗어난 같은 이름의 삭제가 거부된다(합성 시험으로 증명한다)
2. 범위 안의 삭제는 그대로 통과한다
3. 기존 승인 항목의 경과 조치가 정해지고 문서에 적힌다
4. `check_test_edits.py`의 다른 판정(표시 추가·단언 수 감소)은 바뀌지 않는다

## 미검증

실제로 같은 이름이 다시 삭제되는 상황을 재현하지 않았다. 정적 분석과 `approved_marks()`의 계약
(쌍만 읽는다)으로 확인한 것이다. 기존 승인 40여 건 가운데 몇 건이 이 위험에 해당하는지도 세지 않았다.

## 사용자 결정이 필요할 수 있는 것

3번(경과 조치)은 옛 승인의 효력 범위를 바꾸는 것이므로, 소급 적용 여부는 사용자 결정으로 정한다.

## 수정 (2026-11-19, 평가 측)

### 범위를 '시험 본문의 지문'으로 둔다

기준 SHA나 PR 번호를 범위로 쓰는 것을 먼저 검토했으나 버렸다. PR 번호는 게이트가 알 수 없고,
기준 SHA는 base가 갱신되면 달라져 정당한 재실행에서 승인이 풀린다. 막아야 하는 것은
**같은 이름의 다른 시험이 지워지는 것**이므로 범위를 본문에 건다.

    "scope": {"body": "<16자리>"}

지문은 이름을 뺀 정의(표시·인자·본문)의 SHA-256 앞 16자리다. 이름만 바뀐 시험은 같은 지문이고
본문이 바뀌면 다른 지문이다. `scripts/check_test_edits.py`의 `signatures()`를 그대로 쓴다
(이름 변경 판정에 이미 쓰이던 기구다).

지문 뽑기: `python scripts/check_test_edits.py --digest <경로> <시험이름> --ref <기준 커밋>`

### 대조 규칙 (`match_approval`)

1. `scope.body`가 있으면 그 지문과 같을 때만 승인이다
2. 범위가 없고 `approved`가 **2026-11-19 이전**이면 경과 조치로 승인하되 **경고로 센다**
3. 범위가 없고 그 날짜 이후면 **승인으로 보지 않는다**
4. 같은 (시험, 표시)에 항목이 여럿이면 범위가 맞는 것이 이긴다. 범위가 전부 어긋나고 옛 항목이
   있으면 옛 항목으로 통과한다

삭제는 **base 쪽** 본문의 지문으로, 새로 붙은 표시는 **HEAD 쪽** 본문의 지문으로 대조한다.
표시는 '붙는 순간'만 보므로 나중에 본문이 바뀌어도 되풀이 실패가 나지 않는다.

### 경과 조치

옛 승인 40건은 범위 없이 그대로 쓴다. 지문을 소급할 수 없다(그 시점 본문이 이미 바뀌었다).
대신 그 항목으로 통과할 때마다 게이트가 `[경고] 적용 범위 없는 옛 승인으로 통과한 항목 n개`로
적고 그 자리의 지문을 함께 출력하므로, 다음에 같은 자리를 건드릴 때 범위를 넣을 수 있다.
**옛 항목을 한꺼번에 지우지 않는다** — 기존 CI를 깨뜨리고, 그 승인들은 실제 결정 기록이다.

### #343 TK-208 승인 3건 철회 (사용자 결정)

사용자 결정 원문: **"#343 승인 3건의 철회"**

TK-212 수정 뒤 확인한 결과 **그 승인은 불필요했다.** 게이트 기준이 PR 병합 시험 커밋의 첫 부모로
고정되면 그 세 시험은 base에 없던 것이어서 '삭제'로 집히지 않는다. `832c439f` 작업 폴더에서
승인 목록에 TK-208 항목이 **없는 상태로** 두 기준을 돌려 확인했다 — 새 기준 종료 0(삭제 0건),
옛 `push` 규칙 종료 1(삭제 3건).

세 항목을 `approved_test_marks.json`에서 제거하고, 철회 사유·경위·확인 방법을 `note`에 남겼다.
허용만 사라지고 기록은 보존된다.

**평가 측 자기 결함으로 기록한다.** 원인을 다 가리지 못한 상태로 승인을 올려 사용자 결정을
받았다. 재발 방지: 게이트 실패를 승인으로 넘기기 전에 **그 실패가 게이트 자체의 결함인지
먼저 확인한다.** 이번에는 같은 커밋의 다른 실행이 성공하고 있었고(TK-212 중복 실행) 그것이
단서였는데, 기준이 다르다는 사실을 알아내고도 승인 쪽으로 갔다.
