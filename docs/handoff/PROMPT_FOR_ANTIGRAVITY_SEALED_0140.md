# Antigravity 격리 세션 봉인 시험 진행표 (0.14.0, 2026-10-25 한국 시각)

사용자 지시(2026-10-25): "안티그래비티 세션에서 봉인시험을 하도록 준비해줘". 봉인 세트 출제는 원래 저장소를 연결하지 않은 Codex 격리 세션이 맡는다(AGENT_ROLES 개발 체제 ②). 이번 0.14.0은 **Antigravity를 같은 격리 조건으로** 쓴다. 구현에 쓰는 Antigravity 작업 공간·대화는 쓰지 않는다. 그 세션은 탐지 규칙과 은퇴 세트를 알고 있어 출제가 측정이 되지 않기 때문이다.

## 0. 격리 작업 공간 준비 (세 단계 공통)
1. 저장소 사본과 무관한 **빈 새 폴더**를 연다(예: `C:\sealed_work\author_20261025`). 저장소 폴더나 그 하위 폴더를 작업 공간으로 열지 않는다.
2. **새 대화**를 시작한다. 구현 대화를 이어 쓰지 않는다.
3. GitHub 연결·MCP 서버·브라우저 도구로 저장소나 GitHub 페이지를 열지 않는다. 전역 규칙·기억(메모리) 기능에 이 프로젝트 내용이 들어 있으면 그 단계 동안 끄거나 비운 상태로 진행한다.
4. 단계마다 다른 새 폴더·새 대화를 쓴다(작성 → 자체 점검 → 채점). 앞 단계 대화를 다음 단계에 쓰지 않는다.
5. 각 단계의 보고(건수·오류 수·점수 집계)만 평가 측(Claude Code)에 붙여 넣는다. 문서 문장·정답·토큰은 옮기지 않는다.

## 1. 작성 (격리 작업 공간 A)
- 프롬프트: `PROMPT_FOR_CODEX_SEALED_SET_0140.md`의 '--- 프롬프트 시작 ---'부터 '--- 프롬프트 끝 ---'까지 그대로. 본문은 도구 이름과 무관하다(출제자 역할).
- 산출물 zip을 저장소 밖(예: `C:\sealed\sealed_20261025\`)에 푼다. 작성 대화가 작업 폴더 사본을 지웠다고 알리면 그 폴더도 지운다.

## 2. 자체 점검 (격리 작업 공간 B)
- 프롬프트: `PROMPT_FOR_CODEX_SEALED_SELFCHECK.md`의 프롬프트 본문 그대로. `<SEALED_DIR>`만 실제 경로로 바꾼다.
- 오류 0과 지문 16자리를 받는다. 오류가 있으면 사용자가 봉인 폴더에서 고치거나 1단계를 다시 한다.
