# TK-137 제한형 관련 근거 탐색 — 설계 메모 요청 (11-03, 평가 측)

- 결정: 2026-11-03 사용자 '다음 릴리스 범위'(C 묶음) · 11-03 '1,2순위대로 지시를 시작'(2순위 = 이 메모). **코드 금지, 메모만.**
- 범위(원장): 인용 조문 기준 깊이 1, 공식 3단 비교의 위임 관계 + 본문 명시 참조('제N조에 따라')만. 검토 자료로만 제공(finding 승격 금지), 조회 수·시간 상한. lexdiff는 아이디어만 참고(BSL 1.1, 코드·프롬프트·데이터 복사 금지).

## 1. 평가 측이 확인한 공식 API 사실 (11-03, 법제처 OC, 근로기준법 MST 285279)
- `lawService.do?target=thdCmp&MST=…&knd=1`(인용조문 3단 비교): 최상위 `ThdCmpLawXService` → `기본정보`(법령명·시행령명·시행규칙명·각 ID·`삼단비교존재여부`), `인용조문삼단비교.법률조문`(목록, 이 법은 145개), `관련삼단비교목록`.
- `knd=2`(위임조문 3단 비교): 최상위 `LspttnThdCmpLawXService` → `위임조문삼단비교.법률조문`(목록, 172개). 항목 예: `조번호`('0011')·`조가지번호`·`조제목`·`조내용`, `시행령조문`{`법령명`·`조번호`·`조제목`·`조내용`}, `시행규칙조문`.
- 미확인(메모에서 처리 방법을 정할 것): 한 법률 조문에 시행령 조문이 여럿일 때 `시행령조문`이 목록으로 오는지, 3단 비교가 없는 법령(`삼단비교존재여부`=N)의 응답, 시행일 지정(efYd) 동작.
- 기존 어댑터(`packages/source_adapters/law_go_kr.py`)는 `thdCmp`를 쓰지 않는다. 기존 `_http_get`·`mask_oc`·`select_version`(기준일 판) 재사용을 우선한다.

## 2. 메모에 반드시 적을 것 (1~2쪽, `docs/handoff/requests/TK-137_related_basis_design_memo.md`)
1. 입력: 어떤 인용에서 출발하는가(공식 확인된 법령·조문 판정만, 기준일 확정된 판). 인용이 미확인·부존재면 탐색하지 않는다.
2. 관계 두 가지와 추출 규칙: (a) 3단 비교 위임(같은 조번호 행의 시행령·시행규칙 조문), (b) 인용 조문 본문의 명시 참조('제N조(제M항)에 따라/의하여', '같은 법 제N조', '대통령령으로 정하는'). 깊이 1을 넘지 않는 방법.
3. 출력 위치와 형식: 보고서·화면의 어느 자리에 '관련 근거(검토 자료)'로 보이는가, 스키마 필드 이름. **finding 생성·심각도·점수 반영 금지**를 코드 구조로 어떻게 보장하는가.
4. 상한: 문서당·인용당 조회 수, 시간 예산, 응답 크기. 상한·실패 시 표시(조용히 빠뜨리지 않음).
5. 캐시: 한 실행 안 재사용만(실행 간 영속 캐시 금지 원칙, E2 보류와 충돌 금지).
6. 네트워크 꺼짐(`LV_ALLOW_NETWORK=0`)·OC 없음에서의 동작: 탐색 생략과 그 표시. 오프라인 고정·은퇴 점수에 영향 0이어야 하는 이유.
7. 개인정보: 외부로 보내는 값은 법령명·조문 번호뿐임을 보이는 방법.
8. 시험 계획: 합성 응답(시험 파일 안 인라인, `tests/fixtures/`는 보호 경로라 쓰지 않음) 양성 3·대조 3 이상 — 위임 있음/없음/목록형/3단 비교 없음/상한 초과/네트워크 꺼짐.
9. 효과 측정: 온라인 OFF/ON 쌍(평가 측 탐침 서면), 측정 항목(관련 근거 제시 건수·오연결 0).
10. TK-138(관련 판례·권위 가중)과의 접점: 같은 출력 자리를 쓰는지, 무엇을 남겨 두는지.
