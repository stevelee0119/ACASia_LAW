# TK-87 확인할 항목: 검토 상태·의견·담당자 입력을 없애고 '확인이 필요한 내용' 요약으로 바꾼다 (P2, 사용성, 사용자 개선안 3나)
- 근거: 사용자 개선안(2026-10-19) 3나항. 프로그램의 목적은 사용자가 서면에서 무엇을 의심하고 다시 확인해야 하는지 알게 하는 것이고, 프로그램 안에서 검토 결정을 기록·관리하는 것이 아니다.

## 1. 현재
- 표 4열에 행마다 검토 상태·우선순위·담당자 입력이 있다(`apps/web/static/app.js` 1965~2021행).
- 탭 위쪽에 검토 상태·진행 상태·담당자 필터, '선택 항목 검토', '검토 이력' 도구가 있다(`index.html` 확인할 항목 도구줄, `workflow.js` 384~392행).
- 보고서 확정 전 점검이 이 상태값으로 '변호사 검토 미완료'를 센다(`apps/api/routers/reports.py` 483~536행, `report-workbench.js` 105~117행).

## 2. 요구
1. 행 안 입력(검토 상태·우선순위·담당자)과 위쪽 필터·일괄 검토·검토 이력 도구를 화면에서 없앤다. 항목 검색과 중요도 필터는 남긴다.
2. 4열에는 **'확인이 필요한 내용'**을 둔다. 그 행의 기존 결과(판정·근거·대응 방안)에서 만든 2~3줄 요약이다.
   - 새 모델 호출을 하지 않는다. 기존 결과 필드만 조합한다(근거 없는 문장 생성 금지).
   - 무엇을(인용·주장), 왜(판정 사유), 어떻게 다시 확인하는지(공식 원문·증거 대조 위치)를 적는다.
3. 보고서 확정 전 점검에서 '변호사 검토 미완료' 집계와 `acknowledge_unresolved`의 검토 상태 조건을 정리한다. 미확인 항목·조회 실패 출처 확인은 남긴다.
4. API·DB(`finding_workflows`)는 이번에 지우지 않는다. 화면에서 부르지 않게만 한다.

## 3. 시험
- 보고서 점검 서버 시험은 바뀐 조건에 맞게 고치고, 미확인 항목·조회 실패 출처 확인이 그대로 요구되는지 시험한다.
- 화면 시험은 TK-85와 같은 대응표를 낸다. 탐지 diff 0, 고정·은퇴 점수 불변.
