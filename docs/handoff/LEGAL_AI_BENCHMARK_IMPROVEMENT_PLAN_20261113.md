## 3. 티켓 명세

### EV-1 0.19.0 탐침 미통과 7건 원인 분석(평가 측)
- 목적: 탐침 47항목 중 미통과 7건을 원인 유형별로 나눠 티켓(또는 '모델 변동·명세 문제')으로 정리.
- 산출: 항목별 원인·코드 위치·재현 결과. 탐침 문장은 공개하지 않고 꼴만 적는다(CLAUDE.md 2026-10-24).
- 수용: 7건 모두 원인 분류 완료, 새 티켓은 이 표에 추가.

### TK-157 경고 묶기·정밀도 라벨화(B4)
- 문제: 정답지 밖 미판정 경고 문서당 2.0건(102/51). 같은 근거의 경고가 여러 행으로 나와 검토 부담이 늘고 정밀도를 잴 수 없다.
- 현행: 담당자 검토 결정(`packages/common/enums.py` 108행 FALSE_POSITIVE 등 — 지적 수용·오탐·조치 완료)이 있으나 정밀도 집계로 쓰지 않는다.
- 범위: (1) 같은 문서·같은 인용/주장·같은 원인의 경고 묶기 규칙(데이터는 유지, 화면·보고서만 묶음) (2) 묶음 우선순위(심각도·근거 강도) (3) 검토 결정을 익명 집계해 경고 유형별 수용률·오탐률 보고(개인정보 제외).
- 수용 기준: 고정 dev/holdout·case9에서 표시 경고 수 감소, 재현율(v2 일대일) 하락 0, 묶음 안 개별 경고 접근 가능, 유형별 수용률 리포트 생성.
- 측정: 문서당 표시 경고 수, 유형별 수용률·오탐률(라벨 축적 후).

### TK-158 기준일 법령 버전 확정(B3)
- 문제: 공식 원문은 찾았으나 기준일 당시 시행 조문을 하나로 정하지 못하면 '미확인'으로 남는다(case9 국가배상법 사례).
- 현행: `packages/source_adapters/legal_history.py` 106행이 같은 시행 경계에 여러 판이 있으면 `ValueError("Multiple versions share the requested effective boundary")`를 낸다. 이 메시지는 `packages/legal_engine/verifier.py` 1239행 `_unverified_finding`으로 미검증 처리된다.
- 범위: 같은 경계의 판들 중 조문 본문 비교·부칙(시행일·경과규정)으로 하나를 고르거나, 인용 조문 본문이 판들 사이에 같으면 '내용 동일'로 확정. 끝내 못 고르면 지금처럼 미확인(근거 명시).
- 수용 기준: 재현 사례(case9 꼴 합성)에서 확정 또는 '조문 내용 동일' 판정, 다른 내용의 판이 섞이면 확정하지 않음(대조 시험), 기존 시간 적용 시험(TK-141 등) 유지.
- 측정: 기준일 버전 확정률, 시점 오판 0.

### TK-159 판정별 공식 원문 근거 구간(B1)
- 문제: 판정은 서면 쪽 위치(`citation.span` — verifier.py 409·467·540행 등)만 남기고, 공식 원문 쪽 근거 구간은 법률 엔진 판정에 없다(평가 측 grep 확인).
- 범위: 판례·법령 판정(존재·인용문·판시 취지·시점)마다 근거로 쓴 공식 원문의 식별자(판례 일련번호·법령 ID·시행 판)와 문자 구간·원문 해시를 결과 JSON에 싣는다. 근거를 못 찾은 실패(검색 실패)와 찾았으나 불일치(판단)를 상태로 구분.
- 수용 기준: VERIFIED·CONTRADICTED 판정은 근거 구간 필수(없으면 판정 불가), 결과 JSON 스키마 시험, #272 `export_quality_predictions.py`와 연결 확인.
- 측정: 근거 구간 정밀도·재현율(라벨 확보 후 TK-166), 출처 ID 정확도.

### TK-160 주장 판정 3분류(B2)
- 문제: '법률적으로 무리한 주장'은 근거 강도와 무관하게 한 탭에 모인다. 근거 없이 '부당'으로 보이는 행이 있을 수 있다.
- 범위: 주장별 SUPPORTED/CONTRADICTED/INSUFFICIENT(ContractNLI 꼴) + 근거 구간(TK-159). 근거 없는 '모순'은 INSUFFICIENT로 낮춘다. 판례 의견 귀속(TK-153)·시점(TK-158) 결과를 입력으로 쓴다.
- 수용 기준: 기존 무리한 주장 탐지 재현율 하락 0, 근거 없는 CONTRADICTED 0, 화면·보고서에 3분류 표시.
- 측정: 3분류 macro-F1(TK-166 라벨), 잘못된 VERIFIED 비율.

### TK-161 AI 작성 판별 반복 안정성(B5)
- 선행: TK-156 배포 뒤 온라인 case9 3회 측정(사용자 실행).
- 범위: 결과에 따라 (1) 객관적 흔적 우선 결정 규칙 (2) 같은 입력 반복 일치율 보고 (3) 유보 기준 조정 중 필요한 것만.
- 수용 기준: 같은 입력 3회 판정 일치, 유보율 0.19.0보다 증가 0.

### TK-162 판례 효력 확인(N1)
- 문제: 전원합의체 판결로 변경된 옛 판례를 근거로 쓴 주장은 현재 '존재 확인'만으로 통과할 수 있다. 판례 변경 추적 기능은 없다(평가 측 grep: '이와 달리'·'판례 변경' 처리 코드 없음).
- 범위: 전원합의체 판결 이유의 판례 변경 문단에서 변경 대상 판결 목록을 추출해 색인 → 서면 인용 판례가 변경 대상이면 경고(변경 범위 문구 함께 표시, '배치되는 범위' 판단은 사람 검토).
- 수용 기준: 합성 판결문으로 추출 시험(양성·대조 각 3건 이상), 실제 공식 판결 응답으로 재현, 오탐 0(변경 대상이 아닌 판례).
- 전제: 공식 DB 전문 확보, 하드코딩 금지(사건번호를 제품 코드에 넣지 않음).
