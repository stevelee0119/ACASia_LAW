## 사용자 원문
- (10-19, 3다) "주요참고문헌 검토 결과는 현재 클릭을 해야만 상세하게 볼 수 있는데, 주요참고문헌을 검토하는 것은 공신력이 있고 검증된 자료를 제시하고 이를 기반으로 검색해 오류를 최소화하기 위해서야. 하단부에 따로 별도로 설명하지 말고, 위의 표에 각 서면의 내용을 판례, 법령등과 동일한 근거 자료로서 활용하고, 그 내용에 부합하거나 부합하지 않는 내용이 있다면 판례 인용 오류·미확인 검토 (AI 작성 여부 판단과 별개) 부분의 표에 함께 정리해줘."
- (10-25, 3) "주요참고문헌 검토 결과를 별도로 하단 부에 두지 말고, 같은 페이지 상단의 표에 있는 주요 내용들을 검증하는 자료로서 공식데이터베이스의 자료를 API로 검색하는 것에 추가로 구글 DRIVE의 자료를 활용하도록 한 다음 상단표와 통합해서 정리하도록 기능 개선을 요구했는데 구현되지 않았어."

## 현재(평가 측 코드 확인)
- Drive 대조 결과는 문서별 `engine_data.rag.observations`에 있다. 항목마다 `claim_id`, `claim_quote`, `source_id`, `source_quote`, `relationship`(SUPPORTS·CONTRADICTS·CONTEXT·INSUFFICIENT)이 있다(`packages/rag_engine/review.py` 20~28행, 690행).
- 그중 CONTRADICTS만 `RAG.REFERENCE_CONTRADICTION` 결과로 표에 올라간다(TK-70). 나머지(부합·맥락·근거 부족)는 하단 '주요 참고문헌 검토 결과(RAG)' 구역에만 있다(`apps/web/static/app.js` `referenceSection` 1073행~).
- Drive 대조는 '주장' 단위다. 표의 인용 행(판례·법령)을 Drive로 확인하는 경로는 표준판례 사건정보 대조(TK-71, `reference_case_match`)뿐이다.
- TK-88은 '화면 배치만, 탐지 diff 0'으로 좁혀 발행됐다(평가 측 원인).

## 설계 메모에 담을 것 (승인 전 구현 금지)
1. 행 연결 규칙: observation → 표 행(`claim_id` 우선, 없으면 `claim_quote`가 행의 `claim_text`에 포함). 연결 실패 처리.
2. 인용 행의 Drive 조회(원문 3항): 질의(사건번호·법령명·조문 정규화), 색인 범위 한계, 발췌 길이, 개인정보(외부 모델 미사용 시 로컬 검색만).
3. 등급·결과 유형: 부합 표시는 결과(finding)를 새로 만들지 않고 행 속성으로 둔다. 기존 유형·등급은 바꾸지 않는다.
4. 보고서 7형식에 같은 칸을 넣을지 여부.
5. 측정: 오프라인 세트로는 Drive 효과를 잴 수 없다. 운영 Drive로 사용자 실제 서면 1건 이상의 화면 캡처와 온라인 대조 표본으로 확인한다.
