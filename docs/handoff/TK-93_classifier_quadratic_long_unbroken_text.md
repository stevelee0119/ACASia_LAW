# TK-93 문장 구분 부호 없는 긴 본문에서 `classify()`가 길이의 제곱에 가깝게 느려진다 (P2, 성능·견고성, 기존, 평가 측 발견)
- 발견: 평가 측, 2026-10-19 #147(TK-92) 판정 중 성능 점검. 0.13.1 계열 코드(Steve `fb6592c`)에서도 재현.

## 1. 증상 (측정, 이 세션 평가 측 환경)
| 입력(마침표 없는 반복 서술, 지시형 낱말 포함) | Steve `fb6592c` | #147 후보 `7bfd8e8` |
|---|---|---|
| 약 4.3만 자 | 10.0초 | 12.0초 |
| 4배(약 17만 자) | 139초 | 180초 |
- 같은 길이라도 마침표로 문장을 나누면 선형이다(후보 4배 1.9초).
- 원인 후보: 지시형 낱말 hit마다 문장 경계를 `rfind`·`find`로 찾고, 그 '문장'(경계가 없으면 본문 전체)에 정규식을 다시 돌린다(`classifier.py` `_narrative_sentence`·`_is_narrated_legal_context`·`_is_quoted` 등). hit 수 × 본문 길이가 된다.
- 위험: 줄바꿈·마침표가 거의 없는 PDF(표 추출, OCR 결과, 의도적으로 만든 문서)가 들어오면 검증 시간이 크게 늘거나 시간 예산을 넘는다.

## 2. 요구
1. 문장 경계를 한 번 계산해 hit에 대응시키거나, 문장 길이에 상한(예: hit 앞뒤 일정 글자)을 둔다. 탐지 결과는 바꾸지 않는다.
2. 점검표 2항 기준(길이 1배·4배 각 3회, 최솟값 비 < 8, 4배 최솟값 < 1초)을 **문장 부호 없는 입력**으로도 측정해 낸다.
3. 탐지 diff 0, 고정·은퇴 점수 불변, 인젝션 시험·TK-92 시험 통과.
