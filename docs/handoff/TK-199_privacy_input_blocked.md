## 사용자 원문

> 2. 모델별 판정 부분에 INPUT_PRIVACY_BLOCKED, MASKING_PII_DETECTED:PII_INPUT_BLOCKE와 같은 메시지가 발생했어. AI 검토가 진행되지 못한 원인을 분석해서 해결해야 해.

## 원문 대응표 (수용 기준)

| 원문 문장 | 확인할 화면·동작 | 평가 측 확인 (head `2b676c84`) | 판정 |

| `INPUT_PRIVACY_BLOCKED`·`MASKING_PII_DETECTED:PII_INPUT_BLOCKED`가 발생 | 모델별 판정 카드에 차단 메시지가 없어야 함 | 마스킹 멱등성(#328) + `pii_engine/detector.py` 가드 2건(하이픈 달력 일자, 슬래시·물결표 전화 분리) | 오프라인 근거 있음 |

## 평가 측 판정

**오프라인 근거 있음 / 운영 재현 미확인.** 차단을 일으켰던 입력 꼴이 게이트를 통과하는 것을 합성 서면으로 확인했고, 평가 측 개인정보 축 조합 45칸 전수 통과·base 오탐 2종 제거를 확인했다. 그러나 사용자 실제 문서에서 차단이 사라지는지는 오프라인에서 측정할 수 없다. 해결로 적지 않는다.

## 운영 해소 조건

배포 후 사용자 실제 문서로 모델별 판정에 차단 메시지가 없고 교차검토가 수행되는지 확인. 이 확인 전까지 TK-198·TK-199를 해소로 적지 않는다.

## 운영 해소 (2026-11-19 사용자 결정 '의견대로')

평가 세션 의견을 사용자가 채택했다. 아래 증거로 **해소**로 적고, 사용자가 배포본에서 실제 문서를
한 번 확인하는 것을 운영 확인으로 덧붙인다.

증거는 같은 워크플로(`live-source-check.yml`)의 두 배포 기록 대조다. 합성 자료가 아니다.

실제 개인정보(`MEDICAL`·`PERSON`)가 든 30,211자 법률 문서에서, 같은 코드 경로로 차단이 사라지고

운영 온라인 1회차는 합성 35,674자 DOCX에서도 `INPUT_PRIVACY_BLOCKED` 없이 분석이 완료되고

**남는 미측정:** 사용자 자신의 35,674자 문서 자체는 측정하지 못했다. 그 문서를 특정할 수 없었고,
평가·운영 세션이 사용자 원본을 보관하지 않는다. 위 증거는 같은 규모·같은 실패 꼴의 실제 법률
문서에 대한 것이다.
