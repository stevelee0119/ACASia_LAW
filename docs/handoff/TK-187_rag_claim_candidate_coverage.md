# TK-187: 다쟁점 문서의 관련 참고자료 후보 누락

발견: 2026-11-16 (Asia/Seoul). P1, 기존 구조적 결함. 상태: open — 온라인 재현/원인 확인, 수정 설계·사본 검증 전. 담당: Antigravity 구현, 평가 측 독립 수용.

## 재현과 실제 결과

0.22.0 운영 `183f3d22791bb01d4c8a39ce842e193000c663b8`. 공개 `tests/fixtures/rag_controls/`의 지지·무관 PDF를 설정된 Drive 하위 폴더에 두고 case9를 새 평가 프로젝트에서 실행한다. 파일명은 원본 그대로 유지한다. `case9_state_compensation_rag_controls_online.json`으로 채점한다.

현재 수집한 반복 2회에서 기존 case9 정답 23/23, RAG 대조 3/5. RAGC-S1(지지 자료 선택)·S3(지지 의견)이 실패했다. 지지 PDF는 목록에 존재하지만 `NOT_SELECTED_METADATA / NAME_PATH_NOT_RELATED`여서 본문을 색인하지 않았다. 음성 대조 3개가 통과한 것을 전체 검색 성공으로 계산하지 않는다.

실행의 Drive 본문 질의는 문서 전체 대표어 2개를 AND 결합했다. 실제 지지 PDF의 해당 두 단어 포함 여부는 모두 false였고, 대상 주장에 관련된 행위·검사 표현은 존재한다. 파일명은 영문이고 제목 가점 0, fulltext 적중 0. 이는 모델 판단 이전의 후보 수집 누락이다.

- `packages/rag_engine/library.py:614`: 후속 검색은 eligible 색인에 한정되므로 앞단 누락을 복구할 수 없음.

## 설계 요청

[RAG 재설계 제안](requests/RAG_REDESIGN_PROPOSAL_20261116.md)을 기준으로, 질의와 독립된 비동기 수집·색인 및 주장/쟁점별 다중 검색의 구현 설계를 먼저 낸다. 첫 단계는 모든 허용 자료를 수집하고 제목/폴더명은 가점으로만 쓰는 구조다. 단어·식별자 검색을 먼저 고치고 의미 검색/재정렬은 독립 세트로 검증 후 추가한다. 기존 PostgreSQL/작업 큐 활용, 원문/리비전/ACL/쪽별 처리 상태, 검색 판 고정, 실패 재개 및 전환/되돌림을 포함한다.

금지: 평가 파일명/본문/사건번호 예외 등록, 모든 자료를 매번 LLM에 전송, 이름을 바꿔 통과한 결과로 최초 누락을 지우기, 개인정보·입력 인젝션 보호 완화, 출처 본문을 실행 명령으로 취급. 공식 DB/RAG를 입력 공격문으로 격리하는 방식으로 되돌리지 않는다.
