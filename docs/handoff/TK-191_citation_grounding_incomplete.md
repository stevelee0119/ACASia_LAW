## 단계별 원인 근거

- B-P1: primary가 의견 구간 번호를 확신하지 못해 근거 인용0, critic은 인용2개를 냈다. 현재 전체 모델 verdict의 인용을 모두 확인해야 하는 집계에서 primary의 빈 인용만으로 grounded=false가 된다.
- B-P4: primary 인용1, critic 인용2 중 하나는 보존된 원문의 선택 구간에서 정확히 발견되지 않는다. 공백 정규화만으로도 일치하지 않는다. 무리하게 인용 일치로 인정하면 안 된다.
- 두 항목 모두 grounder used=false, 합의 incomplete_models=true. escalation의 추가 의견은 검증 결과를 대체하는 확정 판정이 아니다. TK190 실패와 구분한다.
- 평가 측 진단은 원문 선택 구간 기준이다. 보낸 마스킹 바이트를 완전히 복원한 결과가 아니므로 정확한 전송 인용별 실패 위치/원인을 추가 확인해야 한다. 원문·사건 식별자는 공개하지 않는다.

## 코드 위치와 설계 요청

- `packages/legal_engine/evidence_pack.py:143` render는 구간을 생략 표시로 잇고, 별도로 보낸 opinion_sections의 S번호와 본문 각 구간을 명시적으로 연결하지 않는다. `packages/verification_engine/pipeline.py:1519` 부근에서 비다수의견만 구간 메타데이터로 보낸다. 실제 모델의 구간 번호 혼동이 기록됐다. 각 구간의 ID·의견 종류·원문 위치를 일관된 구조로 보내고, 표시용 태그를 원문 인용으로 허용하지 않도록 설계한다.
- 같은 pipeline1551~1565행은 사용된 모델 verdict 모두의 인용을 all 검사한다. 한 빈/불일치 인용이면 전체 grounded가 false이고 최종 evidence_quotes가 빈 목록이 된다. 인용별 검증 결과와 의미 합의/사건 적용 유보를 분리해 보존·표시하는 설계가 필요하다.
- `semantic_consensus.py`의 보수적 합의와 불완전 모델 표시는 유지한다. 임의로 all을 any로 바꾸거나 부분 일치/모델 확신으로 최종 SUPPORTED를 만드는 수정은 하지 않는다. 부정·조건·다수/별개의견·구간 경계를 보존한 정확 인용을 확보하도록 요청·구조·유한 재검사를 보완한다.

## 수용 기준

정상 인용의 근거가 실제 보낸 단일 원문 구간에서 확인되고, 해당 인용의 의견 종류·문맥과 일치함을 항목별로 입증한다. 문구 일치/법리 취지/해당 사건 적용 판단은 각각 보존한다. B 두 항목을 포함해 같은 기준47항목 재측정, case9 23/23·입력보호 유지. 다수/별개 혼재, 한 모델 유보, 근거 하나만 잘못 인용, 생략 구간 연결, 부정·조건 누락, 틀린 사건번호/다른 판결 인용 각각 양성/대조를 구성한다. 무효 인용을 받아 점수만 회복하면 실패다.

현재 제안은 사본 미검증이다. 실패를 없애려고 정답지/채점 기준을 낮추거나 성공 회차만 골라 보고하지 않는다. 관련 평가 명세의 표현이 바뀌면 평가 측이 구버전까지 동일 규칙으로 재채점한다.
