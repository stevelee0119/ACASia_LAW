## 구현 제출과 평가 순서

1. TK별로 확인된 원인, 변경할 경로·자료 모델, 보존할 동작, 양성/대조/회귀 시험, 전환·되돌림 계획을 낸다. 원인이 확정되지 않은 TK-186은 먼저 안전한 진단을 제시한다.
2. 설계/사본 미검증 항목을 구현 완료로 표현하지 않는다. 사본으로 기존 실패와 새 대조를 확인하고 관련 기존 시험·평가 명세와 충돌하는 부분을 평가 측에 요청한다. 구현 측이 보호된 정답·기준선을 바꾸지 않는다.
3. 사건명·파일명·문구 예외 등록 금지. 같은 원인에 다른 값 양성3개 이상/대조3개 이상을 포함한다. 검색은 후보 재현율과 최종 근거 정확성, OCR은 처리율과 본문 정확성, AI는 반복 일치와 정답 정확성을 각각 분리한다.
4. PR 본문에 TK·head SHA·변경·실제 실행한 관련 시험·미검증 범위를 적는다. 동일head CI가 끝난 후 평가 측이 diff/독립 탐침으로 판정한다. 배포 후 같은 조건의 온라인 재평가까지 결과를 연결한다.
5. 완료 보고는 `CI 통과`, `병합`, `배포`, `운영 해소`를 구분한다. 최초 실패 결과를 보존하고 모든 평가 전용 프로젝트는 결과 보존 후 휴지통 이동 및 재조회 확인한다.

## 추가 조사·판정 보류

- AI 동일조건4회는 모두 일부 생성으로 일치했다. 작성 이력 정답이 없는 반복 관찰이므로 정확도 개선으로 주장하지 않는다. 독립 사람/일부/전체 작성 대조군 확보가 필요하다(TK-185).
- 입력 인코딩 공격 실행의 Gemini `ai_document_v1`에서 본문 없는 응답 1회가 기록됐다(`finishReason=OTHER`). 입력 공격 HIGH 탐지는 통과했다. 모델 장애율 0으로 보고하지 않으며 한 번의 외부 응답만으로 제품의 신규 회귀를 확정하지 않는다. 반복 여부와 fallback/이견·미확인 표시를 별도 조사한다.
- Source 실연동은 실패했고 통합 workflow는 성공했으나 항목은 6 passed/1 unreachable이다. 실행 성공을 7항목 통과로 바꾸지 않는다.
- TK-180 정상 참고자료 TXT는5/5, PDF/DOCX/XLSX는 Drive에서 한 형식씩 교체한 후 별도 실행이 필요하다. 실제 기기·다른 역할/조직 계정·독립 AI 정확도·온라인 봉인 및 지원 형식의 모든 경계는 아직 완료되지 않았다.
- 위 보류는 전체 평가의 합격이 아니다. 필요한 자료·환경과 재실행 조건을 범위표에 유지한다. 새 보완 결과가 나오면 원래 실패를 지우지 않고 후속 근거를 붙인다.
