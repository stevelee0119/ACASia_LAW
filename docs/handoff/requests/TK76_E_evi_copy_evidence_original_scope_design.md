# TK-76 E항 설계 메모: EVI-COPY 원문 범위를 '서술형 원본 서증'으로 확장

- 작성일: 2026-11-18
- 작성: 구현 에이전트(Claude Code, 2026-11-18 사용자 지시로 구현 담당)
- 기준 브랜치: `origin/Steve_ACASiaLAW` (`63c060d`) + PR #330
- 근거: 2026-11-09 사용자 결정 "E(EVI-COPY 원문 범위 확장·문서 종류 판별)는 다음 릴리스 첫 TK로(설계 메모부터)",
  2026-11-18 사용자 지시 "TK-76 E항 포함". 분류는 **(나) 설계 범위**였고 사용자 결정으로 열렸다.

## 1. 현재 동작과 미탐

`cross_document_copies`(`packages/claim_engine/evidence_consistency.py`)의 5순위 경로는
**원문이 사실경위서로 분류된 문서일 때만** 작동한다.

```
elif owner_kind in (DOC_KIND_PLEADING, DOC_KIND_EVIDENCE_EXPLANATION) \
     and other_kind == DOC_KIND_FACT_CONFIRMATION:
```

그래서 소송서면·증거설명서가 **사실경위서가 아닌 원본 서증**의 본문을 인용 표시 없이 통복제해도
아무 결과가 나오지 않는다. 평가 측 진단(전달문 2-20)에 따르면 은퇴 세트 EVI-COPY 7항목 중 6항목의
유사 문장 쌍이 '소송서면 ↔ 사실경위서로 분류되지 않은 문서' 사이에 있다.

## 2. 과거 시안이 실패한 이유 — 이번에 반복하지 않을 것

평가 측이 원문 범위를 '사실경위서로 분류되지 않은 문서'로 넓혀 보니
**은퇴 1세트 53.3 → 49.3, 확인 오탐 0 → 2, 놓친 세트 득점 0**이었다(전달문 2-20).

원인은 범위를 **음성 조건**(사실경위서가 아님)으로 넓힌 것이다. `DOC_KIND_OTHER`에는 분류되지 않은
소송 관련 문서가 모두 들어가므로, 7순위로 보호하던 **소송서면 사이의 정상적인 변론 요지 재진술**과
표제를 판별하지 못한 서면들이 원문 자리에 들어와 오탐이 됐다.

**이번 설계는 음성 조건을 쓰지 않는다.** 원문이 서증 원본임을 **적극 판별**(표제 기반 양성 판정)해야만
범위에 든다. 판별되지 않은 문서(`DOC_KIND_OTHER`)는 지금처럼 원문 자리에 들어오지 않는다.
따라서 `PLEADING ↔ PLEADING`·`PLEADING ↔ OTHER`는 **구조적으로** 결과를 낼 수 없고,
7순위 보호는 조건식 자체로 유지된다.

## 3. 어떤 문서를 원문 범위에 넣는가 — 서술형과 정형의 구분

규칙의 취지는 "대리인 서면이 **남이 쓴 서술**을 제 변론인 척 옮겨 적었다"는 단서다. 그래서 원문 범위는
**서술형 원본 서증**으로 한정한다.

| 넣는 것(서술형 원본 서증) | 넣지 않는 것 | 이유 |
|---|---|---|
| 조사·사고·상황·점검·감사 보고서, 감정서·감정평가서, 소견서, 진단서, 진료기록·의무기록, 시말서 | 계약서·합의서·약정서·각서, 영수증·명세서·내역서, 증명서 | 처분문서·정형 서증의 문구를 서면에 그대로 옮기는 것은 **정상 인용**이다. 넣으면 오탐이 된다 |
| | 소장·준비서면·답변서·의견서(= `PLEADING`) | 7순위 정상 보호 대상 |
| | 진술서·사실확인서(= `STATEMENT`) | 이미 4순위(B등급)가 다룬다 |
| | 표제를 판별하지 못한 문서(= `OTHER`) | 과거 시안의 오탐 원인 |

'의견서'(소송서면)와 '소견서'(원본 서증)는 다른 문서다. 어휘를 겹치지 않게 둔다.

## 4. 변경 설계

1. 새 상수 `DOC_KIND_EVIDENCE_ORIGINAL`("서술형 원본 서증, 사실경위서 외")을 더한다.
2. `_EVIDENCE_ORIGINAL_TITLE_RE`를 기존 `_FACT_CONFIRMATION_TITLE_RE`와 **같은 엄격함**으로 만든다.
   - 첫머리 단독 표제 행만 본다(1쪽 상단 블록 5개 + 상단 15줄/600자).
   - 기존 공통 배제를 그대로 받는다: 목록 줄(`_HEADING_LIST_ITEM_RE`), 직위 낱말(`_HEADING_JOB_TITLE_RE`),
     서술 문장(80자 초과·종결 구두점·어미).
   - 파생 문서명은 배제한다: `사본`·`송부`·`안내`·`요청`·`제출`·`접수`·`발급`·`회신`.
3. `_document_title_kind`에서 사실경위서 검사 **뒤**, 소송서면 검사 **앞**에 새 표제를 확인한다.
   사실경위서로 잡히던 문서의 판정은 바뀌지 않는다(순서로 보장).
4. 5순위 조건을 `other_kind in (DOC_KIND_FACT_CONFIRMATION, DOC_KIND_EVIDENCE_ORIGINAL)`로 넓힌다.
   등급(C)·심각도·문구·사람 확인 표시는 그대로 둔다. 원문 종류를 구분해 기록만 남긴다
   (`copy_category`: 기존 `FACT_CONFIRMATION_REPLICATION` 유지 / 새 `EVIDENCE_ORIGINAL_REPLICATION`,
   `rule_id`도 같은 방식으로 나눈다). 기존 결과의 키·값은 바꾸지 않는다.
5. 이른 종료 게이트(`has_statements or has_facts`)에 새 종류를 더한다. 더하지 않으면 새 경로가
   아예 실행되지 않는다.

바꾸지 않는 것: 문장 유사도 기준(`COPY_SIMILARITY` 0.9·어간 부분열 0.85), 서증 정식 원용 표기 문장 제외,
증거설명서 호증 항목 제외(민사소송규칙 제106조 예외), 4순위 진술서 경로(B등급), 공용 입력
(`exhibit_rows()`·`_sentences_for_copy`), 보호 경로, 기준선.

## 4-1. 1차 판정 보완 — 파생 문서명 배제를 표제 줄 전체로 (2026-11-18)

평가 측 1차 판정(#330, head `c89e8dd`)에서 결함이 확인됐다. 4절 2항의 파생 문서명 배제를 **표제 정규식의
뒤 낱말 제한에만** 걸어 두어, 앞·괄호 축이 남았다. `사본진단서`·`진단서(사본)`·`진단서[송부]`가
`EVIDENCE_ORIGINAL`로 분류되고 합성 소송서면과 같은 본문을 붙이면 새 C등급 경고가 났다
(기준 Steve에서는 세 경우 모두 `OTHER`·경고 0건). 처음 시험이 `점검보고서 사본 송부`처럼 공백 접미만
검사해 이 축을 놓쳤다.

구현 측 재현에서 평가 측이 든 3건 외에 3건이 더 나왔다: `송부진단서`·`진단서(송부)`·`진단서(발급)`·
`감정서[회신]`. 반면 `진단서 - 사본`·`접수보고서`·`보고서(제출)`은 이미 `OTHER`였다.

**고친 방법**: 파생 문서명 낱말을 `_DERIVED_DOC_NAME_RE`로 한 곳에 모으고, 표제 줄에 그 낱말이 있으면
**분류 전에** 배제한다. 축(붙여쓰기·띄어쓰기·괄호·대괄호·구분자)에 무관하게 한 번에 걸린다.
정규식 안의 기존 뒤 낱말 제한은 그대로 두었다(이 줄 단위 가드가 상위 조건이다).
파생 낱말이 섞인 표제는 분류되지 않아 기준과 같은 `OTHER`가 되므로, 과잉 배제의 방향은 안전하다.

**기존 사실경위서 경로에도 같은 구멍이 있다(이번 범위 밖, 사용자 결정 필요)**:
`사실경위서(사본)`·`사실경위서[송부]`는 기준 Steve에서도 `FACT_CONFIRMATION`으로 분류된다.
제 변경으로 생긴 것이 아니라 기존 동작이며, 고치면 기존 탐지 결과가 바뀌어 고정·은퇴 점수에 영향을
줄 수 있다. 그래서 이번 보완에서는 손대지 않고 보고만 한다.

## 5. 수용 기준(구현 측이 확인할 것)

- 양성 3건 이상: 소송서면이 보고서·감정서·진단서 계열 원본 본문을 통복제한 꼴(문서·문장이 서로 다른 값).
- 대조 3건 이상: ① 소송서면 ↔ 소송서면 정상 재진술 ② 파생 문서명(`… 사본 송부` 등) ③ 계약서·영수증 등
  정형 서증 인용 ④ 목록 줄·직위 낱말 꼴.
- 회귀: 고정 dev·holdout 및 확인 오탐 불변, **은퇴 5세트 집계 비교에서 후퇴 0·오탐 증가 0**
  (과거 시안이 깨뜨린 지점이므로 이 항목이 핵심 관문이다).
- 은퇴·봉인 세트의 문서 내용은 열람하지 않는다. 구현은 구조로만 하고, 득점 여부는 평가 측(Codex)이 잰다.

## 6. 측정하지 못하는 것

놓친 은퇴 항목이 실제로 득점되는지는 구현 측이 확인할 수 없다(집계 비교만 가능하고 항목별 내용은
열람 금지). 득점 효과는 평가 측 판정에서 가린다. 이 메모의 점검 통과가 수용을 뜻하지 않는다.
