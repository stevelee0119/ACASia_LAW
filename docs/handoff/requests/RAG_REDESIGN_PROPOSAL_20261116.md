## 2. 권고 구조: 수집·색인과 문서 검증을 분리

```text
Drive 변경 목록 + 정기 전체 대조
  → 권한/리비전 확인 → 영속 작업 큐 → 원본 수집
  → 구조 추출/OCR/쪽별 진단 → 문단·조항·표 행 청크
  → 단어 색인 + 의미 벡터 + 판례/법령 식별자 색인
  → 검증된 자료 판 발행

입력 문서 → 기존 개인정보/인젝션 보호 → 주장·인용·쟁점 분해
  → 고정된 자료 판에서 주장별 다중 검색
  → 후보 합집합·재정렬·인접 문맥 복원
  → 근거 인용 대조 → 지지/모순/자료 부족 판정
  → 출처·쪽/행·인용·적용시점·검색범위 표시
```

### 자료 수집

- Drive는 원본 저장소로 사용한다. 문서 검증마다 Drive 서버의 본문 검색을 통과해야 로컬 색인에 들어가는 구조를 종료한다. 읽기 권한이 있고 지원 형식인 모든 자료를 질의와 무관하게 수집 대상으로 등록한다.
- 변경 토큰/리비전 기반 증분 동기화와 정기 전체 목록 대조를 함께 사용한다. 실패한 페이지나 권한 오류를 삭제로 오인하지 않는다. 파일명/폴더명은 검색 가점·설명 자료이며 탈락 조건이 아니다.
- 파일·쪽 단위 영속 작업, 재시도 횟수, 마지막 성공 리비전, OCR 재개 지점을 저장한다. 영구 실패를 무한 반복하지 않으며, 실패한 쪽 때문에 나머지 파일 수집을 막지 않는다.
- 텍스트 추출 완료, OCR 완료, 확인된 빈쪽, OCR 저품질, 미처리, 오류를 구분한다. 이미지가 없다는 추정만으로 빈쪽을 확정하지 않는 대조를 둔다. 표 병합·각주·조항 제목·문단 경계를 보존한다.
- 전체 색인 완성 전 서비스 사용을 허용하더라도 포함/제외/미완료 리비전을 명시한 스냅샷을 발행한다. 단일 READY 표지로 미처리를 숨기지 않는다. 권한 철회·삭제 자료는 과거 스냅샷 검색에서도 즉시 차단한다.

### 검색

- 문서 하나를 대표어 두 개로 축약하지 않는다. 주장별로 행위·주체·법적 쟁점·사실 조건·인용 식별자를 분리하고, 복수 쟁점에 각각 검색 예산을 배분한다. 예산 초과 주장은 명시적으로 미검토다.
- 세 경로를 합친다: (1) 사건번호·법령명/조문·서지 식별자 정확 조회, (2) 한국어 단어/형태소 또는 문자 n-gram 검색, (3) 한국어 법률자료에서 검증한 의미 임베딩 검색. 정확 조회는 모델 질의 변환에 의존하지 않는다.
- 초기 단어 검색과 의미 검색 후보를 합치고 순위 결합·재정렬한다. 최초 후보는 넓게 받고 최종 근거는 엄격하게 고른다. 파일 이름이나 특정 표현이 없다는 이유로 관련 본문을 읽기도 전에 제외하지 않는다.
- 법령 버전·관할·판결 시점·다수/별개 의견·논문과 판결의 출처 종류를 보존한다. 불확실한 메타데이터를 엄격한 필터로 써 정답 자료를 날리지 않는다. 이전 시점 자료도 필요한 경우 설명과 함께 비교한다.
- 문단/조항/표 행을 기본 단위로 찾고 상위 제목·인접 문맥을 복원한다. 같은 사건·판례집의 중복 조각이 후보 예산을 독점하지 않도록 자료별 다양성을 유지한다. 판례표는 표 행의 사건번호/판시사항 경로를 별도로 유지한다.

### 근거 판정과 보호

- 검색 후보, 모델에 전달한 근거, 최종 인용 근거를 별도로 기록한다. 인용 문자열과 쪽/행 위치가 저장 원문에 실제 있는지 기계적으로 검사한다. 모델의 해석은 그 위에 얹는다.
- 입력 문서만 검증 대상으로 삼는 사용자 정책을 유지한다. 공식 DB/RAG를 지시문 탐지로 격리·삭제하지 않는다. 출처 본문을 프로그램 실행 명령으로 승격하지 않는 입력 경계와 도구 권한 분리는 유지한다.
- 입력 문서의 인젝션 탐지, 개인정보 마스킹, 외부 전송 제한, 사용자/조직별 접근 통제는 그대로 유지한다. 출처의 지시문 탐지 면제는 개인정보 보호 면제가 아니다.
- `자료가 없거나 찾지 못함`, `수집/검색 범위 미완료`, `근거 상충`, `판정할 근거 충분`을 구분한다. 검색 실패를 곧바로 허위 주장이나 인용 부존재의 증거로 사용하지 않는다.

## 3. 구현 선택과 단계적 전환

권고: 기존 PostgreSQL/pgvector와 작업 큐를 활용하되 **참고자료 전용 저장 모델**을 만든다. 입력 문서 테이블의 기존 1536차원 벡터 컬럼을 임의로 재활용하지 않는다. 임베딩 모델·차원·청크판·색인판을 고정하고 교체 시 별도 색인을 만든다. 실제 운영 확장/용량은 마이그레이션 전에 확인한다.

1. **가장 먼저 후보 누락을 제거:** 비동기 전량 수집과 주장별 단어/식별자 검색, 범위 진단을 먼저 구현한다. 현행 이름/대표어 게이트는 참고용 가점으로 낮춘다. 외부 벡터 서비스를 추가하지 않아도 이 단계에서 핵심 누락 원인을 제거할 수 있다.
2. **의미 검색 추가:** 독립 정답 자료로 한국어 법률 검색을 비교한 뒤 임베딩과 재정렬을 추가한다. 벡터 검색만으로 대체하지 않는다. 지연·메모리·색인 비용을 측정하고, 참고자료를 외부 임베딩 API에 새로 전송하는 경우 전송 정책을 먼저 확인한다. 기본 설계는 승인된 환경 내부 처리다.
3. **그림자 비교:** 같은 입력·같은 자료 판에서 기존/신규 검색을 병렬 비교하되 제품 표시 결과는 기존 경로로 유지한다. 누락·오선택·인용 정확성·미완료 상태·시간/비용을 확인한 후 전환한다.
4. **제한 전환 및 복구:** 사용자/평가 범위별 전환과 즉시 이전 색인으로 되돌릴 수 있는 설정을 둔다. 권한 철회 데이터는 되돌리기 대상에서도 제외한다. 기존 원문·출처 ID·기록을 보존하고 안전한 마이그레이션 후 구 색인을 정리한다.

새 검색 서버를 별도로 도입하는 안은 자료량·동시성 측정 후 결정한다. 현재 확인된 실패를 해결하는 데 반드시 새 외부 벡터 DB가 필요한 것은 아니다. 모든 자료를 매번 LLM에 전송하는 방식은 비용·문맥 제한·누락 추적 문제 때문에 권고하지 않는다.

## 4. 수용 기준과 측정

- 기존 공개 대조군: TK-180 정상 4형식 각각 5/5, 입력 공격 4종 HIGH 유지, case9 기존 23/23 유지 및 RAG 대조 5/5. 이것은 최소 회귀 조건이며 일반화 증거 전체가 아니다.
- 독립 검색 세트: 다쟁점 문서, 제목과 무관한 파일명, 유의어·약칭, 다른 시점/관할, 유사하지만 무관한 자료, 긴 문헌의 뒷부분, 판례표, 중복 자료를 포함한다. 설계/보정에 쓴 사례와 분리한다.
- 각 주장에 관련 근거의 위치와 지지/모순/무관 정답을 붙인다. 후보 재현율(Recall@K), 최종 근거 정확성, 무관 자료 채택, 실제 인용 원문 일치, 미확인 표시의 정직성을 따로 측정한다. 수치 목표는 독립 세트의 기준 측정 후 확정하며 현행 기준선을 낮추지 않는다.
- 수집 회귀: 신규/수정/이름 변경/이동/삭제/권한 철회, 파일 일부 손상, 암호화, 스캔·빈쪽·혼합 PDF, OCR 저품질, 재시작/시간 제한/캐시 재개. 합계뿐 아니라 파일·쪽별 원장과 대조한다.
- 운영 지표: 최초 색인 시간과 증분 갱신 지연, 검증 시 검색 지연의 중앙값/상위 지연, CPU·메모리·LLM 호출비용, 미검토 주장 비율. 빠른 대신 읽지 않은 자료가 증가하면 개선으로 인정하지 않는다.
- 입력 보호·개인정보·타 조직 자료 격리·출처 역할·보고서/UI 상태 표시·정리 절차를 기존과 함께 시험한다. RAG 개편 때문에 다른 기능 검증을 축소하지 않는다.

## 5. 책임과 현재 한계

제품 구현은 구현 측, 독립 명세·온라인 비교·수용은 평가 측이 맡는다. 새 구조는 아직 구현·실측하지 않은 제안이다. 현재 확인된 후보 누락과 반복 동기화 구조를 해결할 수 있는 설계이지만, 실제 성능은 위 시험으로 판정한다. '완벽'을 선언하는 대신 검색 범위·근거·미처리 원장을 통해 오류를 확인하고 재현할 수 있게 한다.
