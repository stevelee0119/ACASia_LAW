# TK73 optional review-state design, not authorized criteria

Status: a possible criteria review is pending. This memo authorizes nothing. Product findings/status/grades, original tests936, UNKNOWN fallback, GLOBAL checks, TK64, date/amount/list-missing, baselines and acceptance counts remain unchanged. Neither a review-state label nor the public capability results complete TK73.

Separate three questions in an internal proof record: **source validity** (original native occurrence versus application mapping versus missing/uncertain), **payload role** (positively proved TITLE, positively proved NON_TITLE, mixed/uncertain), and **identity conflict** (distinct complete title values, distinct non-title propositions, unresolved literal difference). They are independent dimensions. Exact glyph provenance does not establish a title role; different description text does not establish different formal names; lack of title proof does not establish equality or NON_TITLE. Proof records carry original occurrence/parent/exact-party-number-branch intervals and validity flags, with no new persistent raw-source copies.

The confirmed route retains A for genuine complete-title differences and every protected legacy positive. It evaluates ALL original same-key alternatives globally, including other parents/branches, unknown or uncategorized origins and full proposition/qualification differences. No local narrative certificate may partition those alternatives away. Existing original UNKNOWN fallback remains A where it was A; a generic UNKNOWN flag never moves a finding to another tier.

An optional REVIEW_CANDIDATE could be considered only with **positive independently verified non-title/narrative ownership**, complete source coverage, exact occurrence/key ownership and no confirmed or protected complete-title/global conflict. A native purpose cell with authoritative source field boundaries is an example of verifiable NON_TITLE ownership; arbitrary headings, finite endings, balanced wrappers, coordinate tokens or registered keys are not. The current native PDF purpose controls are already handled correctly by the existing product. Any new ownership primitive needs original-source positive/opposite controls first. Mixed or missing roles preserve fallback. These requirements may leave the current unresolved path unchanged.

The initial criteria-review artifact would be a parallel diagnostic receipt: current original finding and grade, proposed evidence-state, proof intervals and veto reasons. It must not remove, downgrade or relabel existing outputs or change scoring. Showing a proposed review candidate is not title equality or a finding exemption. Any later movement into a separate user-facing verification tier requires explicit user acceptance of a concrete criteria proposal and independent evaluation; selecting “review the proposal” alone is not implementation approval.

Required review: original936 expectations unchanged; native/untyped role counterparts; genuine plain, comma/colon, sentence, date and qualified titles; contradictory whole propositions; cross-parent/party/branch/uncategorized alternatives; negative/uncertain clauses; quote/NFKC/join/source uncertainty; field/date/source immutability; forward runtime and privacy lifecycle. Record operational row-free controls separately. Measure proposed candidates against unchanged current findings; do not count uncertain or suppressed outputs as AFP0 success. Reject any proposal that only shifts the same unresolved error into another counter or erases genuine A.

Without a new positive ownership/complete-caption relation proof, a criteria-preserving operational change is still blocked. This plan offers verifiable evidence accounting and a safe review boundary, not a guarantee of target effect or a workaround for missing evidence.
