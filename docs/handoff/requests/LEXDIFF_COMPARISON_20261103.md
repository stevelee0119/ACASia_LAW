# lexdiff 대 ACASia_LAW 재비교와 추가 이식 후보 (2026-11-03, 평가 측, 0.17.0 배포 뒤)

- 기준
  - ACASia_LAW: 운영 0.17.0(main `deb387d`). 같은 제품 코드인 Steve `892bbd8`을 읽었다.
  - lexdiff: 11-02 정적 분석(`2bcf525`, `LEXDIFF_COMPARISON_20261102.md`)을 재사용했다. 새로 조회하지 않았다.
- 한계
  - lexdiff는 실행하지 않았다. 수치는 그 저장소의 자체 문서에 적힌 값이다.
  - 두 프로그램을 같은 입력으로 비교하지 않았다.
  - 아래 이식 후보의 효과는 오프라인 평가 세트로 재지 못한다. 고정·은퇴 세트에는 해당 꼴(조례 인용 등)이 0건이다.
- 라이선스: lexdiff는 BSL 1.1이다. 코드·데이터는 복사하지 않고 아이디어만 참고한다.

## 2. 코드로 확인한 추가 격차 (Steve `892bbd8`)

1. **자치법규(조례·규칙) 공식 조회가 없다.**
   - 어댑터가 조회하는 대상(target)은 eflaw·law·admrul·expc·decc·prec·detc뿐이다(`source_adapters/official_legal.py`·`law_go_kr.py`). 자치법규 대상이 없다.
   - 그런데 `source_review._is_statute_form`이 '조례'를 일반 법령 접미사로 본다(344~347행).
   - 그 결과 조례 인용은 국가 법령 목록에서 찾지 못하면 `_law_absent` 3번 분기로 가서 STATUTE_NONEXISTENT CRITICAL을 받는다(426~431행 docstring).
   - 운영 재현은 하지 않았다. 코드 경로로 확인한 사실이다.
   - lexdiff는 조례 검색·비교를 제공한다(README '조례 벤치마킹').
2. **관련 법리 탐색이 사실상 한 가지 쟁점에 고정돼 있다.**
   - `related_authorities.candidates`는 국가계약법 + '지체상금'일 때만 고정된 3개 조문을 낸다(1~20행).
   - lexdiff는 법령·판례 검색을 도구로 호출하고, 판례를 법원 계층 × 연도 감쇠로 순위 매긴다(`precedent-authority.ts`).
3. **위임 연쇄 확인을 사람에게 넘긴다.**
   - `source_review` 649·671·764행이 "위임 근거 … 따로 확인해야 한다"는 메모만 남긴다.
   - lexdiff는 법률–시행령–시행규칙 3단 위임 대조를 제공한다.
4. **개정 전후 조문 대비가 없다.**
   - `temporal_review`는 적용 버전은 고른다. 그러나 개정 전후 조문의 차이(신구조문)를 사용자나 모델에게 보여 주지 않는다. 코드에 신구 대비 기능이 없다.
   - lexdiff는 신구조문 비교와 타임머신 기능을 제공한다.
5. **외부 AI 답변 속 인용을 검증하지 않는다.**
   - `report_engine/external_answers.py`는 답변을 '공식 확인 아님'으로 표시해 보관만 한다.
   - 답변 안의 판례·법령 인용은 공식 DB로 다시 대조하지 않는다.
   - lexdiff의 품질 휴리스틱(도구로 확인하지 않은 인용은 실패)과 같은 원리를 적용할 자리다.
6. **별표 내용 검증이 없다.**
   - 별표 인용은 '본문 밖(버전·부칙·별표)일 가능성' 메모로만 처리한다(515행).
   - lexdiff에는 HWP 별표 파서가 있다. 주 경로는 외부 kordoc에 위임돼 있다.

## 3. 추가 이식 후보 (우선순위)

| 순위 | 후보 | 해결하는 문제 | 예상 효과 | 난이도·위험 | 측정 방법 |
|---|---|---|---|---|---|
| 1 | 자치법규 공식 조회(조례·규칙): 자치법규 목록·본문 조회 추가, 조례 꼴 인용은 이 경로로 존재·조문 확인. 찾지 못하면 '조회 범위 내 미확인'(UNVERIFIED)으로, 국가 법령 부존재 CRITICAL과 구분 | 실재하는 조례 인용에 붙는 '존재하지 않는 법령' CRITICAL 오탐(TK-130b와 같은 계열) | 행정·지방계약·인허가 서면의 최고 심각도 오탐 제거. 오프라인 점수 기여 0(세트에 조례 0건) | 중. 어댑터 1개·판정 분기. 실제 API 응답 형식 확인 필요(미검증) | 온라인: 조례 인용 서면 탐침(평가 측 출제) |
| 2 | 외부 AI 답변 인용 재검증: 붙여넣은 답변에서 인용을 추출해 기존 공식 검증기로 대조, 표에 '답변 속 인용: 확인/미확인/불일치' 표시 | 외부 AI가 지어낸 판례·조문이 '참고 의견'으로 보고서에 그대로 실림 | 보고서 신뢰도·안전성. 결정적이며 기존 엔진 재사용 | 중. 추출기·검증기 재사용, 화면·보고서 표시 추가 | 오프라인 합성 답변 시험 + 온라인 1회 |
| 3 | 관련 판례·법리 탐색 일반화 + 판례 권위 가중: 쟁점(무리한 주장 후보)마다 공식 판례 검색 상위 N건을 법원 계층·선고 연도·전원합의체로 정렬해 법리 검토 모델에 반대 근거로 제공. 지어낸 인용 생성 금지, 공식 조회 결과만 사용 | 법리 과장(OVR)·법률 주장 검토가 모델 지식에만 의존(은퇴 세트 OVR 17항목 미탐) | 모델 의존 유형(OVR·LEG)의 근거 강화. 가장 큰 잠재 효과 | 상. 검색 질의 설계, 비용·시간 상한, 개인정보 가림, 오탐 통제. 설계 메모부터 | 온라인 전용(오프라인 재현 불가). 같은 조건 OFF/ON 쌍 |
| 4 | 위임 연쇄 자동 대조: 시행령·시행규칙·행정규칙 인용 시 위임 근거 조문(상위법 '…으로 정한다')을 공식 본문에서 찾아 연결 | 지금은 '사람 확인' 메모로 끝남 | 행정 서면의 위임 범위 일탈 주장 검토 보조 | 중상. 위임 문구 구조 해석 | 오프라인 합성 + 온라인 |
| 5 | 신구조문 대비 표시: 행위시법 판정(TMP) 때 적용 버전과 현행(또는 서면이 쓴 버전)의 조문 차이를 발췌로 제시 | 행위시법 오류의 근거가 버전 이름으로만 제시됨 | 설명력(사용자 확인 시간 단축). 탐지 점수 변화 없음 | 중. 버전 본문 두 개 대조(이미 조회함) | 화면·보고서 시험 |

## 4. 이식하지 않을 것 (11-02 판단 유지)

- 문자열 유사도 본문 일치(L1/L2): ACASia의 수치·기간·어절 대조가 더 보수적이다.
- 기준일 추출: ACASia는 서면에서 사건일·행위시를 따로 다룬다.
- 생성형 답변 품질 지표(RAGAS)와 빠른 경로(fast-path): 생성형 답변용 장치다.
- 브라우저 위장 요청 헤더(UA): 운영 조회가 정상이다.
