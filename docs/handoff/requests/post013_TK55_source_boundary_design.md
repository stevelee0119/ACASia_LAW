# TK55 residual: source/context boundary precheck

Public base: `2a85aa0e043cb6d13993742c2a053a8b048c48d5`. Accepted first-party closed contracts, lossless duplicate-value inspection, mandatory numeric gates, static-source registration and existing name/particle protections remain. This is a design/spike, not a product fix or closure claim.

**Boundary.** Separate a producer's declared envelope from evidence carried in its text leaves, and separate both from fields in a decoded evidence record. The four existing producers define the envelope; exact original-system/output-schema binding authenticates that shape, not the truth or safety of its values. Contract identifiers inside JSON/metadata never establish provenance. No contract grants a PII exemption. Inspect decoded evidence recursively, including duplicates, lists and escaped strings; maintain original-system and assembled-request scans before cost estimation/reservation/provider dispatch. Preserve benign JSON evidence and the original provider payload.

**New evidence to test.** Stop guessing a role from an expanding key vocabulary. A comparison-only value-first spike identifies complete Korean name-shaped scalar values in decoded object fields using the existing name grammar, regardless of opaque key spelling. It continues baseline PII inspection first and then tests a pre-budget refusal for such unresolved structured atoms. It does not apply the new inference to ordinary prose or to declared envelope metadata. Encoded JSON inside an evidence leaf remains structured inspection input; being quoted evidence does not immunize it. Existing name+particle and phone/RRN rules still run unchanged.

**Irreducible counterexample.** A three-syllable ordinary noun can satisfy exactly the same surname/name grammar as a person. An untyped `{"opaque": "문서함"}` can be a storage category or a person's name; no source, key-independent shape rule or decoding operation can establish which. The spike must expose this counterexample rather than pass only convenient controls. Blanket refusal of every such atom closes the old role cases but changes benign legacy compatibility. Calling it PERSON or bypassing it under a forged contract marker does not solve the ambiguity. No word/name dictionary or numeric overblock limit will be changed.

**Compatibility decision for root precheck.** The viable source-based extension is an immutable, exact-consumer-bound schema for an actual additional producer, with fields declared as structured records or free-text evidence. It can reject unsupported object fields without expanding role nouns. It cannot resolve arbitrary callers' untyped atoms while preserving their current acceptance. A generic user-supplied schema/marker is insufficient provenance. If root accepts candidate-only legacy refusal after its unchanged independent normal gate, the two implementation-owned old residual-PASSED tests need an explicit scoped change; otherwise they remain unchanged and arbitrary-role closure remains unproved. No production default will change before that decision and counterexample review.

**Public precheck.** At least three distinct synthetic names, opaque keys and benign controls; nested/duplicate/Unicode-escaped records; user/original-system/schema/metadata; forged markers; actual four builders including argument retries and AI sampling; fake-provider calls and reservations counted through `LLMRouter.run`. Show both safe controls and unavoidable name-shaped noun refusals. Run only this spike and relevant existing producer tests. Product/other-track files, protected expectations, versions, pricing and CI remain untouched. Root independently judges the original gates and whether a stronger boundary is compatible; a successful synthetic spike alone is not TK55 acceptance.

**Executed synthetic comparison.** `tests/regression/test_post013_tk55_boundary_spike.py`: 141 passed (108 unknown-atom/encoding/position cases; 12 benign controls; 6 noun-collision diagnostics; 3 forged-marker cases; 3 existing-PII-priority cases; 9 actual-builder cases with further benign/unknown encoded-evidence variants). All three ordinary nouns in both system/user positions pass baseline but the value-only spike refuses them before budget/provider. The result rejects blanket value-only inference as a compatible product proposal; it does not count collateral refusals as privacy acceptance. No product change or old expectation edit was made.
