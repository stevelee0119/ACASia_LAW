# TK73 bounded coordinate-only scope proposal

This is a design proposal, not an approved product rule. The free-remainder spike remains HOLD. Test a narrower three-way relationship: (1) a source-proved, independently closed inventory with two definition entries; (2) a later original **plain complete title** row, with no colon/prose clipping; and (3) an independent native whole-line explicit equality `complete title = exact exhibit reference` in a separately closed peer section. The equality has exactly one observed operator and observed spaces, no extra text, negation/condition/qualifier, protected context or synthetic token boundary. It asserts only the complete literal value; it does not supply generic narrative predicates or remove quotation wrappers.

The inventory entry must begin with that entire independently supplied title and an observed delimiter; its **entire** remainder must parse as a coordinate-only grammar: one decimal coordinate or bounded range, one existing page/line unit, and optional single sentence punctuation. No arbitrary prefix/suffix words, dates, captions, adjectives, multiple coordinates, lexical unit prefixes or Cf/symbol uncertainty are accepted. A full match is necessary; `COORD.search` cannot license any remainder deletion. Title punctuation/quotes/dates remain inside the exact complete value. Syntax needs native occurrence coverage and observed boundaries, never fragment ends or NFKC-created tokens.

Before comparison-local projection, retain every original same-party/number/branch origin globally. Any original name that differs from its complete native item value (including legacy date truncation), competing complete inventory caption, source-UNKNOWN/table/uncategorized origin, other-parent/branch identity or non-inventory value other than the exact plain complete title vetoes. The equality statement has a recorded actual occurrence and must not produce a hidden original row. Only a certified inventory candidate can be projected to that exact plain title; every original row, original date/name/author/purpose, population, interval end and other comparison remains unchanged. This scope deliberately does **not** transform body prose or solve the free-description examples. The later pure equality is independent evidence, not an exemption for a registered key.

Public actual TXT/PDF/DOCX precheck will include at least three coordinate/range/unit variants against plain-title repeats, and opposite full-title/qualified coordinate/lexical-prefix/negative-or-conditional equality/quoted/other-parent/global alternative/missing-source cases. Baseline warnings and prediction remain separate. Carry all prior 936 expectations unchanged before a product candidate. Root approval is required after those controls; this bounded capability has no demonstrated relevance to the remaining formal target.

Native provenance must remain request-local proof metadata outside the serialized NormalizedDocument: ownership intervals and validity flags, not duplicate raw source strings. Document `asdict`, cache/log/export/masking and LLM payloads must never acquire the sidecar. Cache reload or changed/masked source/reading coordinates invalidates the affected proof to UNKNOWN; the sidecar cannot survive an unverifiable parse→reading transformation. Production capture would reuse original parse occurrences before normalization/substitution and store exact lexical/space validity flags with native indices. PDF decoded extraction text is not encoded glyph/byte proof. No production sidecar or parser change is implemented here.

Public precheck receipt: 81 actual generated documents, 9 candidate positives and 72 abstaining opposites, zero expectation mismatches; every original exhibit row unchanged. Original product findings are measured separately and unchanged. The prototype now indexes original row correspondence by actual paragraph/ref-span/exact-key occurrence, avoiding a same-key row Cartesian lookup. It is not a production runtime certificate; native PDF provider geometry lookup and existing parser/finding work remain diagnostic-only. Neither these candidate certificates nor the source-only 198 records authorize product changes.

The source-to-original-name equality veto keeps date-truncated originals out of this scope. It does not repair protected-date title misses. Additional native full-coordinate-title, compatibility equality and protected-date uncertainty controls are separate from the initial81 receipt.
