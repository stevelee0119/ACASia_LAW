# TK73 EOF source-support and trailing-context refinement

Design comparison only; no product/status/grade/936/scoring changes. The original111 and dated117 scripts and expectations remain frozen. The original111 parallel receipt now exposes nine extra genuine `date_guard` confirmation losses with no extra false-candidate separation. User criteria approval is still absent.

**Reason for HOLD.** Counting PDF decoded characters or DOCX `w:t` occurrences is not proof that all native source content is supported. An image-only final PDF page and native DOCX `w:sym` can add material without either sequence changing. A trailing unclosed quote after the last parsed item can leave that item's source mapping intact while the outside context is uncertain. These are genuine gaps in c16's source-EOF candidate, not product regressions or grounds to relax UNKNOWN.

**Separate three witnesses.** Report decoded lexical exhaustion, supported-source coverage, and closed protection context independently. A new source-extent certificate requires all three; lexical exhaustion alone is insufficient. It still cannot certify semantic heading/title/description closure. Any original decoded occurrence missing from reading keeps the lexical check false. Never delete/align away excluded material, reorder occurrences, infer the native endpoint from reading, or waive failure for a registered key.

**Bounded support contract.** For public native-text PDF comparisons, reject EOF if any page has non-character source objects or annotations. Images, vector marks, forms and unknown page-object categories remain unsupported; they cannot be declared empty because decoded text is absent. Independently proven TITLE-A conflicts do not need this EOF witness and stay A. For bounded DOCX main-body comparisons, accept only the exercised plain paragraph/run/text grammar with explicit non-text page-layout metadata; unknown child/run types, symbols, pictures/objects/drawings/fields/break sources, tables, header/footer/comment/footnote sources and ambiguous owners reject support. Unknown formatting structures remain unsupported until separately proved; do not generate syntax from automatic labels, compatibility folds or missing nodes. TXT additionally requires exact decoded ownership and rejects unproved format/private/control/surrogate content. These are structural source-type checks, not case vocabulary exceptions.

**Trailing protection.** Scan the entire actual reading context using the existing forward quote/bracket protection grammar, including compatible single-character protection signals. An open context at available source end rejects EOF and any pending route that depends on that outside context. The scan must include material after the final parsed item, not just stored row payloads. Explicitly closed earlier intervals stay separate; no protected marker may certify close or a new scope. Balanced literal titles and current protected-row/global guards remain unchanged. Unknown compatibility/source content is never an opener/closer authentication shortcut.

The comparison will retain the old c16 result for disclosure but veto only its proposed pending/EOF state when new support/context checks fail; original product findings, complete record/date bindings, all-origin groups and calendar A remain intact. Native declared TITLE conflicts remain A. Actual image-page, DOCX-symbol and trailing-quote negatives must reject certification; ordinary native text, balanced context and genuine mixed-role positives must expose any remaining confirmation loss. Apply the refinement separately to the frozen original111 and dated117 populations and report changes rather than revising their expected results. Broader source-provider support requires another independent public proof; missing native-to-reading coverage remains a residual.
