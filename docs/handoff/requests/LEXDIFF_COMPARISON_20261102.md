# lexdiff 기술 분석과 ACASia_LAW 비교 (2026-11-02, 평가 측)

사용자 지시(11-02): lexdiff(https://github.com/chrisryugj/lexdiff)의 기술 노하우를 분석한다. 그 결과로 ACASia_LAW와의 우열·기술 우위를 검토하고, 이식할 만한 요소의 구현 지시를 쓴다.

## 0. 조사 범위와 한계

- **조사 대상**
  - lexdiff는 `2bcf525`(2026-10-11) 시점의 소스를 정적으로 읽었다.
  - 저장소 밖 사본을 썼고, lexdiff 코드는 실행하지 않았다.
  - ACASia_LAW는 Steve `debbe83`(0.16.0)을 기준으로 했다.
- **측정하지 못한 것**
  - lexdiff 운영 서비스의 실제 정확도와 응답 속도.
  - lexdiff 시험 스위트 실행 결과.
  - 같은 입력으로 두 프로그램을 나란히 비교한 결과. 두 프로그램은 목적이 달라 공통 입력이 없다.
  - lexdiff의 수치는 그 저장소 문서에 적힌 값이다.
- **라이선스**
  - lexdiff는 BSL 1.1이다. 비운영 사용만 허용되며, 2030-04-14에 Apache 2.0으로 전환된다.
  - 따라서 운영 중인 ACASia_LAW에 lexdiff 코드나 데이터를 복사하지 않는다. 아이디어만 참고해 새로 작성한다.

## 1. lexdiff의 기술 노하우

| 영역 | 내용 | 위치 |
|---|---|---|
| 도구 호출형 법률 RAG | Claude·Gemini 엔진이 법제처 API를 도구로 호출한다. 도구 계층, 도구·답변 캐시, 단순 질의의 LLM 생략 경로(fast-path)를 둔다 | `lib/fc-rag/*` |
| 인용 검증 | 법령 ID 확인 → 조문 존재 확인 → 본문 일치 판정. 일치는 L1(정규화 뒤 30자 이상 연속 일치)과 L2(문자 bigram Jaccard ≥ 0.25) 두 단계다 | `lib/citation-verifier.ts`, `lib/citation-content-matcher.ts` |
| 법령명 유사 매칭 | 어미를 떼고 다시 검색한 뒤, 공식 약칭이나 정식명과의 부분수열로 점수를 매긴다 | `lib/law-name-match.ts` |
| 기준일 추출 | 질의 속 날짜 뒤에 시점 신호어(허가·착공·당시 등)가 올 때만 기준일로 인정한다. 개정일·판례 선고일은 제외한다 | `lib/fc-rag/reference-date.ts` |
| 판례 권위 점수 | 법원 계층 × (0.5 + 0.5 × 연도 감쇠, 반감기 15년)에, 전원합의체이면 ×1.2 | `lib/fc-rag/precedent-authority.ts` |
| 응답 품질 휴리스틱 | 도구를 호출하지 않고 인용한 답은 '실패'로 판정한다. 연혁 표지가 있는데 답이 현행성을 언급하지 않으면 등급을 낮춘다 | `lib/fc-rag/quality-evaluator.ts` |
| 법령 서비스 기능 | 신구조문 비교, 3단 위임 대조, 영향 추적, 조례 벤치마킹, 위임 미비 탐지, 타임머신, HWP 별표 파서 | `lib/*`, README |
| 평가 | RAGAS 10문항. 자체 보고 종합 0.47(D), Faithfulness 0.50 (2026-03-10) | `evaluation/RAGAS_REPORT.md` |
| 규모 | TS/TSX 약 7.3만 줄, 시험 케이스 약 788개 | 정적 집계 |

## 2. 영역별 우열

| 영역 | 우위 | 근거 |
|---|---|---|
| 법령 열람·검색 기능의 폭과 편의 | lexdiff | 조례, 3단 위임, HWP 별표, 영향 추적처럼 ACASia에 없는 법령 서비스 기능이 많다 |
| 제출 서면 검증(인용 존재·버전·내용) | ACASia | MST·시행일 단위로 버전을 조회하고 부칙을 검토하며, 수치·기간 대조 규칙을 둔다. lexdiff는 문자열 유사도만 쓰고, 자체 주석 기준으로 무관한 조문 사이의 유사도도 0.05~0.10까지 나온다 |
| 시점(행위시법) | ACASia | 기준일 버전 선택에 소급·폐지 경계 차단 등을 둔다(`temporal_review.py`, 937줄). lexdiff는 질의에서 기준일을 추출하는 데 그친다 |
| 법령명 해소 | **lexdiff** | ACASia는 별칭 표 20여 개, 문서 근거, 공식 약칭 완전 일치에만 의존한다. 이 셋이 모두 실패하면 CRITICAL 오탐이 난다 → TK-130 |
| 원숫자 항 번호 범위 | 같음(ACASia 일부 결함) | ACASia의 주 경로는 ㊿까지 처리하지만, `temporal_review`·`provision_content`는 ⑳까지만 처리한다 → TK-130 2번 항목 |
| 평가 체계 | ACASia | 고정 dev 82.6·holdout 81.9·오탐 0, 봉인·은퇴 세트, 점수 하락·회귀 게이트, 배포 직후 온라인 점검(23/23)을 갖췄다. lexdiff는 RAGAS 10문항에 0.47이다 |
| 문서 보안(AI 작성·인젝션·개인정보) | ACASia | 별도 엔진이 있다. lexdiff의 `lib/privacy`는 읽지 않았다(미검토) |

**종합:** 법률 문서 검증이라는 ACASia의 목적에서는 ACASia가 기술적으로 앞선다. 근거는 결정적 규칙과 근거 등급, 버전 정밀도, 오탐 통제, 평가 엄격성이다. 법령 정보 서비스의 폭과 사용자 편의에서는 lexdiff가 앞선다. 다만 두 프로그램의 성능을 같은 입력으로 맞대어 측정한 것은 아니다.

## 3. 이식 판단

| 요소 | 판단 | 이유 |
|---|---|---|
| 법령명 부분수열 추정 | **이식(TK-130)** | ACASia의 CRITICAL 오탐을 직접 줄인다. ACASia 규약에 맞게 보강했다: 종류 일치, 약칭이 있으면 약칭과만 대조, 단일 후보, 조문 실존, 'VERIFIED' 승격 금지 |
| 원숫자 ㉑~㊿ | **이식(TK-130 2번 항목)** | 제20항 추출 범위 결함을 바로잡는다 |
| L1/L2 본문 일치 | 이식 안 함 | ACASia의 수치·기간 대조와 어절 차이 비교가 더 보수적이다. Jaccard 0.25 문턱은 다른 말로 바꿔 쓴 내용의 오일치 위험이 있다 |
| 판례 권위 점수 | 이식 안 함 | ACASia는 판례를 검색해 순위를 매기지 않고, 인용된 판례를 검증한다 |
| 기준일 추출 | 이식 안 함 | ACASia는 사건일·행위시를 서면에서 따로 다룬다 |
| 품질 휴리스틱·fast-path·RAGAS | 이식 안 함 | 생성형 답변용 장치다. ACASia의 평가 체계가 더 엄격하다 |
| 법제처 API 브라우저 UA | 불필요 | ACASia 운영 조회는 정상이다(0.16.0 온라인 점검: law_go_kr READY 20건) |
