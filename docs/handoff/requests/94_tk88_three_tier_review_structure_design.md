# 설계 메모: TK-88 검토 화면 3단 체계 개편 및 법률적 검증 분류 설계

- **문서 번호:** `requests/94_tk88_three_tier_review_structure_design.md` (2026-10-21 평가 측 피드백 3개 항목 반영 개정)
- **작성일:** 2026-10-20 (1차), 2026-10-21 (2차 개정)
- **작성자:** Antigravity (구현 에이전트)
- **대상 티켓:** TK-88 (사용자 개선안 3다·4항: 검토 화면 3단 체계 재편)
- **수용 기준:** 탐지 diff 0, 채점기·match_spec 불변, 고정·은퇴 세트 점수 불변

---

## 1. 배경 및 문제 정의

- **현행 한계:**
  1. 출처 확인(공식 DB 판례·법령 조회 결과)과 법리 타당성(주장 내용의 무리함)이 '확인할 항목' 표 한 줄에 혼재되어, 사용자가 "출처가 허위/부존재한 것"인지 "출처는 실재하나 주장이 왜곡된 것"인지 직관적으로 구분하기 어려움.
  2. 주요 참고문헌(RAG) 결과가 표 아래 별도 구역에 접혀 있어 본문 대조 내용과 유기적으로 연결되지 못함.
  3. '주장·쟁점' 탭에 남아 있는 복잡한 워크플로우 입력(쟁점 편집, 인부, 지지 상태 등)은 프로그램 본래 목적인 "서면의 위험 요인 확인"과 괴리됨.

## 2. 3단 체계 구성 및 실제 코드 기반 분류 규칙 매트릭스 (피드백 1·2 반영)

```
[1단] AI 작성·보안 진단 (기존 탭 유지)
  └─ AI 생성 의심 지표, 시스템 지시문/인젝션 채널 탐지

[2단] 판례·법령·주요참고문헌 인용 오류·미확인 검토 (AI 작성 여부 판단과 별개)
  └─ 인용한 판례·법령·참고문헌의 공식 DB 부존재, 서지 불일치, 원문-인용문 불일치, 시적 적용 오류

[3단] 법률적으로 무리한 주장 (기존 '주장·쟁점' 탭 자리 대체)
  └─ 출처는 실재하나 법리 취지에 반하는 주장(법리 검토 '부당'), 참고자료 내용 모순(TK-70)
```

### (1) 실제 `FindingType` 및 `rule_id` 기반 2단/3단 배치 기준표 (피드백 1 반영)

`packages/common/enums.py`에 정의된 실제 `FindingType` 및 엔진 결과 속성 기준 매핑:

| 단 | 실제 결과 유형 (`FindingType` / `rule_id` / 판정 값) | 대상 설명 | 2단/3단 배치 이유 |
|---|---|---|---|
| **2단** | `CASE_NOT_FOUND`<br>`CASE_METADATA_MISMATCH`<br>`CASE_CITATION_ERROR`<br>`CASE_QUOTE_MISMATCH`<br>`LAW_CITATION_ERROR`<br>`ACADEMIC_CITATION_ERROR`<br>`OFFICIAL_NOT_FOUND` | 공식 DB에 판례·법령·논문이 존재하지 않거나, 사건번호·선고일자·법원명 등 서지정보가 불일치하거나 원문과 인용문이 직접 불일치하는 경우 | **순수 출처 및 인용의 진실성 검증:** 서면에 적힌 인용 표기 자체가 실재하는지, 인용 원문이 정확한지를 객관적으로 검증하는 단계 |
| **2단<br>(경계)** | `CASE_HOLDING_DISTORTION`<br>(판시 취지 왜곡)<br>*(피드백 2 반영)* | 판례의 실제 판결요지/판결이유의 객관적 취지와 서면 인용문 간의 괴리 | **2단 배치 이유:** 판례 원문과 서면 인용문 사이의 '객관적 인용 왜곡/불일치'에 해당하므로 출처 인용 검증에 배치. (단, 그 왜곡된 판례를 기초로 한 무리한 주장은 3단과의 상호 참조 링크 제공) |
| **2단<br>(경계)** | `TEMPORAL_LAW_MISMATCH`<br>(시적 적용 오류)<br>*(피드백 2 반영)* | 사건 기준일 당시에 효력이 없는 개정 전 구법령 또는 미시행 법령을 인용한 경우 | **2단 배치 이유:** 법령 조항의 유효성 및 시적 적용 시점의 형식적/객관적 불일치이므로 출처·조항 검증(2단)에 배치 |
| **3단** | `LEGAL_ARGUMENT_INVALID`<br>`AI_HALLUCINATED_CONTENT` (법리 결여 건)<br>`rule_id` = `RAG.REFERENCE_CONTRADICTION`<br>(참고자료 내용 모순, TK-70) | 출처는 실재하거나 서증이 존재하나, 도출된 주장이 법리상 성립할 수 없거나 주요 참고문헌 실무지침과 정면 모순되는 경우 | **주장의 법리적 당부(무리함) 검증:** 인용 출처의 진위와 별개로, 당사자의 공격·방어 주장이 법리적으로 타당한지 여부를 검증하는 단계 |
| **3단** | 법리 검토 표 판정 값:<br>`verdict_label`이 `"부당"`, `"결여"`, `"배척"` 등인 행 | LLM 교차 검토 및 법리 분석 결과 당사자 주장의 타당성이 결여된 행 | 주장의 법률적 타당성 검토이므로 3단에 배치 |
| **분류** | **결과 유형(`finding_type`)이 없는 순수 검토 행** | 공식 DB 조회 결과 및 법리 검토 의견만 존재하는 행 | `official_status === "OFFICIAL_NOT_FOUND"`이면 **2단**,<br>`verdict_label`이 `"부당"`/`"결여"`이면 **3단**에 자동 분류 |

### (2) 복합 결과 처리 및 상호 참조
- 한 인용에서 출처 미확인(2단)과 법리 부당(3단)이 동시에 도출된 경우:
  - 2단 표: '출처 미발견/인용 왜곡' 항목으로 표시.
  - 3단 표: '법률적으로 무리한 주장'으로 표시하되, 상호 참조 링크(`2단 출처 오류 확인 →`)를 제공하여 문맥 단절 방지.

## 3. 법률적 측면의 참고문헌(RAG) 표시 조건

1. **법적 구속력 배제 명시:**
   - 업무편람, 실무제요 등은 행정·사법 실무 해설서일 뿐 법적 구속력이 없음.
   - 판례·법령과 함께 표시되더라도 배지(`참고문헌(구속력 없음)`)를 명시하고, 위험 지수 산정 제외(`gate.py` 159·238행)를 엄격히 유지.
2. **'대조 안 함' vs '부합'의 엄격한 분별:**
   - 색인 범위 제한(운영 기준 31건 중 5건), 주장별 대조 상한, 문서 앞 12,000자 기준 등으로 인하여 대조 대상에 포함되지 않은 문헌/주장은 절대로 '부합'으로 표시하지 않음.
   - 반드시 **'대조 안 함(미대조)'** 상태로 명시하여 사용자가 허위의 안전성을 신뢰하지 않도록 보장.
3. **표 하단 RAG 구역 및 주장·쟁점 탭 정리:**
   - 표 하단의 RAG 구역은 동기화 상태·자료별 처리 기록을 담은 컴팩트한 '참고자료 연결 상태' 1줄 요약으로 축소.
   - 주장별 대조 의견은 3단 '법률적으로 무리한 주장' 표의 4열 요약 블록으로 직접 이동.
   - 기존 주장·쟁점 탭의 불필요한 입력 도구(쟁점 편집, 인부, 지지 상태)는 TK-87과 동일하게 화면에서 제거하고 3단 전용 검토 표로 전환.

## 4. 데이터 계약 및 보고서 영향 확정 (피드백 3 반영)

- **채점기 및 `match_spec` 불변:** 백엔드 API 출력 JSON의 Finding 스키마, 유형 코드, 등급(`EvidenceGrade`), 심각도(`Severity`)는 일절 변경하지 않음 (diff 0).
- **프론트엔드 배치 분리:** `app.js`의 렌더링 단계에서 Finding의 속성(`finding_type`, `category`, `rule_id`, `official_status`, `verdict_label`)을 기준으로 2단과 3단 패널에 나누어 바인딩.
- **보고서 형식별 영향 확정:**

| 내보내기 형식 | 변경 사항 | 호환성 및 기존 시험 대응 |
|---|---|---|
| **JSON** | **일절 변경 없음 (diff 0)** | 기존 스키마, 키 구조(`findings`, `review_items`), enum 값 100% 동일 유지 |
| **HTML** | 기존 '확인할 항목' 챕터 내부에서 소제목을 3단 헤더(`1. AI 작성·보안 진단`, `2. 판례·법령·주요참고문헌 인용 오류·미확인`, `3. 법률적으로 무리한 주장`)로 구조화 | `test_report_generation.py`, `test_report_workbench.py` 등 기존 보고서 HTML 렌더링 시험 불변 통과 |
| **DOCX** | '확인할 항목' 표 섹션 내에 3단 소제목 스타일 적용 | 기존 DOCX 생성 모듈(`report_generator.py`)의 표 렌더링 로직 및 필드 불변 유지 |
| **PDF** | HTML 렌더링 엔진(Playwright PDF)을 통해 화면과 동일하게 3단 섹션으로 출력 | 기존 PDF preflight 및 크기/페이지 수 기준선 유지 |
