## 원문 1 — 본 지시서

# ACAS AegisLAW v0.20.0 — 템플릿 A 기반 전체 UI/UX 리디자인 및 프론트엔드 구현 지시서

## 0. 역할과 최종 목표

당신은 15년 이상의 경력을 가진 시니어 프론트엔드 아키텍트, 엔터프라이즈 SaaS UI/UX 디자이너, 디자인 시스템 엔지니어입니다.

현재 작업 중인 ACAS AegisLAW 법률문서 검증시스템의 실제 소스코드를 분석하고, 첨부한 **템플릿 A 이미지를 기준으로 전체 프론트엔드를 리디자인하고 실제 구현**하십시오.

본 작업은 새로운 프로그램 개발이 아니라 기존 프로그램의 UI/UX 개선 프로젝트입니다.

**가장 중요한 목표는 다음 세 가지입니다.**

1. 템플릿 A의 디자인 완성도와 시각적 특징을 실제 프로그램에 최대한 충실하게 적용한다.
2. 기존 프로그램의 모든 메뉴, 페이지, 탭, 팝업, 분석 결과 및 관리 기능을 유지하면서 사용성을 개선한다.
3. 기존 API, 분석 엔진, 법률검증 로직, 데이터 모델과 검증 결과의 의미를 변경하지 않는다.

단순한 제안서나 목업으로 끝내지 말고, 실제 저장소의 프론트엔드 코드를 수정해 실행 가능한 상태까지 구현하십시오.

## 1. 첨부자료와 우선순위

### 1.1 디자인 원본

**[첨부 1] 템플릿 A 이미지**

이 이미지는 본 프로젝트의 최우선 시각적 기준(Visual Source of Truth)입니다.

다음 요소들을 충실하게 구현하십시오.

- 진한 네이비색 좌측 사이드바
- 흰색 배경의 상단 헤더
- 프로젝트 제목과 상태 표시 및 주요 작업 버튼
- 파스텔 톤의 4열 KPI 카드
- 부드러운 그림자, 둥근 모서리, 명확한 카드 간격
- 검증 경고와 사람 검토 사유를 강조한 패널
- 최근 작업 활동 타임라인
- 아이콘과 색상으로 구분한 핵심 기능 바로가기 카드
- 전체적으로 여유 있고 정돈된 기업용 대시보드 디자인
- Pretendard 기반의 현대적인 한글 타이포그래피

이미지 우측의 '템플릿 A' 설명 패널은 디자인 제안용 주석이므로 실제 프로그램에는 포함하지 마십시오.

템플릿 A의 낡은 브랜드 로고, 가상의 결과 수치, 예시 날짜와 버전 정보도 그대로 복제하지 마십시오.

### 1.2 실제 기능 자료

**[첨부 2~8] 최신 프로그램 화면 7개**

자료 탭, AI 작성·보안 진단 탭, 출처가 확인되지 않는 항목 탭, 법률적으로 무리한 주장 탭, 보고서 탭 및 검증 진행 중인 화면을 포함합니다.

이 자료는 기존 기능과 데이터 표시 요구사항을 이해하기 위한 기준입니다.

화면 일부만 캡처되었으므로 실제 저장소의 전체 라우트, 컴포넌트 및 상태를 조사하여 누락된 페이지를 발견하십시오.

### 1.3 우선순위 원칙

- **시각 디자인:** 첨부 1 템플릿 A 우선
- **브랜드·기능:** 현재 저장소의 최신 구현 우선
- **검증 결과와 법률적 의미:** 현재 백엔드 및 데이터 계약 우선
- **화면 구성:** 템플릿 A의 디자인 언어를 유지하면서 각 기능에 가장 적합한 형태로 재배치

디자인 이미지의 예시 내용보다 실제 시스템 데이터와 비즈니스 규칙이 우선합니다.

## 3. 전체 디자인 시스템

### 3.1 기본 디자인 방향

키워드:

**Modern LegalTech / Premium SaaS / Professional / Trustworthy / Readable / Accessible**

디자인은 템플릿 A와 최대한 유사하게 구현하되, 법률전문가가 장시간 사용하는 업무용 시스템이라는 점을 고려하십시오.

과도한 애니메이션, 강한 그림자, 불필요한 장식, 지나친 그라데이션, 의미 없는 대형 일러스트는 피하십시오.

### 3.2 폰트

기본 폰트: **Pretendard**

공식 배포처:
https://github.com/orioncactus/pretendard

가능하면 Variable Font와 WOFF2를 활용하고, 기존 프로젝트의 빌드 방식에 맞게 자체 호스팅하십시오.

라이선스 조건과 고지 파일을 보존하십시오.

권장 타이포그래피:

| 용도 | 크기 | 굵기 |
|---|---|---|
| 페이지 제목 | 28px | 700 |
| 섹션 제목 | 20px | 700 |
| 카드 제목 | 16px | 600 |
| 기본 본문 | 15~16px | 400 |
| 데이터 표 | 14px | 400~500 |
| 보조 설명 | 13px | 400 |
| KPI 수치 | 28~32px | 700 |
| 버튼 | 14~15px | 500~600 |

본문 줄간격은 1.5~1.65를 기본으로 사용하십시오.

긴 법률문장과 판례 인용문은 가독성을 우선하고, 지나치게 작은 폰트로 축소하지 마십시오.

## 5. 페이지별 상세 구현 요구사항

### 5.1 프로젝트 개요 — 템플릿 A 직접 적용

이 페이지는 템플릿 A의 구성과 가장 높은 시각적 유사도를 확보해야 합니다.

**상단 KPI 카드 영역**

실제 데이터와 상태에 따라 다음 정보를 구성하십시오.

1. 검토 자료 포함 현황
2. 배포 가능 여부 또는 사람 검토 필요 상태
3. 검증위험 지수와 확인 전 항목
4. AI 작성 진단 및 진행 상태

정보가 늘어난 경우 카드 안에 과도한 내용을 넣지 말고, 보조 지표나 상세 패널을 활용하십시오.

**중앙 주요 검토 영역**

좌측:

- 사람 검토 필요 여부
- 검토 필요 건수
- 주요 사유
- 중요도
- 개별 검토 항목으로 이동하는 기능

우측:

- 최근 작업 활동
- 자료 업로드
- 자동 검증 시작 및 완료
- 분석 진행 및 실패
- 사람 검토
- 보고서 생성·확정

**하단 기능 바로가기**

템플릿 A와 같은 대형 아이콘 카드를 사용하십시오.

- 자료 관리
- AI 작성·보안 진단
- 출처 검증
- 법률주장 검토
- 보고서

실제 제공되는 기능에 따라 카드의 수와 배치를 조정하십시오.

### 5.2 자료 관리 페이지

기존 기능:

- 파일 업로드
- 검토 포함·제외
- 파일명·파일 형식·용량
- 증거번호·제출자
- 자료 편집·제거
- 개인정보 안내
- 파일 관리 상태

개선 방향:

- 상단에 자료 현황 요약
- 우측 상단에 파일 추가 버튼
- 정렬과 검색이 가능한 자료 목록
- 포함·제외 상태를 표시하는 Badge
- 주요 파일 정보와 보조 정보를 시각적으로 분리
- 행별 작업 메뉴
- 긴 파일명의 말줄임 및 전체보기
- 업로드 진행률과 오류 표시

기존 파일의 포함 여부와 메타데이터는 정확하게 유지하십시오.

### 5.3 AI 작성·보안 진단 페이지

기존 기능:

- 문서별 AI 작성 가능성 진단
- 종합 진단 결과
- 복수 AI 모델 평가
- 모델별 점수와 판정
- 모델별 판단 근거
- 분석 범위와 제외 영역
- 보안 관련 진단

개선 방향:

상단:

- AI 작성 가능성 종합 진단 카드
- 분석 상태
- 분석 대상 문서
- 판단의 한계 안내

중앙:

- 모델별 평가 카드를 동일한 디자인으로 가로 배치
- 각 모델의 점수·판정·상태를 분리해 표시
- 모델별 상세 근거는 펼침 패널로 제공

하단:

- 종합 판단의 근거
- 분석 범위
- 보안 진단
- 추가 확인 사항

**매우 중요한 제약**

AI 작성 가능성 추정치는 작성 주체에 대한 확정적 증거가 아닙니다.

서로 다른 모델의 점수를 단순 합산하거나 법률 검증위험 지수와 혼동하지 마십시오.

모델 이름과 점수는 실제 응답 데이터에 따라 표시하십시오.

### 5.4 출처가 확인되지 않는 항목

기존 화면은 긴 표 형태이며 다수의 검증 항목과 설명을 포함합니다.

핵심 정보:

- 원본 문서 위치
- 인용 문장
- 판례·법령 인용
- 공식 DB 확인 결과
- 중요도
- 검증 근거
- 확인 필요사항
- 상세 법리 의견
- 검토 결정
- 외부 AI를 활용한 보조 검증

개선 레이아웃:

**상단 — 출처 검증 현황**

- 전체 항목 수
- 공식 DB 미확인 건수
- 검토 결정 대기 건수
- 중요도별 필터
- 검색 및 정렬

**중앙 좌측 — 검증 항목 목록**

각 항목에 다음을 표시하십시오.

- 인용 대상
- 문서 위치
- 중요도
- 현재 검증 상태
- 사람 검토 상태

**중앙 우측 — 선택 항목 상세**

- 원문 인용
- 공식 출처 확인 결과
- 검증 근거
- 확인 필요사항
- 상세 법리 의견
- 관련 출처
- 검토 결정과 이력

기존의 '엘박스/AI 검증 프롬프트 만들기' 및 '외부 AI 답변 붙여넣기' 기능은 별도의 보조 작업 영역으로 유지하십시오.

외부 AI 응답은 공식 법령·판례 원문 확인과 동일하게 취급해서는 안 됩니다.

공식 DB 미확인은 해당 법령·판례가 존재하지 않는다는 의미가 아니므로 상태 명칭과 안내문을 정확히 구분하십시오.

### 5.5 법률적으로 무리한 주장

이 화면은 법률전문가가 실제로 판단하고 검토 결정을 수행하는 핵심 영역입니다.

기존 데이터:

- 문서의 주장 및 인용 내용
- 문서 위치
- 법률적 문제 유형
- 법리 검토 결과
- 법령 적용 시점
- 확인 필요사항
- 검토 결정 대기 상태
- 상세 검토 의견
- 외부 AI 보조 검증

개선 레이아웃:

상단:

- 전체 검토 대상
- 중요도별 건수
- 검토 결정 대기
- 필터와 검색

중앙:

- 좌측: 법률주장 목록
- 우측: 선택된 주장의 검토 상세

우측 상세 패널에는 다음 순서를 적용하십시오.

1. 원문 주장
2. 검토 결과 요약
3. 법적 쟁점
4. 적용 법령·판례 및 근거
5. 추가 확인 필요사항
6. 상세 법리 의견
7. 담당자 검토 결정
8. 결정 이력

법률적으로 무리한 주장이라는 분석 결과를 곧바로 확정된 위법 판단으로 표시하지 마십시오.

법령의 시행 시점 및 사건 발생 시점과 관련된 문제를 사용자가 명확히 구분할 수 있어야 합니다.

### 5.6 보고서 페이지

기존 기능:

- 검토 보고서
- 실행 ID
- 생성 시각
- 초안 상태
- JSON
- 점검 후 확정
- 고정부 무결성
- 보고서 생성·다운로드

개선 방향:

- 보고서 목록을 카드 또는 정돈된 표 형태로 구성
- DRAFT / 내부 검토용 / 확정 등 상태 명확히 구분
- 보고서 생성 시점과 관련 검증 실행 ID 표시
- 선택한 보고서의 미리보기 제공
- JSON 및 기존 내보내기 기능 유지
- 점검 후 확정 작업을 별도 강조
- 무결성 관련 정보는 상세 패널 제공

보고서 초안은 확정 보고서와 혼동되지 않도록 표시하십시오.

검증이 진행 중이거나 결과가 일부 미확인 상태인 경우 해당 사실을 보고서에 정확히 반영하십시오.

### 5.7 검증 진행 화면

검증이 진행되는 동안 표시되는 화면도 템플릿 A의 디자인 시스템을 적용하십시오.

주요 요소:

- 현재 진행 단계
- 진행률
- 단계별 처리 상태
- 최근 처리 정보
- 장시간 응답이 없는 경우의 안내
- 검증 취소
- 검증 이력·작업 기록
- 완료 후 결과 갱신

진행률이 실제 처리 완료율이 아닌 경우 의미를 정확히 표시하십시오.

진행 중인 검증의 결과를 0건이나 정상으로 확정하여 표시하지 마십시오.

검증 버튼의 중복 실행 방지 및 기존 비동기 작업 동작을 유지하십시오.

## 원문 2 — 제8장 대체

# 제8장 대체 — 모바일·태블릿 반응형 UI/UX 필수 구현 요구사항

## 8.1 모바일 지원 기본 원칙

본 프로젝트는 데스크톱뿐 아니라 **스마트폰과 태블릿에서도 주요 기능을 정상 사용할 수 있어야 하는 반응형 웹 애플리케이션**입니다.

모바일 지원은 선택사항이 아니라 필수 구현 범위입니다.

모든 화면에 템플릿 A의 디자인 언어를 일관되게 적용하되, 데스크톱 화면을 단순 축소하는 방식은 허용하지 않습니다.

화면 크기와 입력 방식에 따라 정보 배치, 탐색 구조, 사용자 작업 흐름을 최적화하십시오.

모바일에서도 기존의 법률문서 검증 및 관리 기능이 동등하게 제공되어야 합니다.

## 8.2 화면별 반응형 기준

최소한 다음 해상도를 대상으로 구현하고 검증하십시오.

| 환경 | 기준 |
|---|---|
| 소형 모바일 | 320~374px |
| 일반 모바일 | 375~430px |
| 대형 모바일·폴더블 | 431~767px |
| 태블릿 | 768~1023px |
| 소형 데스크톱 | 1024~1279px |
| 데스크톱 | 1280px 이상 |

위 범위는 초기 설계 기준이며, 실제 컴포넌트가 깨지는 지점에서 콘텐츠 기반 브레이크포인트를 추가할 수 있습니다.

폴더블 기기의 화면 접힘 및 펼침, 화면 회전, 브라우저 확대·축소에도 레이아웃이 정상 동작해야 합니다.

## 8.3 모바일 공통 레이아웃

### 상단 헤더

모바일에서는 다음과 같이 구성하십시오.

- 좌측 햄버거 메뉴
- 축약된 ACAS AegisLAW 브랜드
- 현재 화면 제목 또는 프로젝트명
- 필요한 알림 및 사용자 메뉴

기존 데스크톱용 전체 헤더 항목을 모바일 상단에 모두 나열하지 마십시오.

### 프로젝트 사이드바

데스크톱의 네이비 사이드바는 모바일에서 슬라이드형 Drawer로 전환하십시오.

- 햄버거 버튼으로 열기·닫기
- 화면 바깥 영역 터치로 닫기
- 프로젝트 검색
- 프로젝트 선택
- 새 프로젝트 생성
- 주요 관리 기능
- 현재 프로젝트 강조 표시

Drawer는 키보드와 터치로 모두 사용할 수 있어야 합니다.

### 하단 내비게이션

모바일에서 자주 사용하는 주요 작업은 3~5개의 하단 내비게이션 항목으로 제공하는 방안을 적용하십시오.

권장 항목:

- 홈
- 자료
- 검증
- 보고서

그 외 기능은 사이드바 또는 프로젝트 내부 탭에서 접근할 수 있도록 하십시오.

고정 하단 내비게이션과 검토 결정 버튼이 서로 겹치지 않아야 합니다.

### KPI 카드

데스크톱의 4열 KPI 카드를 모바일에서는 기본적으로 2열로 배치하십시오.

너비가 부족하거나 내용이 긴 경우 1열로 전환하십시오.

중요 상태는 접힌 영역에 숨기지 마십시오.

## 8.4 모바일 기능별 화면 구성

### A. 자료 관리

- 파일 목록을 모바일 카드형으로 전환
- 파일명, 크기, 자료 상태 표시
- 파일 추가 버튼 명확히 배치
- 증거번호 및 제출자 정보 확인
- 편집·제외 작업을 터치 메뉴로 제공
- 파일 업로드 진행률 표시
- 모바일 파일 선택기 지원
- 업로드 실패 및 재시도 처리

### B. AI 작성·보안 진단

- 종합 진단 결과를 상단 카드로 표시
- 모델별 평가 카드를 세로로 배치
- 각 모델의 점수와 판정을 명확하게 구분
- 상세 근거는 펼침 패널로 제공
- 긴 분석 결과는 자연스러운 세로 스크롤 지원
- AI 추정치의 해석상 한계 안내 유지

### C. 출처 미확인 항목

기존 4열 표를 모바일에서 그대로 표시하지 마십시오.

- 검증 항목을 카드형 목록으로 제공
- 중요도 및 상태 필터 지원
- 항목 선택 시 상세 화면 또는 전체 높이 Drawer 열기
- 원문 인용 및 법령·판례 정보 표시
- 검증 근거와 추가 확인사항 제공
- 외부 AI 보조 검증 기능 유지
- 사람 검토 결정을 터치 방식으로 수행

목록과 상세 화면 사이를 이동하더라도 선택 항목, 필터, 스크롤 위치가 가능한 범위에서 유지되어야 합니다.

### D. 법률적으로 무리한 주장

- 법률주장별 카드형 목록
- 검토 중요도와 결정 상태 표시
- 주장을 선택하면 상세 법리 분석 화면 제공
- 원문, 법적 쟁점, 검증 근거, 확인 필요사항을 명확하게 구분
- 긴 법률문장과 판례 인용문을 읽기 쉬운 폭으로 배치
- 기존 검토 결정 기능 유지
- 검토 결과 저장 후 현재 목록의 상태 갱신

검토 결정을 위해 불필요한 가로 스크롤이나 정밀한 터치가 요구되어서는 안 됩니다.

### E. 보고서

- 보고서 실행 목록을 모바일 카드형으로 제공
- DRAFT 및 확정 상태 명확히 표시
- 보고서 미리보기 지원
- PDF 등 현재 지원하는 보고서 형식의 다운로드 유지
- JSON 확인 및 내보내기 기능 유지
- 점검 후 확정 기능 유지
- 고정부 무결성 정보를 상세보기로 제공

문서 미리보기는 모바일에서도 텍스트를 읽을 수 있도록 확대·축소 기능을 지원하거나 적절한 대체 보기 방식을 제공하십시오.

### F. 검증 진행 화면

- 검증 진행률을 모바일 상단에 표시
- 현재 처리 단계와 상태 메시지 제공
- 검증 진행 중 다른 화면으로 이동해도 실제 작업이 유지되는 기존 구조 보존
- 검증 취소 기능 유지
- 검증 완료 및 실패 안내
- 진행률과 결과 수치의 의미를 정확하게 표시

## 8.5 터치·키보드·접근성

다음 기준을 적용하십시오.

1. 주요 터치 대상은 원칙적으로 최소 44×44 CSS px 크기의 충분한 터치 영역 확보
2. Hover에만 의존하는 기능 금지
3. 모바일 가상 키보드가 입력 영역과 저장 버튼을 가리지 않도록 처리
4. 모달·Drawer의 포커스 및 스크롤 관리
5. 터치와 키보드 양쪽에서 주요 작업 수행 가능
6. 텍스트 확대 시 콘텐츠 잘림 방지
7. 상태는 색상과 문구를 함께 표시
8. 긴 파일명과 법률문장의 줄바꿈 정상 처리
9. 스크롤 위치 및 선택 상태 보존
10. iOS Safe Area와 하단 고정 버튼의 충돌 방지

## 8.6 모바일 성능

- 불필요한 이미지와 아이콘 리소스 최소화
- Pretendard 폰트 파일 최적화
- 대량 검증 항목 렌더링 최적화
- 모바일에서 긴 목록의 스크롤 성능 확보
- 장시간 검증 작업에서 불필요한 전체 화면 재렌더링 방지

- 모바일 네트워크에서도 주요 페이지가 안정적으로 동작하도록 최적화

성능 최적화를 위해 중요한 검증 근거와 법률적 설명을 누락하거나 임의로 축약하지 마십시오.

- 스마트폰 가로 모드

## 8.8 모바일 작업 완료 기준

다음 조건을 모두 충족해야 모바일 UI 구현이 완료된 것으로 판단합니다.

- 모든 주요 기능에 모바일 진입 경로가 존재한다.
- 핵심 법률검증 정보가 화면 크기로 인해 누락되지 않는다.
- 사용자가 검증 결과를 읽고 검토 결정을 저장할 수 있다.
- 모바일 파일 업로드 및 보고서 다운로드가 정상 작동한다.
- 주요 버튼과 메뉴를 터치로 사용할 수 있다.
- 화면 전체의 불필요한 가로 스크롤이 발생하지 않는다.
- 템플릿 A의 브랜드·색상·폰트·디자인 일관성이 유지된다.
- 모바일과 데스크톱에서 동일한 검증 실행 상태 및 데이터를 확인할 수 있다.
- 기존 프로그램의 기능과 API 동작에 회귀 오류가 없다.

**모바일을 단순히 반응형으로 표시하는 것만으로 구현 완료를 선언하지 마십시오. 모든 주요 법률검증 업무를 스마트폰에서 실제 수행할 수 있어야 합니다.**
