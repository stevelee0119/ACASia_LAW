# 설계 메모: TK-94 출처 미확인 판례·법령 외부 법률 AI/엘박스 검증 프롬프트 생성 기능

- **문서 번호:** `requests/96_tk94_unverified_authority_external_ai_prompt_design.md`
- **작성일:** 2026-10-20
- **작성자:** Antigravity (구현 에이전트)
- **대상 티켓:** TK-94 (출처 미확인 판례·법령 외부 법률 AI/엘박스 검증 프롬프트 제공)
- **수용 기준:** 순수 프론트엔드 기능, 탐지 diff 0, 채점기 불변, 고정·은퇴 세트 점수 불변

---

## 1. 개요 및 설계 의도

- **배경:**
  - 공식 DB에서 `OFFICIAL_NOT_FOUND` 등으로 확인되지 않는 판례·법령은 하급심(고법/지법) 판결이거나, 사건번호 오기, 또는 생성형 AI가 만든 가짜 판례일 수 있습니다.
  - 사용자가 이를 엘박스(L-Box) 등 법률 특화 검색/AI 도구에서 검증하고자 할 때, 최적의 질의 구조를 갖춘 프롬프트를 자동 생성하여 업무 생산성을 극대화합니다.
- **설계 원칙:**
  1. **Zero Backend Impact:** 백엔드 API 스키마나 탐지 파이프라인의 변경 없이, 기존 Finding 및 Row 항목의 메타데이터를 프론트엔드(`app.js`)에서 순수 조합하여 클립보드에 복사.
  2. **Security & Privacy First:** 프롬프트 생성 시 시스템 내부의 비실명화/마스킹 텍스트를 사용하고, 주의 문구를 반드시 포함.
  3. **High Usability:** 개별 행 단위 단건 복사와 전체 미확인 항목 일괄 복사 지원.

---

## 2. 프롬프트 템플릿 설계

### (1) 단건 검증 프롬프트 구조
```markdown
[역할]
당신은 대한민국 법률 및 판례 검증 전문 법률 비서 AI입니다.
아래 소송 서면에서 인용된 [판례/법령]의 실재 여부와 주장의 타당성을 정밀 검증해 주세요.

[검증 대상 정보]
- 인용 표기: {cited_authority}
- 서면 내 주장 요지: "{claim_text}"
- 1차 검증 시스템 진단: {system_verdict} (공식 DB 미확인/불일치)
- 적용/기준 시점: {incident_date 또는 "미지정"}

[검증 요청 사항]
1. 판례/법령 실재 여부:
   - 해당 사건번호/법령 조항이 실제로 존재하는가? (대법원 또는 하급심 판결 여부, 사건명, 실제 선고일자)
   - 만약 존재하지 않는다면, 유사한 사건번호나 당사자 주장을 다룬 유사 대법원 판례가 있는가?
2. 판시사항 부합 여부:
   - 해당 판결이 실재한다면, 서면의 주장 내용과 실제 판시사항/판결요지가 일치하는가? 아니면 판례 취지를 왜곡·과장한 것인가?
3. 대체/반박 리딩 판례:
   - 위 쟁점에 대해 확립된 대법원 리딩 판례(정확한 사건번호 및 판결요지)를 제시해 주세요.

[답변 형식]
- 1) 검증 결과 요약 (실재 여부 / 왜곡 여부 / 신뢰도 등급)
- 2) 실제 판결 정보 및 핵심 판결요지
- 3) 서면 주장과의 비교 분석
- 4) 권장 대응 방안 및 대체 판례

※ 주의: 외부 AI 도구 입력 전 당사자 개인정보(실명, 고유식별정보 등)가 포함되어 있는지 다시 한번 확인하시기 바랍니다.
```

### (2) 다건 일괄 검증 프롬프트 구조
- 복수의 미확인 판례/법령을 목록 번호로 열거하고, 엘박스에 일괄 표 형태로 검증 결과를 반환받도록 요청하는 구조.

## 3. UI/UX 구현 명세

1. **단건 복사 버튼 (`app.js`):**
   - 4열 통합 검토 표의 각 행(`item`) 중 `item.cited_authority`가 존재하고 출처 미확인 또는 인용 오류가 있는 행의 2열(`tdClaim`) 또는 3열(`tdBasis`)에 `[📋 엘박스 검증 프롬프트]` 버튼 배치.
   - 클릭 시 `copyPromptToClipboard(promptText)` 실행 후 토스트 메시지 출력.
2. **다건 일괄 복사 버튼:**
   - `unverifiedScopeContainer` (미확인 범위 구역) 또는 판례 오류 검토 구역 상단에 `[📋 미확인 판례 전체 검증 프롬프트 복사]` 버튼 배치.
3. **스타일 (`styles.css`):**
   - 기존의 컴팩트한 `link-button small` 또는 `action-button` 디자인을 계승하여 시각적 간결함 유지.

## 4. 검증 및 영향도

- **영향 범위:** `apps/web/static/app.js`, `apps/web/static/styles.css` 국소 추가.
- **백엔드/탐지 영향:** 0 (점수 하락 게이트, 은퇴 세트, acceptance 테스트 diff 0).
- **테스트 계획:** 프롬프트 생성 유틸리티 함수 및 복사 버튼 렌더링 검증 단위 테스트 작성.
