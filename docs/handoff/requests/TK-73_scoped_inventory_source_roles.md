# TK-73 independently scoped inventory roles (design precheck)

The source-prefix revision changed no comparison offset in the reported aggregate and did not meet the mandatory criterion. Keep `30a2029` unchanged. Ordinary balanced title wrappers provide no independent semantic presentation role, so do not strip them. Public code instead shows a separate source-role limitation: inventory recognition accepts a fixed set of headings and its flag persists beyond later peer sections. Adding a header spelling alone would therefore still treat later narrative rows as inventory rows. This proposal changes the approach to document source/context roles, not title-string equivalence.

Build a comparison-only scoped role index from the original reading paragraphs. A candidate inventory heading must have an observed structural enumerator plus a nonempty heading ending in the generic inventory noun `목록`; no case-specific heading phrase or category stem list. Require independent inventory evidence immediately after it: at least two leading-reference entries with an observed colon directly after each reference, either in a multi-item paragraph or consecutive item paragraphs. A heading word alone, one isolated reference, or ordinary reference/title/narrative colons are insufficient. Require a subsequent independently observed peer/ancestor numbered heading to close the inventory before assigning its role. Recognize enumerator families and their conventional hierarchy; child headings do not certify a peer close. Missing/ambiguous boundaries remain under the old comparison. All evidence comes from actual reading/source spans; synthesized joins do not prove punctuation or heading markers. Preserve original `name`, `date`, `author`, `purpose`, `in_section`, reference spans and source projections; Keep the role/proof map local to the numbering call, keyed by existing row/paragraph provenance; do not add or alter original row/source fields. A closed inventory starts at its heading and ends before the first later heading in the same enumerator family, or a conventional ancestor family. The following sibling region is narrative context until its next ancestor boundary; independently proved later inventory scopes override that role. Require actual source-covered markers/colons, not a normalized or synthetic joining character.

Use existing TK-64 inventory-versus-body numbering semantics for these independently proved regions: inventory rows remain the authoritative duplicate-number population for keys they contain; later narrative references for those keys are mentions rather than another inventory definition. The original recognized-list route remains untouched: existing sticky `in_section` and original section-key filtering execute as before. New roles apply only to previously unrecognized, independently scoped regions, and exclude narrative mentions only for exact party/number/branch keys represented in the proved inventory. Body rows with another branch/party remain eligible. Do not change global gap/list-missing population or reinterpret all UNKNOWN rows as narrative. This requires evaluator precheck because its context policy supersedes title-only corroboration for a proved inventory, as existing TK-64 already does. It is not a universal suppression of duplicate findings: different complete titles assigned within the inventory still yield A; body rows for unlisted keys still participate; with no proved inventory, genuine same-number/different-title body rows retain A. Neither title-prefix similarity nor a pair of weak captions proves the region. Other mismatch, numbering-gap, amount/date checks and the all-date/protection scanner remain unchanged.

Before product, actual generated TXT/PDF controls use three independently created generic heading/enumerator families, multiple entries including base/branch keys and a peer explanatory section. Keep genuine duplicated inventory definitions, body duplicates without inventory, title colon/comma/quote/date content, fake heading without entry evidence, one entry, missing peer close, child heading and unrelated-party/branch keys as opposite controls. Retain the existing 652 tests and original expectations, original row/source historical equality, forward bounded scanning and the 0.1-second comparison budget. No table ownership changes, protected edits, new rule IDs or private raw input access. Public tests establish only this source-role cause; mandatory AFP0 and exact-SHA CI remain independent evaluator gates.
