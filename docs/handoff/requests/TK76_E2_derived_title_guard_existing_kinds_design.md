# TK-76 E 후속 설계 메모: 파생 문서명 가드를 기존 서증 종류 판별에도 적용

- 작성일: 2026-11-18
- 작성: 구현 에이전트(Claude Code)
- 기준: Steve `8b760d2`(PR #330 병합 뒤)
- 근거: 2026-11-18 사용자 지시 "4번 구현"(제가 #330 보완 때 보고한 기존 동작 결함).
  분류상 **기존 탐지 동작을 바꾸는 변경**이므로 사용자 결정을 받고 착수했다.

## 1. 결함과 재현 (기준 `8b760d2`)

PR #330에서 새로 만든 `EVIDENCE_ORIGINAL` 경로에는 파생 문서명 가드
(`_DERIVED_DOC_NAME_RE`, 표제 줄 전체·분류 전)를 넣었다. 그러나 **기존 두 종류 판별에는 가드가 없다.**
표제 정규식의 뒤 낱말 제한은 구분자 뒤·공백 접미만 막고 **괄호·대괄호 안은 통과**시킨다.

| 표제 | 현재 분류 | 소송서면과 같은 본문 → 경고 |
|---|---|---|
| `사실경위서(사본)` | FACT_CONFIRMATION | 1건 |
| `사실경위서[송부]` | FACT_CONFIRMATION | 1건 |
| `사실경위서(제출)` | FACT_CONFIRMATION | 1건 |
| `사고경위서(접수)` | FACT_CONFIRMATION | 1건 |
| `경위서(발급)` | FACT_CONFIRMATION | 1건 |
| `증거설명서(사본)`·`증거설명서[송부]` | EVIDENCE_EXPLANATION | (owner 쪽이라 경고 주체가 된다) |

이미 막히는 축: `사실경위서 - 사본`(구분자), `사본사실경위서`(붙여쓴 수식어 — 기존 정규식이 공백을 요구),
`사실경위서 사본`(공백 접미).

사본·송부 표지가 붙은 문서는 **그 문서 자체가 아니라 송부·접수 과정의 파생 문서**다. 원본 서증으로 보고
통복제를 판정하면 근거가 약하고, 반대로 owner(증거설명서) 쪽에서는 파생 문서가 경고의 주체가 된다.

## 2. 변경 설계

`_document_title_kind`에서 표제 줄마다 `_DERIVED_DOC_NAME_RE`를 한 번 평가하고, 파생 낱말이 있으면
**서증 종류 세 분기**(증거설명서·사실경위서·서술형 원본 서증)를 건너뛴다. 가드는 이미 #330에서
`EVIDENCE_ORIGINAL`에 쓰던 것과 **같은 정규식**이다.

바꾸지 않는 것:
- **소송서면(`PLEADING`) 판별은 그대로 둔다.** `소장(사본)`도 내용은 그 소송서면이므로 owner 자격을 유지한다.
  파생 가드를 여기까지 넓히면 owner가 사라져 기존 탐지가 줄어든다. 이번 범위 밖이다.
- 진술서(`STATEMENT`, 1순위 `_statement_start`) 경로도 건드리지 않는다(Steve 원본과 100% 동일 유지 대상).
- 문장 유사도 기준, 서증 정식 원용 표기 제외, 민사소송규칙 제106조 예외, 등급·문구.

## 3. 범위에 대한 보고

사용자 지시는 **사실경위서 경로**였다. 구현 중 `증거설명서` 경로에도 같은 괄호·대괄호 구멍이 있음을
확인해 같은 가드로 함께 고쳤다(2026-11-09 사용자 지시 '식별된 추가 문제는 TK 안에서 해결').
증거설명서는 owner 쪽이라 성격이 다르므로, 분리를 원하면 이 분기만 되돌릴 수 있게 한 줄로 두었다.

## 4. 수용 기준과 측정

- 파생 표제가 분류·실제 `cross_document_copies` 두 축에서 모두 배제될 것(사실경위서 5종·증거설명서 2종).
- 정상 양성 유지: `사실경위서`·`사 실 경 위 서`·`사고경위서`·`사건경위서`·`경위서`·`사실경위서(원본)`,
  `증거설명서`·`증 거 설 명 서`, 그리고 #330의 서술형 원본 서증 양성.
- **기존 탐지 동작을 바꾸는 변경이므로 고정 dev·holdout과 은퇴 5세트를 반드시 다시 잰다.**
  점수가 바뀌면 숫자와 방향(오탐 제거인지 득점 상실인지)을 그대로 보고하고 평가 측 판정에 맡긴다.
- 은퇴·봉인 세트 내용은 열람하지 않는다. 집계 비교만 쓴다.
