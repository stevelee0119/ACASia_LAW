# Post-0.13 CI TK-43 시간 진단 계획

평가 세션 · 시작 f64edbe · PR #99. 제품/원본 시험/기준선 변경 0.

CI 38245722221의 SQLite가 같은 원본 시간 시험에서 두 번 실패했다: 최초 0.625568초, 실패 job 1회 재실행 0.748032초, 기존 상한 0.1초. 각 실행 9731 통과·1 실패, PostgreSQL·Docker·점수 게이트 성공이다. 원래 실패를 보존하며 환경 문제로 면제하지 않는다. 운영/검증 후보/기록 HEAD의 해당 detector와 원본 시험 blob은 같다.

단독 원본 시험은 운영 0.003376초·후보 0.003441초에 통과했다. 로컬 선행 시험 진단에서도 대상 시간 시험은 통과했고 call 범위 0.003281초·generation0 GC만 관측했다. 같은 실행은 이 제한된 로컬 파일시스템의 mount 판별 시험에서 실패했으며 CI 통과를 대신하지 않는다. 로컬 진단 1·2회는 브라우저 통신 권한 누락으로 중단, 권한을 맞춘 실행만 위 수치의 근거다. 원인 미확정이다.

세 번째 단순 재실행 대신 공개 관찰 플러그인만 CI에 추가한다. 원래 test frame의 원래 perf_counter builtin c_return/c_call 경계를 관찰하고 GC callback 시작/끝·세대·수집 수 및 thread CPU를 기록한다. 원래 clock/입력/출력/assert/GC 설정/시험 순서/0.1초 상한을 바꾸지 않는다. observer 자체의 작은 부하와 GC 시점 교란 가능성을 명시한다. 양 DB job 모두 같은 방식, 실패 종료·필수 check·로그를 유지한다. 봉인 재실행/유료 호출은 없다.

원인이 입증되기 전 시험 분리는 적용하지 않는다. 추후 분리한다면 정확 node 하나만 별도 새 프로세스에서 원본 그대로 1회 실행하고 원래 수집 집합 N-1+1, 동일 DB/worker 환경·conftest/options, 실패 OR/pipefail·로그를 검증한다. 판정 기준·node 집합 보존과 실행 맥락 변경을 구분한다. 독립 감사의 원인/실제 diff 검토 및 새 HEAD 필수 CI 성공 후에만 릴리스한다.
