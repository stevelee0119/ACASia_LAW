# TK73 dated complete-record / source-EOF review amendment

Design review only. Product, existing finding status/grade, original111/936 expectations and original scoring remain unchanged. The proposed pending tier is not equal-title certification or original AFP0. This amendment requires independent review and later user criteria approval.

**Complete-record binding.** A native item occurrence can be mapped losslessly even when its complete payload differs from the parser's canonical name. Verify its exact reference/key and original lexical owners, then reproduce the existing parser derivation: the first DATE_RE occurrence partitions the complete payload into the original name prefix, exact parsed-date substring and author/purpose suffix. Check every original field against that derivation; retain the entire payload, all date occurrences, delimiters and qualifications in the receipt. Every date occurrence must have native contiguous ownership, so application whitespace cannot create date syntax for certification. No prefix becomes an authenticated formal title, and the matched date is not certified as a creation date. Missing, reordered or ambiguous owners, protected/uncertain text, unsupported item prefixes or any failed original-field binding remain UNKNOWN/legacy A.

**Date and duplication uncertainty are distinct.** If an already-existing duplicate otherwise satisfies the bounded pending review contract, a date need not forbid explaining uncertainty about payload roles. Every original date finding stays A with its original text/status. Global comparisons use the complete original records, never names with dates removed: two complete alternatives in either role, qualifications, uncertainty or independently declared TITLE differences veto pending. Native whole-date TITLE conflicts stay A. A genuine untyped dated mixed-format title may still become pending; record that confirmation loss explicitly. A legacy name-only parser miss caused solely by title-internal date differences remains a miss, not a pending success.

**EOF is source extent, not an inferred semantic close.** Inventory entry/peer-close proof remains mandatory. For an outside section with no following heading, an optional pending-only boundary is the independently accounted end of the actual decoded source: all original lexical occurrences appear exactly once in order in reading, every occurrence has the right original owner, the final occurrence is reached, and no unaccounted native text or unsupported content source exists. TXT uses decoded file character offsets; bounded DOCX uses actual body run occurrences and rejects unsupported text-bearing structures/header sources; PDF uses decoded page-character occurrences. Application joins cannot certify native grammar. This proves the available source ended, not that author intent or a formal title ended. Partial-page, omitted/reordered/unowned text, unsupported source and quote uncertainty keep legacy A. No original inventory/narrative interval is expanded or key exempted.

Programmatic full-record/EOF/parent/global checks and manual semantic role assumptions are separate. Pending may use a physically exhausted, source-complete outside context only after the user approves this changed review contract. Independently declared TITLE fields, all-origin competing records, dates/protected literals, original calendar/gap/TK64 findings and original A audit records remain. The public counterpart must show dated same-description, invalid-date, EOF cases against genuine mixed-title/whole-date-title, competing date-bearing propositions and source/parent/quote failures. Any safety/application limit is reported before an approval question. No current product permission is inferred.
