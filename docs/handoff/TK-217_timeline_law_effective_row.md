# TK-217 Time-Table에 법률 시행일 서술 꼴 비사실형 행이 남는다

- 발견일: 2026-11-19 (2회차 온라인 점검 PR #347)
- 종류: 기존 기능 개선. **TK-206의 실패가 아니다**
- 상태: open
- 우선순위: P3

## 문제

실제 서면9 세 실행의 Time-Table에서 재판행위 날짜 행은 0이었다(TK-206 해소). 그런데 같은 표에
`case9_real_law_effective_candidate_rows: 1` — **법률 시행일 서술 꼴의 비사실형 행 후보 1개**가 남았다.

| 관찰 | 값 |
|---|---|
| `case9_real_timeline_rows` | 3 |
| `case9_real_judicial_rows` | **0** |
| `case9_real_incident_rows` | 1 |
| `case9_real_law_effective_candidate_rows` | **1** |

## 왜 TK-206과 섞지 않는가

TK-206은 **재판행위 날짜**(선고·결정·판시 등)를 사실관계 표에서 빼는 것이고, 그 축은 실제 서면 두 종류에서
행 0으로 확인됐다. 시행일은 재판행위가 아니다. `extractor.py`의 `_STATUTE_*` 경로이고 TK-206 수정은 그것을
건드리지 않았다(수용 당시 명시).

'사실관계 중심 Time-Table'이라는 더 넓은 요구의 잔여다. 두 문제를 섞으면 TK-206의 해소 판정이 흐려지고,
수정 범위도 잘못 잡힌다.

## 아직 모르는 것

1회차 판정에서 본 법령 시행일 유형과 같은 잔여인지는 **비공개 원문 문맥 대조가 필요해 미확정**이다.
운영 기록은 실제 서면의 행 문구를 공개하지 않으므로(옳은 처리다) 평가 측도 그 문구를 갖고 있지 않다.

## 할 일 (다음 릴리스)

1. **먼저 전수 조사.** 시행일 서술이 사실관계 행으로 올라오는 꼴을 합성으로 전수 조사한다. 한 꼴만 고치면
   다음에 다른 꼴이 남는다 — TK-206에서 네 번 반복한 실수다.
2. 사실 날짜(당사자 행위·사고·처분)와 법령 효력 날짜를 가르는 **구조**를 정한다. 낱말 열거로 하지 않는다
   (2026-11-19 재발 방지 규칙).
3. 과차단을 함께 본다. 시행일이 **사건의 쟁점일 때**(행위시법 판단)는 표에 있어야 할 수 있다 —
   그 경우를 배제하면 새 결함이다.

## 수용 기준

1. 합성 전수 조사 결과를 제출한다(꼴 목록과 현재 동작)
2. 비사실형 시행일 행이 사라지고, 사실 날짜·쟁점 시행일은 남는다
3. 재판행위 날짜 배제(TK-206)와 당사자 사실 날짜 보존이 바뀌지 않는다 — 누적 탐침 127칸 유지
4. 고정 세트·은퇴 세트 변화 없음
