## 평가 측 코드 경로 특정 (오프라인 정적 분석, SHA `556dac84`)

원인 후보가 셋이고 서로 다른 자리에 있다. 운영 접근 없이 어느 것이 주원인인지 가릴 수 없으므로
**진단을 먼저 세우는 것**을 이 티켓의 1차 수용 기준으로 둔다.

### 후보 A — 동기화 예산이 말뭉치 규모에 비해 짧다

`packages/common/config.py:112`

    rag_sync_seconds: int = ... max(1, min(600, int(os.getenv("LV_RAG_SYNC_SECONDS", "120"))))

`packages/rag_engine/library.py:166`에서 `budget = max(1, min(600, settings.rag_sync_seconds))`,
`:184`에서 `deadline = time.monotonic() + budget`로 쓰인다. 기본값 **120초**이고 상한이 600초다.
운영 말뭉치는 41파일·2,636쪽이다. 1회 실행의 색인 35/41과 '예산 소진' 기록은 이 값과 부합한다.
2·3회가 41/41에 도달한 것은 앞 실행의 캐시가 남았기 때문으로 보인다.

### 후보 B — `coverage_complete`가 parse 경고 한 건에도 전체를 미완독으로 만든다

`packages/rag_engine/extract.py:335-344`

    coverage_complete = (
        not incomplete_pages
        and not next_continuation
        and not coverage_missing
        and not doc.parse_warnings
    )

`doc.parse_warnings`가 하나라도 있으면 모든 쪽을 읽었더라도 `coverage_complete`가 거짓이 되고
`:357-359`에서 `REFERENCE_PARTIALLY_READ`가 붙는다. 2,636쪽 중 37쪽이라는 작은 차이는
특정 쪽(스캔·저품질 OCR)이 구조적으로 읽히지 않는 꼴과 부합한다. 그렇다면 **몇 번 다시 돌려도
`H-REF`는 영구히 충족되지 않는다.**

### 후보 C — 쪽 단위 재시도·체크포인트가 자료 단위에서 끊긴다

`library.py:416-485`에 `continuation` 이어가기가 있고 `:52`의 `isolated_extract(..., continuation=)`로
넘어간다. 그러나 보류(`FILES_DEFERRED`, `:684`)와 시간 초과가 자료 단위로 집계되어, 읽지 못한
개별 쪽만 겨냥한 재시도 경로가 보이지 않는다.

## 할 일 (구현 측)

1. **진단 분리.** 자료별로 (ㄱ) 읽지 못한 쪽 번호, (ㄴ) 그 쪽의 사유를 `예산 소진`·`읽기 시간 초과`·
   `파서 실패`·`자료 성질상 텍스트 없음`(스캔·빈 쪽)으로 나눠 실행 기록에 남긴다. 사유가 섞여 있으면
   섞인 그대로 남긴다. 추정으로 하나를 고르지 않는다.
2. **완독 판정 분리.** `coverage_complete`를 둘로 나눈다.
   - `coverage_complete`: 실행 문제(예산·시간 초과·파서 실패)로 못 읽은 쪽이 없다
   - `content_readable_complete`: 자료 성질상 읽을 수 없는 쪽까지 없다
   `REFERENCE_PARTIALLY_READ`는 앞의 것에만 붙이고, 자료 성질 쪽은 별도 사유 코드로 표시한다.
   표시 문구는 `packages/common/display_text.py`에 함께 넣는다.
3. **쪽 단위 재시도.** 읽지 못한 쪽만 다음 실행에서 이어 읽는다. 자료 전체를 다시 내려받지 않는다.
4. **예산.** 기본값·상한이 말뭉치 규모에 맞는지 근거와 함께 적는다. 값을 바꾸려면 측정으로 보인다.
   코드에 말뭉치 규모를 하드코딩하지 않는다.

## 수용 기준

1. 실행 기록에 자료별 미완독 쪽 번호와 사유 분류가 남는다
2. 실행 문제 0이면서 자료 성질 쪽만 남은 경우 `coverage_complete`가 참이 된다
3. 쪽 단위 이어 읽기가 합성 자료 시험으로 증명된다
4. 기존 시험 전부 통과, 은퇴 세트 후퇴 없음, 고정 세트 점수 이동 없음, 엔진 오류 0
5. 다음 온라인 회차에서 `H-REF`의 충족/미충족 사유가 위 분류로 설명된다

## 미검증

후보 A·B·C 중 주원인은 **평가 측에서 검증하지 못했다.** 운영 Drive 연결과 색인 상태가 필요하다.
세 후보는 정적 분석으로 특정한 코드 자리이며, 구현 측이 진단으로 가려야 한다.
