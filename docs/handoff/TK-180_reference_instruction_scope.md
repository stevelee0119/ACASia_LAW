# TK-180 — 지시문 판정 범위를 입력 법률 문서로 한정

평가 재개: 2026-11-15(한국). 평가 측 사본 `64c4ff9a`, 기준 #298 `d0af8733`(Steve `c99e611` + TK-178). 제품 코드 변경은 저장소 밖 평가 사본에만 있다.

## 사용자 원문
> RAG에 저장된 자료들은 검증이 완료된 것에 한정되므로, RAG에 저장된 자료는 전부 '지시문'으로 판정하지 않도록 해줘.
> 지시문을 판정하는 것은 오로지 입력된 법률 문서 자체 및 그 내용에 한정되고, 공식 DB 또는 RAG자료들의 내용은 '지시문'으로 판정해서는 안돼. 특히 문헌 자료들은 학술 논문이나 판례등이 있어 지시문으로 보일 수 있는 내용이 있지만 '지시문'으로 판정하지 않도록 구성해야 해.

## 원문 대응표
| 요구 | 확인 동작 |
|---|---|
| 입력 법률 문서만 지시문 판정 | 같은 합성 문장 3꼴을 입력 서면으로 검사하면 MM1 탐지 유지 |
| RAG 자료를 지시문으로 판정하지 않음 | TXT·PDF·판례표 본문·속성·링크에서 지시문 분류를 호출하지 않고 읽을 수 있는 자료 보존 |
| 공식 DB 자료를 지시문으로 판정하지 않음 | 공식 원문은 기존 경로에 분류기 호출 없음. 모델 프롬프트에 원문 보존·범위 명시 |
| 문헌·논문·판례의 지시형 문구 보존 | 문헌의 지시형 문구를 이유로 파일·쪽·행을 제외하지 않음 |

## 확인한 원인과 수정
1. `packages/rag_engine/extract.py::extract`: 참고문서 전체를 AdversarialScanner에 넣어 본문·메타데이터의 MM1을 파일 격리·쪽 제외로 연결했다. 사본은 분류기 호출을 없앤다. `EXTRACTOR_VERSION`을 올려 이전 격리·쪽 제외 캐시를 재추출한다.
2. `packages/rag_engine/case_table.py::_row_scan`, `_scan_hyperlink`: 참고자료의 행·속성·링크를 분류했다. 사본은 두 경로에서 빈 지시문 결과를 반환하고 분류기를 생성하지 않는다. 표 버전도 올려 이전 체크포인트를 무효화한다.
3. 공식 DB 응답·RAG 검색 결과는 별도의 지시문 분류기에 들어가지 않는다(호출 경로 검색). `review.py::RAG_REVIEW_SYSTEM_PROMPT`, `argument_validity_verifier.py::_OPINION_SYSTEM`, `llm_router/router.py::_build_prompt`에 판정 범위를 명시한다. 원문을 삭제하거나 모델의 실행 지시로 승격하지 않는다.
4. 입력 서면의 `verification_engine/pipeline.py` adversarial 단계는 그대로다. 개인정보·출력 검사·권한·리비전·용량·파싱·암호화 파일·가시성 제한은 그대로다. 숨김 행 제외는 지시문 판정과 별개로 유지한다.
