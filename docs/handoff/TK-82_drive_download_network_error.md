# TK-82 Drive 참고자료 내려받기 네트워크 오류가 원인 구분·재시도 없이 그 자료를 통째로 뺀다 (P3, 견고성·관측성, 기존 공백)
- 유형: 견고성·관측성(참고자료 동기화). 탐지·채점 규칙 변경이 아니다.
- 발견: 평가 측, 2026-10-19. 0.13.1 운영 분석(TK-80 4단계, 사용자 실행)의 '자료별 처리 기록'에서 `분야별 업무편람/헌법재판실무제요_제3개정판.pdf · UNAVAILABLE · DRIVE_NETWORK_ERROR`.
- 근거는 운영 실행의 처리 기록 1건과 0.12.0 운영 실행 기록('파일 1개 내려받기 네트워크 오류', HISTORY 2026-10-10)뿐이다. 두 건이 같은 파일인지는 기록이 없어 확인하지 못했다.

## 1. 증상
- `packages/rag_engine/drive.py` `read()`는 `httpx.HTTPError`를 모두 `DRIVE_NETWORK_ERROR` 하나로 바꾼다(161~163행). 연결 실패·응답 지연·전송 중 끊김을 구분하지 못한다.
- 받은 바이트 수는 호출 기록에 남지만 처리 기록 화면에는 나오지 않는다. 큰 파일이 중간에 끊긴 것인지, 처음부터 연결되지 않은 것인지 알 수 없다.
- 재시도가 없다. 한 번 끊기면 그 실행에서 해당 자료는 `UNAVAILABLE`로 빠지고, 그 자료와 관련된 주장의 참고자료 대조가 줄어든다.
- 시간 제한은 `timeout=min(15, self.remaining())`이다. httpx에서는 연결·읽기 단계마다 적용된다.

## 2. 요구
1. 오류 원인을 구분해 남긴다. 호출 기록(`calls`)과 자료별 처리 기록의 `reason`에 남긴다.
   - 예외 종류: 연결 실패, 읽기 시간 초과, 전송 중 끊김(`RemoteProtocolError`·`ReadError` 등), 그 밖의 오류.
   - 받은 바이트 수를 함께 남긴다.
   - 상태 코드는 기존처럼 `DRIVE_NETWORK_ERROR`로 유지해 기존 집계와 호환한다. 세부는 `reason`에 둔다.
2. 동기화 예산이 남아 있을 때만 **1회만** 재시도한다.
   - 대상: 연결 실패, 읽기 시간 초과, 전송 중 끊김.
   - 다음은 재시도하지 않는다: `DRIVE_HTTP_4xx`, `FILE_SIZE_LIMIT`, `SYNC_BUDGET_EXHAUSTED`.
   - 재시도 여부를 호출 기록에 남긴다.
3. 예산·파일 크기 상한·선별 규칙은 바꾸지 않는다. 키·URL·파일 내용은 기록에 넣지 않는다.

## 3. 시험
- `httpx.MockTransport`로 다음을 각각 흉내 낸 단위 시험을 둔다.
  - 연결 실패
  - 읽기 시간 초과
  - 전송 중 끊김(일부 바이트 뒤 예외)
  - 403
- 확인할 것:
  - 첫 번째 시도 실패 뒤 재시도에 성공하면 내용이 정상으로 반환되고, 호출 기록에 재시도가 남는다.
  - 두 번 모두 실패하면 `DRIVE_NETWORK_ERROR`와 세부 `reason`이 남는다.
  - 403·크기 초과·예산 소진은 재시도하지 않는다.
- 기존 `tests/` 중 Drive 동기화 시험이 그대로 통과한다. 고정 82.6/80.1·오탐 0은 바뀌지 않는다(오프라인은 네트워크를 쓰지 않음).

## 4. 수용
- CI 필수 검사가 성공해야 한다. 탐지 diff는 0이어야 한다(drive.py·library.py 기록 경로와 시험만 바뀜).
- 배포 뒤 다음 운영 분석에서 같은 파일이 다시 실패하면, 처리 기록의 세부 `reason`으로 원인을 판정한다.
