## 1. 사용자 요구 원문(11-03)

> 외부 AI 답변 내용 인용 재검증을 하게되면, 결국 검토가 끊임없이 반복되어야 하는 구조인 것 같아.
> claude, gemini, chatgpt를 모두 활용해 얻은 답변을 바탕으로 법률에 특화된 AI로 검증을 하는 구조이므로, 법률 AI가 새로운 환각을 일으킬 가능성은 높지 않아보여. 그런 우려가 있다면 그 부분의 엄격성을 강조하도록 검증 프롬프트를 생성하는 것이  추가적인 검증단계를 만드는 것보다 더 효율적이지 않을까?

## 2. 원문 대응표(수용 기준)

| 원문 문장 | 대응 | 확인 방법 |
|---|---|---|
| 인용 재검증은 검토가 끝없이 반복되는 구조 | 외부 답변 재검증 단계를 만들지 않는다. 답변 반영 흐름(`parseExternalAnswers`·보고서 반영)은 바꾸지 않는다 | diff에 재검증 코드 없음, 파서 시험 통과 |
| 법률 AI가 새 환각을 일으킬 가능성은 높지 않음 | 별도 단계 대신 프롬프트에서 환각 경로(기억으로 사건번호 생성, 의역에 따옴표, 반대의견 인용, 근거 없는 부존재)를 막는다 | 규칙 1·3·4·5 |
| 우려가 있으면 그 부분의 엄격성을 강조하는 프롬프트 | 두 프롬프트(미확인 판례·법령, 무리한 주장)에 '엄격성 규칙 7개' 블록. 대체 판례 요청은 규칙 6으로 한정(최대 2건, 못 지키면 '해당 없음') | 화면 '프롬프트 생성' 결과 캡처 2장 |
| 추가 검증 단계보다 효율적 | 결과 블록 칸 수(4칸) 유지, 근거 칸에 '(확인 방법)'만 추가 → 기존 답변 반영과 호환 | 결과 블록 시험 |

## 3. 원인(`892bbd8`, `apps/web/static/app.js`)

1. `buildExternalAiPromptForUnverifiedAuthorities`(362행~) 요청 3항(391행)이 '가공 판례라면 같은 쟁점의 실제 대법원 판례 제시'를 확인 조건·건수 제한 없이 요구한다. 확인하지 않은 판례를 새로 만들 유인이다.
2. `buildExternalAiPromptForLegalClaims`(554행~) 요청 3항(572행)도 '주장을 뒷받침하거나 반박하는 실제 대법원 판례'를 조건 없이 요구한다.
3. 두 프롬프트 모두 인용 표기(법원·선고일·사건번호), 따옴표 사용, 의견 귀속, '부존재'와 '불명' 구분 규칙이 없다.
