# TK-182 — Drive 참고자료 읽기 완전성·빈 쪽/스캔 구분·암호화 진단

발견: 2026-11-15 · 우선순위 P1 · 유형 existing · 목표 0.22.0 · 구현 Antigravity / 평가 별도 세션.

## 확인된 문제와 원인

운영83d862e7의 이번 자동6실행 모두 reference_sync 미완료. 실제 색인27자료 중19자료의 read_pages<pages, 차이 합163쪽. 암호화 거절1자료, 판례표3556행은 격리0/오류0/대기0. 163쪽이 모두 내용 있는 쪽이라고 단정하지 않는다.

`packages/rag_engine/extract.py` PDF 분기는 pypdfium2→pypdf 텍스트만 읽고 OCR을 하지 않는다. 이후 텍스트가 비면 no_text_pages에 넣고 partial로 기록한다. 입력문서 OCR 준비가 READY여도 이 참고자료 경로에는 적용되지 않는다. 합성 재현: 텍스트PDF는1/1, 완전 빈PDF와 글자 이미지PDF는 둘 다0/1·REFERENCE_PARTIALLY_READ. 현재 보고서에는 빈 쪽/스캔/OCR/파서 경고를 분리하는 증거가 부족하다.

같은 파일의 `reader.is_encrypted` 일괄 거절은 빈 비밀번호로 정상 열리는 PDF도 막는다. 합성으로 확인했다. 실제 암호화1자료의 빈 비밀번호 열림 여부는 아직 미검증이다.

## 해결 방향

1. 페이지별 상태를 NATIVE_TEXT / OCR_TEXT / VERIFIED_BLANK / UNPROCESSED / OCR_LOW_QUALITY / ERROR 등으로 구분하고, 원인·쪽번호·재시도 여부를 캐시/보고서 진단에 보존한다. 텍스트가 없다는 이유만으로 VERIFIED_BLANK로 처리하지 않는다.
2. 기존 정상 입력 PDF의 OCR·렌더 경로를 참고하되 참고자료용 자원·시간·메모리·페이지 예산을 유지한다. 빈 쪽 확인과 이미지/OCR은 필요한 쪽만 수행하고, 파일SHA/추출기판/쪽별 체크포인트로 이어 읽는다. 예산 종료는 남은 쪽을 명시하고 다음 동기화에서 재개한다.
3. 빈 비밀번호로 정상 열리는 PDF는 읽되 비밀번호가 실제로 필요한 PDF는 여전히 미확인으로 남긴다. 암호 대입/보호 우회는 하지 않는다. 부분 사본 패치는 아래에 있다.
4. 전체 라이브러리 완전성과 이번 검색 범위의 동기화/대조 완료를 구분하되 전체163쪽/암호화1자료를 숨기지 않는다. 무관 자료가 검색되지 않은 것과 자료를 읽지 못한 것을 같은 완료 상태로 표시하지 않는다.
5. 관리자 진단에는 파일별 쪽/사유/캐시판/다운로드·추출 시간을 제공한다. 일반 사용자 화면에는 조치 가능한 이유를 표시하고 원문/인증정보/서버경로는 노출하지 않는다. 보호경로·PII·입력 인젝션 탐지와 TK-180의 기준자료 역할 분리를 유지한다.
6. 추출 의미가 바뀌므로 추출기판을 올려 기존 partial/오격리 캐시를 재평가한다. 실제19자료의 빈 쪽/내용 쪽을 확인한 뒤163쪽의 처리 결과와 암호화1자료의 조치를 운영에서 재측정한다.

## 사전 검증·미검증 경계

`patches/TK-182_empty_password_reference_subpatch_on_83d862e7.diff`는 빈 비밀번호 처리만의 부분 패치다. 평가 사본에서 기존 관련54시험+새3시험 통과. 원래 코드는 새3시험 중1실패/2통과. 비밀번호 필요 PDF 거절은 유지. OCR/빈 쪽/이어읽기/운영163쪽의 해결 패치는 아직 없으며 이 부분 패치를 전체 해결로 제출하면 안 된다.

수용: 일반텍스트·순수빈쪽·텍스트이미지·혼합PDF·저품질OCR·예산중단/재개·빈비밀번호/실제비밀번호 대조 시험. 원래 입력 문서의132 보안회귀와 참조역할 시험 유지, 고정/은퇴 게이트. 운영 재색인에서 모든 누락의 처리/미처리 이유가 설명되고 필요한 본문이 색인되며, 진짜 미확인을 READY로 숨기지 않아야 한다. TK-180 TXT/PDF/DOCX/XLSX 대조·case9 대조군도 최종 후보에서 실제 실행.
