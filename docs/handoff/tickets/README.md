## 3. 구현 에이전트 작업 규칙 (필수 준수)
- **회귀 0 및 하드코딩 0 엄수 (절대 원칙):**
  - 기존 기능, 고정 세트(`dev`/`holdout`), 은퇴 5세트, 확인 오탐 0·A등급 오탐 0에서 **단 1건의 회귀도 허용하지 않는다**(`scripts/score_gate.py`, `scripts/regression_gate.py`).
  - 사건 고유 값(당사자명·사건번호·금액·수치), 서면 문구(한글 10자 이상), 영문 대문자 식별자(12자 이상), 특정 문구 맞춤 정규식 등 **하드코딩·과적합을 엄격히 금지한다**(`scripts/check_case_literals.py`, `scripts/check_hardcoding_diff.py`, `check_train_phrase_overlap.py`).
  - 모든 새 규칙·개선은 서로 다른 일반화 양성 3건 이상과 대조군(부정·가정·상대방 전언·적법 사안 등) 3건 이상의 단위 시험 및 축별 자체 점검을 통과해야 한다.
- **티켓 범위 완결성 (부분 구현·잔여 이월 금지):**
  - 티켓 1건은 **해당 티켓에 명시된 수용 기준과 인접 결함 전체를 한 번에 완결**해야 한다.
  - 핵심 연결만 해두고 `shadow`/`stub` 상태로 두거나 일부 축만 고친 채 나머지를 "후속 과제/잔여 과제"로 남기지 않는다.
  - 구현 중 같은 원인 축에서 드러난 인접 결함도 같은 PR에서 함께 해결하며, 범위를 축소·연기해야 할 구조적 사유가 있으면 임의로 자르지 말고 사유를 명시해 사용자·평가 측 결정을 먼저 받는다.
- **절차 및 보고:**
  - 1티켓 = 1PR 단위로 `Steve_ACASiaLAW` 대상 PR을 생성한다.
  - 각 티켓의 4절(구현 설계 요약)을 채우고, PR 코멘트 3줄(`바꾼 것`·`남은 것`·`검토 요청`)과 커밋 끝 `Agent: implementer`를 적는다.
  - 보호 경로(`docs/scorecards/**`, `tests/acceptance/**`, `tests/fixtures/**` 등) 수정 금지.
