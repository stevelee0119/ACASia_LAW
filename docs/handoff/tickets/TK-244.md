## 1. 문제 현상 및 결함 범주
- **현상**: 운영 저품질 스캔에서 RapidOCR 원본 신뢰도 **0.582**, 전처리본 **0.534**인데 **전처리본이 선택**됐다(사유 `PREPROCESSED_HIGHER_QUALITY`). 0.26.0의 선택 신뢰도 0.582 → 0.29.0 0.537 → 0.30.0 0.534로, TK-231 전처리 투입 뒤 선택 품질이 떨어진 상태가 이어진다.
- **범주**: OCR 선택 정책 결함 + 사유 표기 결함. 탐지 diff는 OCR 쪽 품질 변화로만 생긴다.

## 2. 원인 (코드 확인 + 사본 재현, `71a8ffc3` 기준)

1. **비교 순서.** `packages/document_engine/ocr.py:542-548` `_quality_rank()`가 `(저품질 아님, hangul_ratio, confidence, lines)` 순의 튜플이다. 두 변형이 **둘 다 저품질**이면 첫 칸이 같아 `hangul_ratio`가 결정한다. 한글 비율의 작은 차이가 신뢰도의 큰 차이를 이긴다. `:806` `choose_pre`가 이 순위를 그대로 쓴다.
2. **사유 표기.** `:814-818` `selection_reason`은 어느 칸이 결정했는지와 상관없이 `PREPROCESSED_HIGHER_QUALITY`/`RAW_HIGHER_OR_EQUAL_QUALITY`만 남긴다. 신뢰도가 낮은 쪽이 "품질이 높다"고 기록된다.
3. **감사 불가.** 원격 측정에 변형별 `hangul_ratio`·`low_quality`가 없어 운영 기록만으로 선택을 검증할 수 없다. 평가 측은 운영 값(원본 0.582 > 전처리 0.534 선택)과 코드 순서로 원인을 추정했고, 변형별 한글 비율 값은 **운영에서 관측하지 못했다.**
4. `_fallback_improved()`(`:551-569`)도 마지막에 같은 `_quality_rank()`를 쓴다. 1차↔폴백 비교에도 같은 성격이 남는다.

## 3. 고칠 것

1. **순위 재설계.** 한글 비율은 **기준(`settings.ocr_min_hangul_ratio`) 통과 여부**로만 먼저 본다. 둘 다 통과(또는 둘 다 미달)하면 **신뢰도**로 고른다. 그다음 한글 비율 값, 줄 수.
   ```python
   def _hangul_ok(q):            # 비율 None(글자 적음)은 통과로 본다 — page_quality와 같은 규칙
       r = q.get("hangul_ratio"); return r is None or float(r) >= get_settings().ocr_min_hangul_ratio
   def _quality_rank(q):
       return (not q.get("low_quality"), _hangul_ok(q), conf, hangul_ratio, lines)
   ```
   깨진 한글(로마자로 읽힌 쪽)을 거르는 기존 방어(한글 비율 미달 변형이 신뢰도로 이기지 못함)는 둘째 칸이 유지한다.
2. **결정 기준 기록.** 첫 번째로 달라진 칸 이름을 `deciding_key`(`LOW_QUALITY`·`HANGUL_RATIO_THRESHOLD`·`CONFIDENCE`·`HANGUL_RATIO`·`LINES`·`EQUAL`)로 남긴다. `selection_reason` 기존 값은 하위 호환으로 유지해도 되지만, 신뢰도가 낮은 쪽을 고른 경우 그 사실이 `deciding_key`로 드러나야 한다.
3. **원격 측정 보강.** `raw_hangul_ratio`·`preprocessed_hangul_ratio`·`raw_low_quality`·`preprocessed_low_quality`를 추가한다.
4. `_fallback_improved()`가 같은 `_quality_rank()`를 쓰므로 1차↔폴백 비교도 새 순위를 따른다. 시험으로 그 경로를 함께 확인한다.
5. **D-2 범위 주의:** 원본(0.582)을 골라도 `OCR_EXTRACTED` 기준(평균 신뢰도 0.70) 미만이다. **이 티켓만으로 TK-239 D-2(실제 복구)는 충족되지 않는다.** 복구 미달 쪽을 `OCR_EXTRACTED`로 둔갑시키지 않는다(TK-237 수용 기준 4항 유지). 기준·엔진 변경은 이 티켓 범위가 아니다(아래 7절, 사용자 결정 대기).

- 위 세 꼴: 깨진 한글 폴백 **채택 안 함** / 0.4997 → `hangul_ok=False`(순위·저품질 일치) / 13자 → `hangul_assessed=False`·`hangul_ok=True`. 기존 방어(20자 이상 깨진 한글은 신뢰도가 높아도 진다) 유지.
