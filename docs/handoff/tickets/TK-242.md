## 2. 원인 (재현으로 확인, SHA `bc7b0de0` 기준)

### 원인 1 — `signatures()`가 `ast.dump`를 쓴다 (`scripts/check_test_edits.py:76-95`)

`signatures()`가 시험 본문을 `ast.dump(...)`로 직렬화하고 `body_digest()`(`:100-104`)가 그 문자열을 SHA-256으로 해시한다. `ast.dump` 출력은 파이썬 판마다 다르다(3.12에서 `FunctionDef.type_params` 추가 등). 그래서 **같은 파일·같은 커밋인데 지문이 판마다 다르다.** 같은 커밋 `d9af4044`의 같은 시험에서:

```
파이썬 3.11 → 1e69f91f3460d3af
파이썬 3.12 → 1e69f91f3460d3af
파이썬 3.13 → 32ea042c74344f37
```

CI 러너는 `3.11.18`, 평가 컨테이너 기본 파이썬은 `3.13.18`이다. 평가 측이 컨테이너에서 뽑은 지문을 `approved_test_marks.json`에 넣으면 CI에서 범위 불일치로 실패한다. 실패 메시지는 지문만 보여주고 **어느 판에서 계산한 값인지 적지 않아** 원인을 짚기 어렵다.

`TK-215` 시험(`tests/test_tk215_test_edit_approval_scope.py`)은 지문 **대조 논리**만 검사하고, 모든 지문을 같은 인터프리터 안에서 계산하므로 판 간 불일치를 잡지 못한다.

### 원인 2 — `all_evaluator_commits()`가 PR 병합 시험 커밋에 걸린다 (`scripts/check_test_edits.py:107-112`)

```python
log = _git("log", f"{base}..HEAD", "--format=%H%x00%B%x01")
return all("Agent: evaluator" in c for c in commits)
```

CI의 `HEAD`는 GitHub가 만든 **PR 병합 시험 커밋**이고 그 메시지는 `Merge <sha> into <sha>`다 — 꼬리표가 없다. 따라서 `base..HEAD` 범위에 꼬리표 없는 커밋이 항상 하나 섞여 `all(...)`이 거짓이 된다. **문서가 약속한 평가 측 예외는 PR에서 구조적으로 발동하지 않고, 직접 푸시에서만 발동한다.**

파급이 더 크다: 평가 측이 로컬에서 그냥 돌리면 예외가 걸려 **통과**하므로, CI 실패를 로컬에서 재현할 수 없다. 이번에 CI와 같은 병합 커밋을 손으로 만들어야 원인이 보였다.

### 원인 3 — `read_tickets()`의 경로와 식별자 (`scripts/ticket_metrics.py:37-39`)

```python
for path in sorted(HANDOFF.glob("TK-*.md")):   # HANDOFF = docs/handoff (최상위만)
    tid = path.name.split("_")[0]
```

결함이 둘이다.

- **경로**: `docs/handoff` 최상위만 읽는다. `TK-220` 이후 티켓은 `docs/handoff/tickets/` 하위에 있어 **22건이 집계 밖**이다. 그래서 `--check`가 세는 수는 156건(`TK-219`까지)이고, 하위 티켓의 등재 여부를 **아예 묻지 않는다.** `test_ticket_registry_covers_every_ticket`도 같은 함수를 쓰므로 함께 눈을 감는다.

## 3. 고칠 것

### 3-1. 직렬화를 파이썬 판에 안정적으로 바꾼다 (원인 1)

`ast.dump`를 쓰지 않고 필드를 직접 쓴다. 노드 종류 이름 + `_fields`를 **이름순으로** 직렬화하고, 판마다 추가·변동된 필드(`type_params`·`type_comment`)는 제외한다. 주석·서식 비민감성(현행 성질)은 그대로 유지된다.

```python
_IGNORED_FIELDS = frozenset({"type_params", "type_comment"})
SIGNATURE_ALGO = 2

def _canon(node) -> str:
    if isinstance(node, ast.AST):
        parts = [f"{f}={_canon(getattr(node, f, None))}"
                 for f in sorted(node._fields) if f not in _IGNORED_FIELDS]
        return f"{type(node).__name__}({','.join(parts)})"
    if isinstance(node, list):
        return "[" + ",".join(_canon(x) for x in node) + "]"
    return repr(node)
```

`signatures()`는 `out[...] = _canon([*node.decorator_list, node.args, *node.body])`로 바꾼다.

함께 할 것:

- **고정값 회귀 시험을 둔다.** 알려진 입력의 기대 지문을 시험에 **문자열 상수로 박아** 둔다. 직렬화가 앞으로 또 바뀌면 게이트가 조용히 실패하는 대신 그 시험이 큰 소리로 깨진다. 이것이 이 수정의 핵심 안전장치다.
- **실패 메시지에 계산 환경을 적는다.** 지문을 출력할 때 파이썬 판과 `SIGNATURE_ALGO`를 함께 적는다. `--digest`의 출력도 같다.
- **낡은 알고리즘의 승인을 조용히 통과시키지 않는다.** 승인 항목에 `scope.algo`를 두고, 값이 현행 `SIGNATURE_ALGO`와 다르면 **승인으로 보지 않고** 그 사유를 출력한다(지문을 다시 뽑으라는 안내 포함). 모르는 것을 맞다고 치지 않는다.

### 3-2. 평가 측 예외의 판정 기준을 바로잡는다 (원인 2)

**(가) 보수로 확정.** 2026-11-26 사용자 승인(원문 "(가) 보수 승인"). 게이트의 판정 범위를 바꾸는 변경이므로 승인 사항이었고, 느슨해지지 않는 쪽을 택했다.

- 예외의 동작을 **그대로 둔다.** `all_evaluator_commits()`의 판정 기준을 고치지 않는다(`--no-merges` 같은 완화를 넣지 않는다).
- **PR에서는 발동하지 않음을 명시한다.** 모듈 머리글(`check_test_edits.py:9`의 예외 설명)에 "직접 푸시에서만 발동한다. CI의 PR 검사에서는 병합 시험 커밋 때문에 발동하지 않는다"를 적고, 삭제·약화 실패 메시지에도 같은 뜻을 한 줄로 적어 다음 사람이 승인 목록 경로를 바로 찾게 한다.
- **평가 측 보호 시험 수정은 승인 목록 경로로만 처리한다**(설계된 경로). 이번 `#438`이 그 경로로 해소된 선례다.
- 검토하지 않은 완화를 넣지 않으므로 **기존 승인·기존 판정에 소급 영향이 없다.**

함께 할 것:

- **로컬·CI 일치 확인 수단을 둔다.** 병합 시험 커밋을 만들어 게이트를 돌리는 절차를 `scripts/precheck_pr.py`에 넣거나 같은 일을 하는 스크립트를 둔다. 지금은 손으로 `git commit-tree`를 해야 CI 조건을 재현할 수 있다.

### 3-3. 티켓 집계의 경로와 식별자를 고친다 (원인 3)

```python
paths = sorted({*HANDOFF.glob("TK-*.md"), *(HANDOFF / "tickets").glob("TK-*.md")})
for path in paths:
    tid = path.name.split("_")[0].removesuffix(".md")
```
