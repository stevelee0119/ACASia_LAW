## 2. 원인
1. **Drive 대조 호출 상한**: `packages/rag_engine/review.py:858-859` `max_total_calls = 2×ceil(N/6)×청크 수`가 거절된 첫 시도와 대체 공급자 재시도를 모두 센다(`:885` `total_calls += 1`).
   - 묶음마다 2회를 쓰므로 25묶음 가운데 14묶음에서 상한(28)에 닿았다.
2. **주장 대조 비용 예산**: 라우터는 사용량이 없는 실패를 원장 예약액 전액으로 기록한다(`packages/llm_router/router.py:585-592`, `RESERVED_UNCERTAIN`, 호출당 약 $0.30).
   - `review.py:1314-1319`가 이 값을 단계 예산(`rag_claim_budget_usd`, 기본 $1.00)에 더하고, `:1021`에서 COST로 멈춘다.
   - 실제 처리 비용은 대체 공급자 호출당 약 $0.02다.
3. 오류 응답의 과금 여부는 공식 문서(https://platform.claude.com/docs/en/api/errors)에 적혀 있지 않다. 그래서 원장 규칙(사용량을 확인하지 못한 예약은 풀지 않음, `budget.py:179-195`)은 바꾸지 않는다.

## 3. 고칠 것 (`review.py`만. 라우터·원장은 바꾸지 않는다)
1. 공급자 거절 판정 함수 `_provider_rejected(execution)`를 둔다. 조건은 `ok is False`이고 `error`가 `^HTTP [45]\d\d`로 시작하는 것이다. 응답 시간 초과(`PROVIDER_TIMEOUT`)와 예외(`PROVIDER_EXCEPTION`)는 해당하지 않는다.
2. **Drive 대조**:
   - 실패한 실행이 **모두** 공급자 거절이면, 대체 공급자 재시도를 호출 상한에 세지 않는다.
   - 출력 잘림(`OUTPUT_TRUNCATED`)처럼 사용량이 생긴 실패의 재시도는 지금처럼 센다(TK-68 C3 시험 유지).
   - 묶음마다 대체 재시도는 1회뿐이므로 최악 호출 수는 `max_total_calls + 최초 묶음 수`로 유계다.
   - 구현 방법: 세지 않는 재시도 항목을 따로 표시한다(사전 검증본은 `id(item)` 집합). 대기열 루프 조건은 '상한 미달이거나 다음 항목이 세지 않는 재시도'로 한다. `remaining_calls`는 세는 항목만 뺀다.
3. **주장 대조**:
   - `accumulated_rejected_usd`(공급자 거절 예약액)를 따로 쌓는다.
   - COST 중단 판단과 다음 묶음 크기 계산에는 `accumulated_cost_usd - accumulated_rejected_usd`를 쓴다.
   - `spent_usd`·`uncertain_usd` 기록의 의미는 그대로 두고(`test_tk65` 유지), `budget.provider_rejected_usd`를 추가한다.
4. 전역 예산(원장 월·실행 한도)은 예약을 그대로 유지하므로 Fail-Closed를 유지한다.
5. **시험**: 평가 측 패치 [`TK-254_255_tests.patch`](TK-254_255_tests.patch)(sha256 앞 12자리 `22d5a1f6bb69`). 새 시험 `test_tk255_provider_rejection_budget.py` 3건(양성 2, 대조 1: 시간 초과는 계속 예산에 셈).
