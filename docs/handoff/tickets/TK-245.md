## 1. 문제 현상 및 결함 범주
- **현상**: case9 Drive 라이브러리에서 미완독 16쪽이 모두 `OCR_LOW_QUALITY`로 기록되고 재처리 트리거도 발동했지만(3파일 재추출·5쪽 재처리) **복구 0/16**, `searchable_pages_delta 0`, **`ocr_fallback_attempted_pages 0`**이다. 같은 운영 판의 문서 업로드 경로(TK-239 측정)에서는 폴백이 시도된다.
- **범주**: 설정 전파 결함(참고자료 경로만). 재처리 판 기록으로 다음 실행부터 재시도도 막힌다.

## 2. 원인 (코드 확인 + 사본 재현, `71a8ffc3` 기준)

1. **환경 허용 목록 누락.** `packages/rag_engine/library.py:210-240` `isolated_extract()`는 추출 하위 프로세스(`python -m packages.rag_engine.extract`) 환경을 허용 목록(`:228-231`)으로만 만든다. 목록에 **`LV_OCR_FALLBACK_ENGINE`·`LV_OCR_FALLBACK_MODE`가 없다.**
2. **부모·자식 판단 불일치.** 부모는 `:737-743`에서 두 변수를 읽어 "폴백이 켜져 있으니 저품질 쪽 재처리"를 결정한다. 실제 OCR을 하는 자식은 `packages/rag_engine/extract.py:112-115` → `packages/document_engine/ocr.py:882-896` `get_ocr_adapter()`에서 `LV_OCR_FALLBACK_ENGINE`이 없어 `"none"` → **폴백 없는 `TesseractOCRAdapter`**를 만든다. 같은 엔진으로 다시 읽으니 결과가 같다.
3. **재시도 봉쇄.** 재처리 뒤 `:934`에 `low_quality_reprocess_version = OCR_REPROCESS_VERSION`(`:22`, `tk231-rapidocr-preproc-v1`)이 기록되고 `:753`이 같은 판이면 다시 시도하지 않는다. 고쳐 배포해도 판을 올리지 않으면 이미 시도한 파일은 다시 재처리되지 않는다.
4. **복구 집계 누락.** `:916-917`은 전후 저품질 쪽수를 `ocr_low_quality_pages`로만 센다. TK-237 이후 시도했으나 빈 OCR 쪽은 `unread_pages_by_cause["OCR_LOW_QUALITY"]`에 들어가므로(`extract.py:402-405`), 이 집계는 그 쪽들을 놓쳐 복구·잔여를 틀리게 셀 수 있다.

재현: 평가 측 사본에서 부모 환경에 `LV_OCR_FALLBACK_ENGINE=rapidocr`·`LV_OCR_FALLBACK_MODE=auto`를 두고 `isolated_extract()`가 만드는 자식 환경을 가로채 `get_ocr_adapter()`를 실행 → 배포 코드는 `TesseractOCRAdapter`, 수정 사본은 `CompositeOCRAdapter(…, RapidOCRAdapter)`.

## 3. 고칠 것

1. `isolated_extract()` 허용 목록에 `LV_OCR_FALLBACK_ENGINE`·`LV_OCR_FALLBACK_MODE`를 추가한다. **허용 목록 방식은 유지**(전체 환경 전달 금지 — 비밀 값 차단 목적). 폴백 엔진 모델 위치 등 그 엔진이 읽는 설정 변수가 더 있으면 같은 이유로 함께 넣고 PR 본문에 목록을 적는다.
2. 부모의 재처리 판단과 자식 어댑터 구성이 **같은 출처**를 쓰도록 한다(예: 부모가 판단에 쓴 값을 자식에 명시 전달하거나, 공용 함수로 둘 다 계산). 다시 어긋나면 시험이 실패해야 한다.
3. `OCR_REPROCESS_VERSION`을 올린다(예: `tk245-fallback-env-v2`). 배포 뒤 이미 v1로 기록된 파일이 **한 번** 다시 재처리된다. 그 뒤에는 반복되지 않는다(TK-237 수용 기준 2항과 같은 성질).
4. 복구 집계는 `ocr_low_quality_pages ∪ unread_pages_by_cause["OCR_LOW_QUALITY"]`(쪽 번호 합집합)로 전후를 센다.
5. 매니페스트 `reference_library`에 재처리 시 자식의 OCR 구성(폴백 엔진·모드)과 `ocr_fallback_attempted_pages`를 남긴다. 폴백이 켜졌다고 판단했는데 시도 0이면 사유를 기록한다.
