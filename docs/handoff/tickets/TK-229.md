# TK-229 · P2 · 로컬 모델의 설정·라우팅 활성화 (`I-4`)

- **우선순위:** `P2`
- **선행 조건:** 없음 (단, `LOCAL_ONLY` 전용 평가 프로젝트 짝 비교 필수)
- **근거:** [0.25.0 온라인 평가 판정서](../../scorecards/online_0250_20261122.md) · [결함 요청 I-4](../online/0250_20261122/issues.md)
- **대상 모듈:** `config/providers.json`, `packages/common/config.py`, `packages/llm_client/`(또는 모델 라우터), `apps/api/capabilities.py`

## 1. 관찰된 현상 및 사용자 영향
- `config/providers.json`의 로컬 공급자가 `enabled=false`이며 고정 `localhost` 주소로 돼 있어 운영 환경에서 안전하게 설정·호출할 수 없다(운영 `/api/diagnostics` 로컬 공급자 `0`개, 호출 `0`건).

## 2. 정량 수용 기준
1. **운영 안전 설정 및 연결 검증:** `config/providers.json` 및 환경 설정으로 운영 환경에서 로컬 추론 서버 엔드포인트·서버 인증·모델명을 안전하게 설정하고 실제 연결 확인·응답 형식(JSON Schema) 검증·실패 시 처리·호출 기록을 수행한다.
2. **실호출 기반 검증:** 공급자 등록 표시만으로 완료 처리하지 않고 실제 호출 건수·토큰/지연시간·오류율을 기록한다.
3. **`LOCAL_ONLY` 짝 비교 및 교차검토 영향 평가:** 전용 평가 프로젝트의 `LOCAL_ONLY` 조건으로 기존 클라우드 모델 경로와 짝 비교를 수행하며, 단일 로컬 모델 사용 시 독립 모델 교차검토가 줄어드는 영향을 함께 기록한다.
4. **효과 서술 원칙:** 개인정보 외부 전송 감소·비용·가용성 개선은 가능한 효과로 기록하되, 법률 판단 정확도와 속도 향상은 실제 측정 전까지 주장하지 않는다.

## 3. 불변식 및 재검증 방법
- **불변식:** 클라우드 자동 대체된 실행을 로컬 모델 성공으로 집계하지 않으며, 비밀값/개인정보 미노출, 입력 문서 지시문 탐지(`INJ-1`), 고정/은퇴 세트 회귀 `0`을 유지한다.
- **오프라인·온라인 재검증:** 로컬 엔드포인트 설정·인증·응답 스키마 검증·실패 폴백/차단 양성 3건·대조 3건 단위 시험, 배포 후 전용 평가 프로젝트 `LOCAL_ONLY` 실측(신규 지표는 기존 `dev`/`holdout` 상승에 합산하지 않음).
