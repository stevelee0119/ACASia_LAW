# TK-237 · P1 · Drive 미완독 쪽의 사유 미기록으로 TK-231 재처리 트리거가 영구 미발동

- **우선순위:** `P1`
- **근거:** [0.29.0 운영 온라인 실측 판정서](../../scorecards/online_0290_20261126.md) 2절 4항 · 선행 [TK-231](TK-231.md)(0.27.0 병합, 운영 효과 미확인)
- **대상 모듈:** `packages/rag_engine/library.py`
- **작성자:** `Agent: evaluator` / **담당자:** `Agent: implementer`

## 1. 문제 현상
운영 `0.29.0`(`9c63772f`) 3회 실행 모두 Drive 참고자료가 `files_seen 41 / files_indexed 41 / files_reused 41`로 **전량 캐시 재사용**이고, 쪽 집계는 `총 8,823 / 완독 8,807`로 **미완독 16쪽이 0.26.0 관측값과 동일하게 유지**된다. `TK-231`이 추가한 선택 재색인은 한 번도 발동하지 않았다.

## 2. 재현으로 확인한 원인 (평가 측 재현, SHA `9c63772f`)
운영 `run_manifest.reference_library.sources`의 41개 자료를 전수 조사한 결과:

| 확인 항목 | 결과 |
|---|---|
| `ocr_low_quality_pages` 보유 자료 | **0 / 41** |
| `unread_pages`·`unread_pages_by_cause`·`incomplete_pages`·`no_text_pages`·`unprocessed_pages`·`retryable_unread_pages`·`confirmed_unreadable_pages`·`execution_incomplete_pages`·`content_unreadable_pages`·`page_state_counts` 보유 자료 | 각 **0 / 41** |
| `low_quality_reprocess_version` 보유 자료 | **0 / 41** |
| `searchable_pages`·`searchable_pages_delta` 보유 자료 | 각 **0 / 41** |
| 미완독 자료 | 7건, 합계 **16쪽**(각 1~4쪽) |

미완독 7건은 쪽 카운터만 어긋나 있고(예: `pages=178, read_pages=177, extracted_text_pages=177, completed_pages=176`) **사유 필드가 하나도 없다.**

`library.py:936~945`의 매니페스트 투영은 이 키들을 `if parsed.get(key)`로 **값이 있을 때만** 싣는다. 따라서 41건 전부에서 누락된 것은 투영 누락이 아니라 **캐시 메타 자체에 사유가 기록되지 않았다**는 뜻이다. 그 결과:

- `_needs_low_quality_ocr_reprocess()`(`library.py:582-588`)는 첫 줄 `low_pages = p.get("ocr_low_quality_pages") or []`가 항상 빈 리스트여서 **무조건 `False`** 를 돌려준다.
- `_has_retryable_unread()`·`_needs_unreadable_confirmation()`(같은 블록) 역시 사유 필드에 의존하므로 발동하지 않는다.
- 그래서 `retry_reason`이 끝까지 `None`이고 `row`가 살아남아 `files_reused += 1`로 끝난다(`library.py:604-607`).

즉 `TK-231`이 만든 자동 감지는 **감지할 입력이 없어 구조적으로 영구 미발동**이다. `auto_reprocess` 자체는 참이다(운영 `/api/diagnostics`의 `ocr_fallback.engine=rapidocr`, `mode=auto`이므로 `library.py:573-579` 조건 충족).

## 3. 고칠 것 (알고리즘·구조 수준, 구현 선택은 담당자)
1. **미완독 쪽의 사유를 캐시 메타에 기록한다.** 쪽 카운터(`pages`/`read_pages`/`extracted_text_pages`/`completed_pages`)가 어긋나면 그 차이를 사유별로 분해해 남긴다(최소: 열지 못한 쪽 / 읽었으나 본문 추출 실패 / 저품질 OCR / 빈 쪽 확인 / 설정 차단). 분해 합이 `pages - completed_pages`와 일치해야 한다.
2. **재처리 트리거를 사유 집합 기준으로 바꾼다.** `ocr_low_quality_pages` 한 가지에만 걸지 않고, 1항의 사유 가운데 재시도 가치가 있는 것(저품질 OCR·추출 실패·열기 실패)을 포괄한다. 빈 쪽 확인·설정 차단은 재시도 대상에서 제외한다.
3. **사유를 알 수 없는 기존 캐시의 이행 경로를 둔다.** 사유 필드가 없고 카운터만 어긋난 레거시 항목을 한 번은 재평가해 사유를 채운다(재평가 1회 표시를 남겨 매 실행 반복을 막는다).
4. **관측을 노출한다.** `low_quality_pages_before/after`·`reprocessed_pages`·`recovered_pages`·`searchable_pages_delta`와 사유별 미완독 쪽수를 `run_manifest.reference_library`에 싣는다(`TK-231` 수용 기준 2항이 요구했으나 운영 매니페스트에 나타나지 않는다).

## 4. 정량 수용 기준
- [ ] 운영과 같은 조건의 시험에서 미완독 쪽이 있는 자료는 **사유별 분해 합 = `pages - completed_pages`** 로 기록된다.
- [ ] 사유 필드가 없는 레거시 캐시 항목에 대해 재평가가 **1회** 수행되고, 그 뒤에는 반복되지 않는다.
- [ ] 재처리 대상 자료만 다시 열고 **나머지는 캐시 재사용**이다(전체 재다운로드 금지: 41건 중 재처리 대상만 `reused=false`).
- [ ] 복구 기준(최소 글자 수·신뢰도)을 넘지 못한 쪽을 `완독`·`OCR_EXTRACTED`로 둔갑시키지 않는다.
- [ ] 양성 3건(저품질 OCR 쪽 복구 / 추출 실패 쪽 재시도 / 사유 없는 레거시 항목 1회 재평가)·대조 3건(완독 자료 비재처리 / 확인된 빈 쪽 비재시도 / 설정 차단 쪽 비재시도) 단위 시험.
- [ ] 고정·은퇴 세트 회귀 0, 확인 오탐·A등급 오탐 0, `Docker OCR readiness` 통과, CodeQL 새 경고 0.

## 5. 제약·불변식
- Drive 파일 식별자·개인정보를 저장소 산출물에 남기지 않는다.
- 참고자료는 기준 자료 역할이며 입력 문서 탐지와 섞지 않는다.
- 전체 재색인으로 문제를 덮지 않는다(동기화 예산 `sync_budget_seconds=300` 초과 금지).

## 6. 평가 측 사전 검증 상태
- **검증한 것:** 운영 매니페스트 전수 조사로 사유 필드 0/41과 미완독 16쪽(7파일) 분포를 확인했고, `library.py:573-607` 조건을 코드로 따라가 트리거 미발동 경로를 특정했다.
- **미검증:** 수정안을 적용한 재처리 결과(복구 쪽수)는 Drive 접근이 필요해 평가 측 임시 사본에서 재지 못했다. 구현 측 PR 제출 후 운영 재측정으로 확인한다.
