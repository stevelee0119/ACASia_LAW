# TK-227 · P2 · 한국어 OCR 폴백의 운영 활성화 (`I-3`)

- **우선순위:** `P2`
- **선행 조건:** 없음(단독 배포 가능, 단 Render 메모리·기동 시간 한계 확인 필수)
- **근거:** [0.25.0 온라인 평가 판정서](../../scorecards/online_0250_20261122.md) · [결함 요청 I-3](../online/0250_20261122/issues.md)
- **대상 모듈:** `requirements.in`, `requirements.txt`, `requirements-test.txt`, `docker/`, `packages/document_engine/ocr.py`, `packages/common/config.py`, `apps/api/capabilities.py`

## 1. 관찰된 현상 및 사용자 영향
- 0.25.0 운영(`023fc33c`)에서 정상 스캔(신뢰도 `0.89`)은 1차 Tesseract가 채택됐으나, 저품질 스캔(신뢰도 `0.611`)은 `FALLBACK_NOT_CONFIGURED`로 폴백 시도·채택이 `0`건이며 `/api/diagnostics`도 엔진 `none`·사용 불가를 보고한다.
- Render Docker 이미지에 `paddleocr`·`rapidocr` 실행 의존성이 포함되지 않아 환경변수만으로 사용할 수 없으며, `LV_OCR_FALLBACK_MODE`가 현재 실제 실행을 제어하지 못한다.
- Drive 저품질 미독 `16쪽` 등 저품질 스캔의 본문 복구 경로가 운영에서 동작하지 않는다.

## 2. 정량 수용 기준
1. **의존성·이미지 고정:** 한국어 인식 성능을 확인한 폴백 OCR 엔진 1종을 선정해 `requirements.in`, 해시 고정된 `requirements.txt`·`requirements-test.txt`, Docker 이미지에 반영한다(환경변수 추가 또는 Render 셸 일회성 설치는 완료로 인정하지 않음).
2. **제어·진단 일치:** `LV_OCR_FALLBACK_MODE`가 실제 폴백 실행 여부를 제어하고, `/api/diagnostics` 및 배포 이미지(`Docker OCR readiness`)에서 선택 엔진 가용 상태가 정확히 보고된다.
3. **Render 자원 한계 확인:** Docker 빌드·무네트워크 OCR 기동·Render 메모리 및 기동 시간 한계를 시험 기록으로 남긴다(한계 초과 시 별도 OCR 서비스 분리 방안 비교 포함).
4. **전후 비교 기준:** 정상 스캔(`0.89`)은 기존 1차 OCR을 유지(불필요 폴백·재처리 `0`건)하고, 저품질 대조 쪽(`0.611`)에서만 폴백을 시도·채택해 읽을 수 있는 본문/쪽 수 및 인식 정확도가 개선된다. Drive 저품질 `16쪽`은 교체/재색인 전후를 별도 계측한다.

## 3. 불변식 및 재검증 방법
- **불변식:** 고정 `dev 83.9`·`holdout 83.3`·은퇴 5세트 회귀 `0`·확인/A등급 오탐 `0`·네트워크 차단 `Docker OCR readiness` 통과. (고정 `dev`/`holdout` 점수 상승으로 합산하지 않음)
- **오프라인·온라인 재검증:** 정상 스캔 대조 3건·저품질 스캔 양성 3건 단위 시험, Docker 무네트워크 OCR 검증, 배포 후 동일 `clean_scanned.pdf`/`low_quality_scanned.pdf` 재측정.

## 4. 구현 설계 요약 (구현 에이전트 작성)
- `requirements.in`, `requirements.txt`, `requirements-test.txt`에 `rapidocr>=3.0,<4`와 `onnxruntime>=1.18`을 해시 고정으로 반영하였다(`uv pip compile --generate-hashes`).
- `docker/Dockerfile` 빌드 단계에서 `RapidOCR(Rec.lang_type=LangRec.KOREAN, Rec.ocr_version=OCRVersion.PPOCRV5, Rec.model_type=ModelType.MOBILE)`로 한국어 ONNX 모델(`korean_PP-OCRv5_rec_mobile.onnx`, ~12.86MB)을 사전 내려받아 무네트워크 기동(`check_ocr_runtime`)을 보장하고, 기본 환경변수 `LV_OCR_FALLBACK_ENGINE=rapidocr`, `LV_OCR_FALLBACK_MODE=auto`를 설정하였다.
- `packages/document_engine/ocr.py`의 `RapidOCRAdapter`를 지연 초기화(`lazy=True`, 서버 기동 시 추가 메모리 0MB·0.53s 내 로드) 및 한국어 PP-OCRv5 모바일 모델 지원으로 보강하고, `CompositeOCRAdapter`·`get_ocr_adapter()`가 `LV_OCR_FALLBACK_MODE`(`off`/`auto`/`shadow`/`force`)를 실제로 제어하도록 구현하였다.
- `packages/verification_engine/environment.py`에서 `LV_OCR_FALLBACK_MODE=off`일 때 `DISABLED_BY_MODE`를 정확히 보고하도록 보강하였다.
- `tests/unit/test_tk227_ocr_fallback_activation.py`에 양성 3건(지연 초기화·한국어 인식, 저품질 스캔 폴백 채택, 진단 가용 보고)과 대조 3건(정상 스캔 폴백 미시도, `off` 모드 차단, `shadow` 모드 미채택) 단위 시험을 추가하였다.
- **Render 자원 한계 실측 기록:** `rapidocr` v3 + `korean_PP-OCRv5_rec_mobile.onnx`(12.86MB) 지연 로딩 기준 기동 오버헤드 0ms, 첫 폴백 초기화 0.53s, 최대 RSS 563.4MB(Tesseract 1차 정상 스캔에서는 ONNX 세션 미로드). 512MB 무료/소형 플랜에서는 동시 OCR 시 OOM 위험이 있으므로 Render Starter(512MB) 초과 환경(Standard 2GB 이상) 또는 필요 시 별도 OCR 워커/서비스 분리를 권장한다.
