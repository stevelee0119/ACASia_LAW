## 2. 원인과 고칠 것
1. **원인**: `packages/llm_router/providers.py:275-276` `AnthropicProvider.generate.body`는 캐시를 켜면 최상위 `cache_control`(자동 캐시)을 보낸다.
   - 자동 캐시는 마지막 블록, 즉 매번 바뀌는 사용자 입력에 캐시 지점을 둔다. 그래서 쓰기 할증(1.25배)만 생기고 읽기는 생기지 않는다.
   - 캐시 읽기는 앞선 요청이 캐시 지점을 둔 위치에서만 일어난다. 공식 문서: https://platform.claude.com/docs/en/build-with-claude/prompt-caching
   - 운영 기록상 Sonnet 호출 전부 `cache_read_tokens=0`이다. 플래그 `LV_LLM_PROMPT_CACHING`도 꺼져 있다(`packages/common/config.py:171`).
2. **고칠 것**: `llm_prompt_caching`이 켜져 있고 `request.system`이 비어 있지 않을 때만 다음처럼 보낸다.
   - `payload["system"] = [{"type": "text", "text": request.system, "cache_control": {"type": "ephemeral"}}]`
   - 최상위 `cache_control`은 보내지 않는다. 지시문이 비었거나 캐시가 꺼져 있으면 지금처럼 문자열로 보낸다.
   - 사용량을 읽는 부분(`:304-309`)과 원장 예약(`budget.py:258` cache_write 단가)은 이미 맞으므로 바꾸지 않는다.
3. **`config/pricing.json`에 단가를 추가한다.** Haiku 실측 전에 필요하다. 없으면 공급자 단가($3/$15)로 계산돼 비용이 약 30배로 잡히고, 주장 대조 예산($1)이 곧바로 COST로 멈춘다.
   - 추가할 항목: `"claude-haiku-5-5": {"input": 0.1, "output": 0.5, "cache_read": 0.01, "cache_write": 0.125}`
   - 근거: https://platform.claude.com/docs/en/about-claude/pricing (10만 토큰 이하 $0.10/$0.50, 캐시 읽기 0.1배, 5분 쓰기 1.25배. RAG 요청은 약 8천 토큰)
   - 모델 배정(`config/llm_routing.json`)은 바꾸지 않는다.
4. **운영 설정(사용자)**: 배포 뒤 Render에 `LV_LLM_PROMPT_CACHING=1`을 설정한다. 처리 대기 작업이 없을 때 바꾼다. 실행 설정 스냅샷에 들어가는 값이라 대기 중인 작업은 `EXECUTION_SETTINGS_CHANGED`로 다시 시도하게 된다(`apps/worker/runtime.py:189-196`).
5. **시험**: 평가 측 패치 [`TK-254_255_tests.patch`](TK-254_255_tests.patch)(sha256 앞 12자리 `22d5a1f6bb69`)를 그대로 적용한다.
