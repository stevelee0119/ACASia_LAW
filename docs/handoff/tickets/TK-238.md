# TK-238 · P2 · `next_gen_feature_diagnostics()`의 `actual_calls` 상수 0 — 실호출 집계 누락(RAG·OCR 폴백 공통)

- **우선순위:** `P2`
- **근거:** [0.29.0 운영 온라인 실측 판정서](../../scorecards/online_0290_20261126.md) 2절 3항 · 선행 [TK-232](TK-232.md) 수용 기준 3항(`configured`/`effective`/`actual` 3중 일치)
- **대상 모듈:** `packages/verification_engine/environment.py`
- **작성자:** `Agent: evaluator` / **담당자:** `Agent: implementer`

## 1. 문제 현상
운영 `0.29.0`(`9c63772f`)의 `run_manifest.rag_retrieval_diagnostics`와 `/api/diagnostics`는 3회 실행 모두 `effective_mode=HYBRID`·`dense_enabled=true`·`reranker_enabled=true`·**`actual_calls=0`** 을 보고한다. 같은 보고서의 문서 단위 기록은 이와 다르다:

| 실행 | 문서 단위 `search_diagnostics.retrieval` | 매니페스트 `actual_calls` |
|---|---|---|
| `m1` | `effective_mode=HYBRID_RERANK`, `embedding_requests=1/successes=1`, `reranker_requests=1/successes=1`, `cache_hits=9` | 0 |
| `m2` | 같음 | 0 |
| `m3` | 같음 | 0 |
| 다문서 실행 | 3문서 중 1문서 `HYBRID_RERANK`(`emb 1/1`, `rer 1/1`), 2문서 `LEXICAL_ONLY`(`emb 0/0`) | 0 |

**Dense 임베딩과 재순위는 실제로 작동했다**(`TK-232`의 상용 API 임베딩 실전화는 운영에서 확인됨). 문제는 집계다.

## 2. 재현으로 확인한 원인
`packages/verification_engine/environment.py`의 `next_gen_feature_diagnostics()`가 반환 딕셔너리에 값을 **상수로 박아** 둔다.

- `environment.py:230` — `"actual_calls": 0`  (rag)
- `environment.py:241` — `"actual_calls": 0`  (ocr_fallback)

이 함수는 설정·가용성만 보고 만드는 **실행 전 스냅샷**이며, 실행 중 누적된 호출 수를 되받아 채우는 경로가 없다. 전 저장소에서 `actual_calls`를 쓰는 곳은 이 두 줄뿐이다(제품 코드 기준). 따라서 어떤 실행에서도 두 값은 0이고, `TK-232` 수용 기준 3항의 '3중 일치'는 `configured`/`effective` 2개만 충족한 상태다. 같은 성격의 결함이 OCR 폴백에도 있으므로 **두 축을 같은 회차에서 함께 고친다**(2026-11-13 사용자 지시).

## 3. 고칠 것
1. 실행이 끝난 뒤 문서 단위 `search_diagnostics.retrieval`의 `embedding_requests`·`embedding_successes`·`embedding_failures`·`reranker_requests`(및 OCR 폴백의 시도·채택·거부)를 **run 단위로 합산해** 매니페스트·진단에 싣는다.
2. 값이 아직 없는 시점(요청 직후 `/api/diagnostics` 같은 실행 전 조회)에는 0이 아니라 **'미집계'임이 드러나는 표현**을 쓴다(예: `null` 또는 `measured: false`). 실행 전 0과 실행 후 실제 0을 구분할 수 있어야 한다.
3. `effective_mode`가 `HYBRID`인데 합산 호출이 0인 실행은 **그 사실을 `fallback_reason`에 남긴다**(문서별로 관련 참고자료가 선택되지 않아 Dense를 쓰지 않은 경우가 실제로 있다 — 다문서 실행의 2문서가 그 예다. 이것은 결함이 아니므로 사유로 구분해 적는다).

## 4. 정량 수용 기준
- [ ] Dense 1회 이상 호출된 실행의 매니페스트 `actual_calls`가 **문서 단위 합산값과 일치**한다(합산 불일치 0).
- [ ] 실행 전 조회에서 `actual_calls`가 '미집계'로 구분되고, 실행 후 실제 0과 혼동되지 않는다.
- [ ] `lexical_only`/`off`/네트워크 비허용 조건에서 `configured`=`effective`=`LEXICAL_ONLY`·합산 0·`fallback_reason` 기재가 함께 성립한다(`TK-232` 기존 계약 유지).
- [ ] OCR 폴백 `actual_calls`도 같은 기준으로 집계된다(시도·채택·거부 구분).
- [ ] 양성 3건(Dense 호출 합산 / OCR 폴백 채택 합산 / 다문서 부분 사용 합산)·대조 3건(`lexical_only` 0건 / 네트워크 비허용 0건 / 실행 전 미집계) 단위 시험.
- [ ] 고정·은퇴 세트 회귀 0, 확인 오탐·A등급 오탐 0, CodeQL 새 경고 0.
