# TK-225 · P1 (Regression) · RAG 검색 제한 초과(`OperationalError: interrupted`)로 문서 대조 전체 중단 방지

- **우선순위:** `P1` (`regression`, 차기 릴리스 필수 해소)
- **근거:** [0.25.0 온라인 평가 판정서](../../scorecards/online_0250_20261122.md) · [결함 요청 I-1](../online/0250_20261122/issues.md)
- **대상 모듈:** `packages/rag_engine/library.py`, `packages/verification_engine/pipeline.py`

## 1. 문제 현상
- 0.25.0 운영 배포(`023fc33c`)에서 동일 `case9`·동일 Drive 스냅샷(`41/41`)을 4회 실행한 결과, 2회의 `reference_review`가 약 5.1초에 `sqlite3.OperationalError: interrupted`로 중단되어 표준 `21/23`(`RAG-1`·`RAG-2` 실패), RAG 대조 `3/5`, 건강 `5/6`(`H-ENGINE` 실패)으로 하락했다.

## 2. 정량 수용 기준 및 불변식
1. **예외 전파 차단 및 복원력:** SQLite 조회의 progress handler 제한(3s/5s) 초과 시 문서 RAG 단계 전체가 실패 예외로 빠지지 않도록 조회 범위 축소/재시도 또는 부분 완료 처리한다.
2. **관측성:** 제한 초과 시 조회 종류, 소요 시간, 후보 건수, 재시도/미완료 사유를 개인정보·원문 없이 진단/건강 기록과 화면/보고서에 남긴다.
3. **불변식:** 입력 문서의 지시문 탐지(`INJ-1`), `H-ENGINE` 실패 투명 노출(진짜 실패를 녹색으로 숨기지 않음), 고정/은퇴 세트 회귀 0·오탐 0을 유지한다.
4. **시험:** 타임아웃/interrupted 모의 환경에서 부분 복구·사유 기록을 검증하는 단위 시험(양성 3건·대조 3건 이상)을 포함한다.

## 3. 부분 구현·잔여 이월 금지
- 예외를 단순히 삼켜 거짓 성공(녹색)으로 바꾸는 우회를 금지하며, 타임아웃 진단 필드·부분 결과·재시도 경로를 한 PR에 완결한다.

## 4. 구현 설계 요약 (구현 에이전트 작성)
- **선택한 아키텍처/모듈(How)**:
  1. `packages/rag_engine/library.py`: `select()`(5s 핸들러)와 `search_claim()`(3s 핸들러)에서 `OperationalError: interrupted` 발생 시 전체 중단 대신 구간별(`term_frequency`, `main_fts`, `window_fts`, `priority_fts`, `claim_fts`, `claim_stem_scan`, `claim_hybrid_scan`)로 축소 범위 재시도(예: `present[:40]`/`q_tokens[:16]`) 또는 부분 결과 보존 후 `search_diagnostics`(`query_kind`, `ms`, `candidate_chunks`/`candidate_count`, `interrupted`, `interrupted_phases`, `retried_queries`, `partial_results`, `incomplete_reason`)를 기록하고, 비-interrupted SQLite 오류는 그대로 재전파한다.
  2. `packages/rag_engine/review.py` 및 `packages/verification_engine/pipeline.py`: `review_document()`가 `document_select`·`claim_search` 진단을 `review["search_diagnostics"]`로 집계하고, 중단 시 `search_interrupted=True`·`incomplete_reason="SQLITE_QUERY_INTERRUPTED"`를 전파하며, 빈 중단 결과가 `NOT_RELEVANT`(거짓 녹색)로 숨겨지지 않도록 `UNVERIFIED` 및 `unverified_items`로 투명하게 노출한다.
