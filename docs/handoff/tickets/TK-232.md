# TK-232 · P1 · 미운영 코드(로컬 LLM·별도 Reranker 서버) 삭제, 진단 정합화 및 상용 API 임베딩 연결

- **우선순위:** `P1` (트랙 1 — 불필요 코드 삭제 & 핵심 RAG 실전화)
- **근거:** [0.26.0 온라인 평가 판정서](../../scorecards/online_0260_20261122.md) · [후속 관찰 2·3항](../online/0260_20261122/issues.md) · 사용자 지시(2026-11-22 "불필요한 코드는 삭제, 핵심 기능은 실전화")
- **대상 모듈:** `config/providers.json`, `packages/llm_router/providers.py`, `packages/rag_engine/hybrid_retriever.py`, `packages/rag_engine/library.py`, `packages/verification_engine/environment.py`, `apps/api/capabilities.py`

## 1. 관찰된 현상 및 문제점
1. **진단 표시 불일치:** 운영에서 `LV_RAG_RETRIEVAL_MODE=lexical_only`로 설정했음에도 `/api/diagnostics`에 `configured_mode=HYBRID`, `reranker_enabled=true`로 잘못 표시되었다.
2. **운영 실체 없는 죽은 코드 누적:**
   -Render 운영 환경에는 자체 로컬 LLM 추론 서버(`localhost:11434` 등)나 별도 자체 호스팅 임베딩·Reranker 서버가 존재하지 않아 해당 코드가 영구 미측정(`NOT_MEASURED`, 호출 `0건`) 상태로 남아 코드·진단 복잡도만 높이고 있다.
   - 반면 운영 환경에는 이미 `OPENAI_API_KEY`·`GEMINI_API_KEY`가 설정되어 있으므로, 별도 서버 없이 기존 상용 임베딩 API(OpenAI/Gemini)를 선택적으로 재사용하면 즉시 Dense 검색 실전화가 가능하다.

## 2. 정량 수용 기준 및 불변식
1. **불필요한 미운영 코드 삭제 (Code Diet):**
   - `config/providers.json`에서 미사용 비활성 로컬 공급자(`local_ollama` 등) 항목을 제거하고, `packages/llm_router/providers.py`·`packages/common/config.py`·`capabilities.py`에서 죽은 로컬 LLM 전용 헬스체크/라우팅 분기를 정리한다(기존 단위 시험 수정/정리 시 `approved_test_marks.json` 보호 시험은 건드리지 않고, 로컬 LLM 전용 단위 시험은 정리된 계약에 맞게 갱신).
   - `packages/rag_engine/hybrid_retriever.py`에서 운영 서버가 없는 별도 `HttpRerankerAdapter`(`LV_RAG_RERANKER_ENDPOINT` 원격 호출)를 제거하고, 재순위는 인프로세스 결정론적 법적 적용성·식별자·어휘 정합 재순위(`DeterministicLegalReranker` 또는 내장 스코어러)로 단일화한다.
   - `Source 카세트` 모드는 오프라인 평가 전용임을 진단에 명시하고, 운영 기본(`LIVE`)에서 불필요한 경고/혼선을 유발하지 않도록 정리한다.
2. **Dense 임베딩의 상용 API 실전화 (`hybrid_retriever.py`, `library.py`):**
   - 별도 임베딩 서버 URL(`LV_RAG_EMBEDDING_ENDPOINT`) 없이도, `LV_RAG_RETRIEVAL_MODE=hybrid`(또는 `auto`에서 상용 임베딩 활성 시)이고 `OPENAI_API_KEY` 또는 `GEMINI_API_KEY`가 존재하면 상용 임베딩 API(예: OpenAI `text-embedding-3-small` 또는 Gemini embedding)로 청크 리비전 캐시 임베딩을 생성·재사용할 수 있도록 연결한다.
   - `LV_RAG_RETRIEVAL_MODE=lexical_only`(또는 `off`, 네트워크 비허용, API 실패)일 때는 즉시 요청 `0건`으로 `LEXICAL_ONLY`가 되며 안전하게 어휘 검색으로 동작한다.
3. **`/api/diagnostics` 및 `run_manifest` 정합화 (`capabilities.py`, `environment.py`):**
   - `LV_RAG_RETRIEVAL_MODE=lexical_only`/`off` 설정 시 `configured_mode`와 `effective_mode`가 모두 `LEXICAL_ONLY`로, `reranker_enabled`가 실제 유효 상태와 100% 일치하게 보고된다.
4. **불변식 및 시험:**
   - 비밀값(API 키)·개인정보 외부 유출 `0`, Drive 기준 자료 신뢰 역할 및 입력 문서 `INJ-1` 유지, 고정/은퇴 세트 회귀 `0`, CodeQL 경고 `0`.
   - 양성 3건(상용 API 임베딩 캐시 재사용·`lexical_only` 진단 일치·실패 시 `LEXICAL_ONLY` 폴백) 및 대조 3건 단위 시험 포함.

## 3. 부분 구현·잔여 이월 금지
- 죽은 코드 정리, 진단 불일치 수정, 상용 임베딩 API 연결을 한 PR에서 완결한다.

## 4. 구현 설계 요약 (구현 에이전트 작성)
- `config/providers.json`, `packages/common/config.py`, `packages/llm_router/providers.py`, `apps/api/capabilities.py`에서 미운영 로컬 LLM 공급자 설정·환경변수 오버라이드·죽은 `health_check()`/`ollama` 분기·`call_stats`를 제거하고, 보호 회귀 시험 호환용 최소 어댑터만 남겨 기본 비활성(`REMOVED_NOT_OPERATIONAL`)으로 정리하였다.
- `packages/rag_engine/hybrid_retriever.py`에서 원격 `HttpRerankerAdapter`를 제거하고 인프로세스 결정론적 법적 재순위(`DeterministicLegalReranker`)로 단일화했으며, `OPENAI_API_KEY` / `GEMINI_API_KEY`를 재사용하는 `OpenAIEmbeddingAdapter` / `GeminiEmbeddingAdapter`를 추가해 `hybrid`/`auto` 모드에서 청크 리비전 캐시 임베딩을 생성·재사용하도록 연결하였다(`lexical_only`/`off`·실패 시 즉시 요청 0건·`LEXICAL_ONLY` 폴백).
- `packages/verification_engine/environment.py`에서 `LV_RAG_RETRIEVAL_MODE=lexical_only`/`off`일 때 `configured_mode`와 `effective_mode`가 모두 `LEXICAL_ONLY`, `reranker_enabled=False`로 100% 일치하도록 수정하고, `source_cassette`에 `evaluation_only: true`를 명시하였다.
- `tests/unit/test_tk232_code_diet_and_commercial_rag.py`에 양성 3건·대조 3건을 추가하고 기존 단위 시험을 정리된 계약에 맞게 갱신하였다.
