## 1. 문제 현상 및 결함 범주
- **현상**: 운영 저품질 스캔에서 RapidOCR 이중 비교 기록이 `raw_chars 0`·`preprocessed_chars 0`이다. 원본·전처리본 모두 줄이 인식됐는데도(신뢰도 0.582·0.534) 0이다. TK-239 D-1이 요구한 "추출 글자 수 노출"이 운영에서 사실상 빠져 있다.
- **범주**: 관측·기록 결함(`OBSERVABILITY`). 탐지 diff 0.

## 2. 원인 (코드 확인 + 사본 재현, `71a8ffc3` 기준)

1. `packages/document_engine/ocr.py:56-81` `page_quality()`는 `{"lines","confidence","hangul_ratio","low_quality","reasons"}`만 돌려준다. **`chars` 키가 없다.**
2. `RapidOCRAdapter.recognize_image()`의 `:774` `raw_chars = int(q_raw.get("chars") or 0)`, `:805` `pre_chars = int(q_pre.get("chars") or 0)`가 없는 키를 읽어 **항상 0**이 된다.
3. `#436` 시험은 원격 측정 필드가 **있는지**만 보고 값이 0이 아닌지는 보지 않아 이 결함을 통과시켰다.

재현: 평가 측 사본에서 모의 엔진으로 `recognize_image(preprocess=True)`를 부르면 배포 코드는 `raw_chars 0 / preprocessed_chars 0`이다.

## 3. 고칠 것

1. `page_quality()`가 `chars`를 돌려준다. 정의: **잡음 제외 줄(`texts`)의 공백 제거 글자 수 합.** 기존 키·`low_quality` 판정은 바꾸지 않는다.
   ```python
   chars = sum(len("".join((line.text or "").split())) for line in texts)
   return {"lines": len(texts), "chars": chars, "confidence": ..., ...}
   ```
2. `:774`·`:805`는 그대로 둬도 된다(키가 생기면 값이 들어온다). 다른 곳에서 `chars`를 따로 세고 있으면 이 정의로 통일한다.
3. 시험: 원격 측정의 `raw_chars`·`preprocessed_chars`가 **인식한 글자 수와 같음**을 단언한다(존재만 보는 단언 금지). 빈 인식은 0, 잡음 줄만 있으면 0.
