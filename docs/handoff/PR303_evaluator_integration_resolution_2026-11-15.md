# PR #303 평가자 변경 통합 정정

2026-11-15 사용자 요청에 따른 평가자 조치. 이 문서는 기존의 “#311을 Steve에 먼저 병합한 뒤 #303을 갱신한다”는 지시를 대체한다.

## 원인과 해결

- #303의 운영 잠금 파일은 pytest를 제외한다. 기존 score-gate가 운영 파일만 설치하면 수용·회귀 시험을 실행할 수 없다. 전체 CI의 workflow 계약 시험도 이를 거부한다.
- 평가자 PR #311의 해시 강제 설치 명령은 #303의 테스트 잠금 파일과 함께 있어야 한다. 기존 Steve의 비잠금 요구사항 파일과 조합하면 pip의 버전 고정 검사가 실패한다.
- 따라서 두 변경을 서로 다른 순서로 Steve에 먼저 넣으라는 지시는 성립하지 않는다. 평가자 workflow 커밋 `a429e2d07cc54e43ed47927a5fee7bc51fbaf362`와 #303 잠금 파일을 같은 PR에서 검증·병합한다.
- 평가자가 #303 브랜치에 Steve `eff703868a4e2b44bb27657703e0b187481da671`와 #311 평가자 커밋을 일반 병합했다. 제품 코드·잠금 파일은 구현자의 기존 내용을 유지하고, 보호 경로의 원래 평가자 커밋 이력도 보존했다. 결합 병합 커밋: `6ef6c11b0723ec7129d29c7896b96a1cbaf869af`.
- #311 단독 선행 병합은 폐기한다. #303 수용 후 병합하면 workflow와 잠금 파일이 함께 Steve에 들어간다. Steve 선행 변경을 더 기다리지 않는다.

## 구현 에이전트에게 남은 조치

1. 원격 `feat/tk-181-lockfile-runtime-manifest`의 평가자 통합 커밋을 fetch하고 로컬 브랜치를 fast-forward한다. 로컬 미반영 작업이 있으면 보존하고 일반 병합으로 통합한다. 강제 푸시·리베이스로 평가자 커밋을 제거하지 않는다.
2. 새 head SHA의 계약 시험·전체 CI(SQLite/PostgreSQL)·Docker OCR·점수 게이트(수용/회귀 포함)·은퇴 세트 비교·CodeQL·pip-audit 결과를 확인한다. 기존 `0c3f915`의 실패 결과는 현재 head의 결과로 재사용하지 않는다.
3. 검사에 실패하면 실패 로그의 실제 원인을 기준으로 담당 경로만 보완한다. 현재 확인된 workflow/pytest 문제를 이유로 요구사항 잠금을 풀거나 검사 기준을 낮추지 않는다.
4. 모든 검사가 통과하면 추가 구현 없이 재판정·병합 승인 단계로 진행한다. PR 본문의 검증 SHA와 결과를 최종 head에 맞춘다.

## 사전 검증

결합 트리에서 `tests/test_tk181_runtime_manifest.py`와 `tests/test_v5_eval_reliability.py` 18건 통과. 보호 경로 검사는 workflow의 마지막 변경자를 `a429e2d` 평가자 커밋으로 인식했고, 시험 삭제·약화/하드코딩/평가 세트 문구 대조도 통과했다. 전체 CI 결과는 PR의 최신 head에 연결된 실행을 기준으로 판정한다.
