## 사용자 원문
- (10-25) "AI 답변 저장 위치는 브라우저에 저장. 타 사용자와는 AI 검토 내용을 표에 반영한 다음 보고서로 추출하여 공유가 가능할 것으로 예상됨."
- (10-25) "AI 검토내용이 표에 반영된 후 다시 보고서를 생성할때, 그 내용이 보고서 내용에 반영되도록 기능구현을 하면, 보고서가 브라우저 저장된 AI 답변을 담을 수 있지 않을까?"

## 현재(평가 측 코드 확인, `b68e70f`)
- 보고서는 서버가 검증 결과 고정본으로 만든다: `report-workbench.js` 72행이 `POST /projects/{id}/report-jobs`에 `run_id·formats·audience·detail_level`만 보내고, `apps/api/routers/reports.py` `_build_draft`(227행~)가 실행 결과(`run.result_json`)로 고정본(snapshot)을 만든다. 요청 모델 `ReportRequest`(`apps/api/schemas.py` 174행)에 외부 답변 칸이 없다.
- 따라서 TK-128의 브라우저 저장 답변은 지금 구조로는 보고서에 들어가지 않는다.

## 평가 측 검토: 가능
- 보고서 생성 요청에 브라우저의 반영 답변을 함께 보내고(`external_ai_answers: [{code, item_id, verdict, basis, summary, applied_at}]`), 서버가 고정본(snapshot)에 넣어 해시로 묶으면, 이후 확정본·내려받기 모두 같은 내용을 담는다.
- 보고서 각 형식에 '외부 AI 참고 의견(사용자 입력, 공식 확인 아님)' 절을 둔다. 공식 판정·등급·점수에는 쓰지 않는다.

## 설계 시 확인할 것 (사전 검증에서 확정)
1. 입력 검증: 건수·길이 상한, 해당 실행의 item_id만 받기, 문자열만(HTML 해석 없음).
2. 공유용(SHAREABLE) 보고서: 사용자가 붙여넣은 답변에 실명 등이 있을 수 있으므로 기존 개인정보 가림을 적용.
3. 고정본 해시·확정(finalize) 사전 점검과의 일관성.
4. 형식별(pdf·docx·xlsx·csv·json·manifest) 표시 위치와 기존 보고서 시험 충돌.
