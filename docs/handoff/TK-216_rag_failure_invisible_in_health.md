# TK-216 RAG 단계 실패가 파이프라인 건강에 드러나지 않는다

- 발견일: 2026-11-19 (2회차 온라인 점검 PR #347, 운영 측 `issues.md` 1항)
- 종류: **제품 결함.** 건강 판정의 거짓 녹색
- 상태: open — 2026-11-19 사용자 결정 **"(가)"**로 0.23.0에 포함
- 우선순위: 운영 측 P2 → **평가 측 상향**

## 증상

TK75 OFF 3회를 마치고 ON으로 전환해 실행한 첫 ON 실행이 이렇게 끝났다.

| 필드 | 값 |
|---|---|
| `rag_status` | `UNVERIFIED` |
| `rag_reason` | `REFERENCE_REVIEW_FAILED` |
| `rag_error_class` | `OperationalError` |
| 표준 23항목 | **21/23** (`RAG-1`·`RAG-2` 실패) |
| 지지·무관 대조 | 3/5 (`RAGC-S1`·`RAGC-S3` 실패) |
| **`H-ENGINE`** | **통과** |

같은 ON 설정에서 즉시 재실행하면 정상 완료됐다(23/23, 대조 4/5). 두 실행의 참고자료 해시는 같았다.

## 왜 상향하는가

**참고자료 검토가 실패했는데 건강 판정이 녹색이면 사용자가 그것을 알 수 없다.**

이것은 TK-208 1차 판정의 F1과 **같은 종류의 결함**이다. F1은 '내용이 있는 스캔 쪽을 자료 탓으로 적어
`coverage_complete=True` → 라이브러리 `READY` → `H-REF` 통과'였고, 평가 측이 합성 PDF로 재현해 막았다.
여기서는 'RAG 단계가 예외로 죽었는데 `H-ENGINE`이 통과'다. 자리가 다르고 꼴이 같다.

건강 판정의 거짓 녹색은 그 자체로 **모든 온라인 판정의 근거를 흔든다.** 평가 측이 `H-REF`·`H-ENGINE`을
수용 기준으로 쓰고 있기 때문이다.

## 아직 모르는 것

`OperationalError`의 내부 원인과 TK75 전환과의 인과관계는 운영 측 증거로 확정되지 않았다. 추정하지 않는다.
설정 변경 중 시작한 사전 실행 1건이 `EXECUTION_SETTINGS_CHANGED`로 실패한 기록이 있어 전환 시점의 경쟁
상태가 의심되지만, 그 실행은 점검 점수에서 제외된 별건이다.

따라서 할 일은 **둘로 나뉜다.** (1)은 원인과 무관하게 지금 고칠 수 있고, (2)는 원인 확인이 먼저다.

## 할 일

### (1) 건강 판정이 RAG 단계 실패를 반영하게 한다 — 1차 수용 기준

- `rag_status`가 `UNVERIFIED`이거나 `rag_reason`이 `REFERENCE_REVIEW_FAILED`면 `H-ENGINE`이 **불통과**여야 한다.
- 실패 사유와 미검토 범위가 사용자 화면에 드러나야 한다. '검토했으나 근거 없음'과 '검토 자체가 실패'를
  사용자가 구분할 수 있어야 한다.
- 다른 건강 항목의 판정은 바꾸지 않는다. `H-REF`의 현재 동작(TK-208에서 고친 것)을 건드리지 않는다.
- 합성으로 RAG 단계 예외를 일으켜 `H-ENGINE`이 불통과로 바뀌는 것을 시험으로 고정한다.

### (2) `OperationalError`의 자리와 원인

- 서버 측 예외 위치와 로그를 확인한다. DB 세션·연결 풀·작업자 재시작 가운데 무엇인지 가린다.
- 설정 전환(TK75 ON/OFF)과 진행 중인 작업의 경쟁 상태가 있는지 본다.
- 원인이 가려지면 그에 맞는 수정을 올린다. **가려지기 전에 추측으로 고치지 않는다.**

## 수용 기준

1. RAG 단계 실패가 `H-ENGINE` 불통과로 드러난다(합성 시험으로 증명)
2. 사용자 화면에 실패 사유와 미검토 범위가 적힌다
3. `H-REF`를 포함한 다른 건강 항목의 판정이 바뀌지 않는다(기존 시험 통과)
4. `OperationalError`의 자리가 특정되고, 특정된 원인에 대한 수정이거나 '원인 미특정'이 명시된다
5. 건너뛰기·`xfail` 없음, 기존 시험 삭제·약화 없음

## 3회차 온라인 점검에서 확인할 것

RAG 실패를 일으킨 뒤 `H-ENGINE`이 불통과로 바뀌는지. 정상 실행에서는 통과가 유지되는지.
