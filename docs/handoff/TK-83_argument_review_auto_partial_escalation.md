# TK-83 효율 라우팅(auto)에서 법리 검토가 항목 하나만 엇갈려도 세 번째 공급자에 전체를 다시 보낸다 (P3, 효율, 기존 설계)
- 유형: 효율(호출 구성). 탐지·채점 규칙 변경이 아니다. 판정 결과를 바꾸지 않아야 한다.
- 발견: 평가 측, 2026-10-19. TK-79 OFF/ON 온라인 대조(HISTORY 2026-10-19, 같은 입력·`c512462`). 운영은 사용자 결정(10-19)으로 ON(`LV_LLM_EFFICIENT_ROUTING=1`·`LV_LLM_CROSS_CHECK=auto`)이다.
- 근거는 대조 실행 JSON의 호출 집계뿐이다. 원문·항목별 판정은 저장소 밖에 있다.

## 1. 증상
- ON에서도 법리 검토(`argument_review_v1`)가 요청 2건 모두 공급자 3곳을 다 불렀다. Sonnet·gpt-6.1-sol·gemini 각 2건으로 6건이며, OFF와 같다.
  - 설계상 auto는 2곳 응답이 완결되고 엇갈리지 않으면 멈춘다(`packages/llm_router/router.py` 359~375행).
- `routing.conflicting()`은 응답 전체를 `(item_id, validity_verdict)` 묶음 하나로 비교한다(67~78행). 항목이 많으면 한 항목만 엇갈려도 '불일치'가 된다. 그러면 세 번째 공급자에게 **모든 항목**을 다시 보낸다.
- 이번 실행에서 법리 검토 비용은 OFF $0.134 → ON $0.077로 작았다. 다만 주장이 많은 문서에서는 이 호출 수가 함께 커진다.

## 2. 요구 (설계 메모 먼저)
1. 먼저 설계 메모를 낸다. 세 번째 공급자에게 **엇갈린 항목만** 보내는 방식으로, 최종 판정이 지금(세 공급자 전체 응답)과 같아짐을 보여야 한다.
   - 메모에 담을 것: 항목별 다수결·불일치 표시 규칙, 완결성 검사(`complete_argument_reviews`)와의 관계, 실패·잘림 시 처리, 호출 수 예상.
2. 메모가 승인되면 구현한다. OFF(`all`)·`off` 모드의 동작은 바꾸지 않는다.
3. 같은 실행 안에서 항목을 나눠 보내는 것도 입력 마스킹·격리 검사를 똑같이 거쳐야 한다.

## 3. 시험·수용
- 단위 시험으로 다음을 고정한다.
  - 2곳이 모든 항목에 일치하면 2건에서 멈춘다.
  - 1개 항목만 엇갈리면 세 번째 호출에는 그 항목만 담긴다.
  - 최종 항목별 판정이 기존 '세 곳 전체 호출'과 같다.
- 수용 근거는 (다) 사용자 지시 사항 개선(비용)으로 본다. 배포 뒤 같은 문서로 ON 실행을 다시 해, 법리 검토 호출·비용이 줄고 finding이 같은지 평가 측이 확인한다.
