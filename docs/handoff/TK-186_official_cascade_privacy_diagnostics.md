# TK-186 — 공식 Source 인용 검증의 개인정보 전송 차단 정밀 진단

발견: 2026-11-15 · 우선순위 P1 · 유형 existing · 목표0.22.0 · 상태 원인 미확정.

배포 후 실연동43683347281에서 공식 판례 전문을 이용하는 cascade의 세 공급자가 모두 INPUT_PRIVACY_BLOCKED/NOT_SENT로 끝났다. 현재 이번 자동80호출은 성공했지만 해당 Source/질문/소비자 경로를 같은 조건으로 재실행한 결과가 아니므로 해소 근거로 쓰지 않는다. 이전0.20.0 점검은 모델OFF여서 신규/기존 귀속도 미확정이다.

관련 경로: packages/llm_router/router.py의 inspect_request 및 차단 반환, packages/llm_router/privacy.py, cascade_source.py, scripts/live_source_check.py:check_cascade. 현재 요약만으로 직접 개인정보 잔존·마스킹 누락·검사 예외·소비자 증명/스키마 문제를 구분할 수 없다. 근거 없이 지시문 탐지의 실패라고 분류하지 않는다.

다음 조사(평가 측): 실행 기록의 input_privacy에서 안전한 사유 코드/실패 단계/모델 요청 수/보낸 여부만 허용목록으로 수집한다. 원문·개인정보·요청본문·키/쿠키·서버경로는 출력하지 않는다. 공식자료 부분과 입력문서 부분의 마스킹/직렬화/출처증명 단계를 분리해 같은 공개자료·동일 요청으로 사본 재현한다. 검사 예외를 조용히 무시하거나 빈 진단을 성공으로 취급하지 않는다.

해결 기준: 실제 개인정보가 있으면 차단을 유지하며 정확한 마스킹 경로를 고친다. 스키마/소비자 연결 문제라면 그 연결을 고친다. 공식 DB/RAG의 지시문 분류 제외를 개인정보 전송 검사 면제로 확대하거나 입력 문서의 보호를 약화하지 않는다. 원인이 확인되면 최소 사본 패치와 양성3/대조3 이상, 위조 출처/인코딩/숨김/개인정보 잔존 대조를 평가한 뒤 구현 지시를 확정한다.

수용: 같은 공식 Source의 실제 cascade가 정상 호출·근거인용 검증까지 수행되거나, 전송할 수 없는 자료라면 정확한 잔여 사유/조치가 표시된다. 필요한 본문을 무조건 빼고 성공했다고 표시하지 않는다. 실제3공급자 중 참여/생략/오류를 구분하고, 사용자 문서 PII/인젝션 경계 회귀를 보존한다. 원인이 미확정인 현재는 제품 수정 사본이 없으며 0.22.0 완료로 처리하지 않는다.
