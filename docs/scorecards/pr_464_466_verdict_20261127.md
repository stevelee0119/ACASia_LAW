## 1. #465 운영상 제약(사용자 설정 필요, 제품 영향 없음)
- 저장소 설정 `Workflow permissions`에서 GitHub Actions의 PR 생성이 꺼져 있다(PR 본문의 `can_approve_pull_request_reviews=false`). 그래서 `GITHUB_TOKEN`으로는 **새 봇 PR을 만들 수 없다.** `main` 릴리스 병합 뒤 `bot/readme-sync-main` PR을 만들 때 워크플로가 실패(명시 오류)한다.
- GitHub 규칙상 `GITHUB_TOKEN`으로 한 푸시와 PR은 다른 워크플로(필수 CI)를 일으키지 않는다. 그래서 봇이 기존 PR(#464)을 갱신하면 새 머리에 필수 검사가 돌지 않아 병합이 막힐 수 있다. 이것은 GitHub 공식 동작에 근거한 판단이며, 이 저장소에서 실측하지는 않았다(미검증).
- **해소:** `secrets.README_SYNC_TOKEN`(이 저장소의 contents·pull-requests 쓰기 권한만 가진 fine-grained 토큰)을 설정한다. 워크플로가 이미 이 비밀을 우선 사용한다. 설정은 사용자 결정 사항이다.
