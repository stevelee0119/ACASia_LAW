사용자 질문에 대한 답:
- **영어권 벤치마크는 채택할 필요가 없다는 판단에 동의한다.** 이유는 세 가지다.
  - 제품 경로에 들어가지 못한다(추출 0건).
  - 들어가는 구성요소만 떼어 재도 한국법 결론을 뒷받침하지 못한다.
  - 비용·유지 부담만 생기고, '공개 벤치마크 점수'라는 오해를 만든다.
- **'한국권 벤치마크가 별도로 없다'는 전제는 사실과 다르다.** KBL이 있다.
  - 다만 KBL 대부분은 모델의 법률 지식을 묻는 선택형이라 제품(서면 검증 도구)의 성적이 되지 못한다.
  - 제품과 맞닿는 과제는 1개뿐이다.
  - 다른 한국어 법률 데이터셋은 이번에 조사하지 않았다(미검증).

**R2 어댑터 계약**
- 입력: 고정 revision의 statute_content 파일, as_of.
- 처리:
  - 각 선택지 문자열 → 제품 인용 추출기 → `verify_statute(citation, as_of)`.
  - 어댑터는 정답을 읽지 않고 실행한다. 정답은 채점 단계에서만 연다.
- 정규화(명세 고정):
  - 조와 인용문이 공식 원문과 일치 → MATCH
  - 인용문 불일치(CITATION_TEXT_MISMATCH·CONTRADICTED) → MISMATCH
  - 조회 실패·UNVERIFIED → UNKNOWN
  - 추출 0건 → EXTRACTION_FAILED
- 채점:
  - 선택지 단위: MATCH 정밀도, **잘못된 내용에 MATCH(false VERIFIED) 비율**(분모 = 오답 선택지 전체), MISMATCH 재현율.
  - 분모 처리: UNKNOWN·EXTRACTION_FAILED를 분모에 남기고 따로 센다. 성공한 것만 남겨 정확도를 올리지 않는다.
  - 문항 단위: 'MATCH가 정확히 1개이고 그것이 정답' 비율.
  - 불확실성: 문항 단위 부트스트랩 95% 구간. 선택지를 독립 표본으로 세지 않는다.
- 기준시점:
  - 두 as_of에서 정답 선택지가 MATCH가 아니면 '기준시점 변동·정답 의심'으로 따로 보고한다. 분모에서 조용히 빼지 않는다.
- 거절 조건: revision·파일 해시 불일치, 중복·모르는 ID, 제품 SHA·as_of가 섞인 결과.
- 실행 manifest: run_id, product_sha, evaluator_sha, benchmark_revision, file_sha256, task, as_of, network_mode, 조회 횟수, 실패 수, 소요 시간, limitations.

**배치**
- PR 회귀 게이트(결정적·오프라인)는 그대로 둔다.
- KBL 연구는 PR·릴리스 게이트에 연결하지 않는다.
- 온라인 실행 실패는 '측정 미완료'로 남긴다.
