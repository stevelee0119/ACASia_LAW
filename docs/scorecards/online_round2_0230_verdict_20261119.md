## 4. TK-208 — 거짓 녹색은 막혔고, 이어 읽기는 작동하지 않았다

### 충족 (제품 수정이 운영에서 확인됐다)

- 전역 집계 8,823쪽 중 8,807쪽 완료, 실행 미완료 16쪽.

### 평가 측이 코드로 확정한 것과 확정하지 못한 것

확정:

1. OCR 쪽 예산 기본값은 **추출 1회당 5쪽**이다 — `packages/rag_engine/extract.py:186`,
   `LV_REFERENCE_OCR_MAX_PAGES` → `LV_OCR_MAX_PAGES` → `"5"`.
2. 예산 소진 시 이어 읽기 토큰은 **만들어진다** — `extract.py:251-259`가 `next_continuation = {"next_page": …}`를
   세우고 쪽 루프를 끊는다. `OCR_UNAVAILABLE`이 0이고 `BUDGET_EXHAUSTED`가 11인 운영 수치와 맞는다.
3. 다시 읽는 조건은 **`prior["continuation"]`이 참일 때뿐**이다 — `library.py:486-489`. 거짓이면 `row`가 남아
   파일이 통째로 재사용된다(`files_reused`).
4. 저장되는 것은 `parsed` 전체이므로 토큰은 사전 그대로 보존된다 — `library.py:612`.

확정하지 못한 것(**미검증**):

> **1차와 2차 사이에 토큰이 사라진 지점.** 후보는 `library.py:511-514`(저장 revision이 방금 계산한 `version`과
> 다르면 `prior, continuation = None, None`)와 `library.py:569-572`(`resume_failures >= 2`에서 토큰 폐기·캐시 삭제)다.
> 운영 자료로는 가릴 수 없다. **추정으로 지시서를 쓰지 않는다** — 합성 PDF로 2회 동기화를 재현해 가린다.

평가 측 가설 2개가 틀렸음도 기록한다. (가) 저장 payload가 불리언이라 토큰이 유실된다 → 틀렸다(`:612`가 `parsed`를
저장한다). (나) `total > MAX_PAGES` 경로로 토큰 없이 `BUDGET_EXHAUSTED`가 찍힌다 → 틀렸다(`MAX_PAGES = 1500`,
가장 큰 자료 795쪽).

## 5. TK-209 — 끊기는 지점이 모델 관계 판단으로 확정됐다

진단 3단계가 운영에서 제 일을 했다.

| 단계 | 관찰 |
|---|---|
| `excerpt_delivery` | 목표 자료 발췌가 각 실행 주장별 4번 모두 `387/387자`, 오프셋 `0–387`로 전달 |
| `model_responses` | 모델은 응답했으나 목표 자료에 대한 원응답 `SUPPORTS` **0건**(`CONTEXT` 또는 `INSUFFICIENT`) |
| `promotion_attachment` | 최종 목표 지지 의견 0건 |

따라서 **화면에서만 사라진 것이 아니다.** `RAGC-S3`는 OFF 3회 모두 거짓이다.

이 축은 [AGENT_ROLES 2.1](../AGENT_ROLES.md) **`(가)` 모델 판단·외부 자료**에 해당한다 — 규칙으로 풀 수 없고
프롬프트·관계 판정 설계를 바꾸는 일이다. **사용자 범위 결정 대기**로 둔다. 평가 측이 임의로 지시하지 않는다.
