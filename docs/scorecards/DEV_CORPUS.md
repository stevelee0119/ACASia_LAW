등록: 2026-10-17 한국 시각. 사용자 전달문 MSG_TO_CODEX_DEV_CORPUS_20261016.md(작성일10/16)와 check ZIP을 접수했다. **현재 check만 원본 확인·운영본 첫 측정 완료, train은 원본 미수령**이다. 두 부분의 수신·제공·첫 측정과 일반화 격차를 완료했다고 표시하지 않는다.

## 1. 목적과 다른 평가 자료와의 구분

- 개발 말뭉치는 중점6유형(EVI-INCONS·SRC-UNV·EVI-NUM·EVI-FORM·EVI-DATE·EVI-COPY)의 개선과 일반화 격차를 측정한다.
- 고정 비공개 벤치 지문9de8ab2dbe9439c2와 별도다. [FIXED_BENCHMARK4절](FIXED_BENCHMARK.md#4-오염-방지가장-중요)은 그대로 유지한다. 말뭉치는 고정벤치나 매릴리스 새 봉인 세트를 대체하지 않는다.
- check 결과는 **판정 참고 지표**다. 결과의 집계 개선 목표를 개별 구현PR의 비공개 정답 맞추기 조건으로 쓰지 않는다. train에서 유형 원인별로 개선하며 공개 양방향 합성·실제진입점 시험·원래필수 보호를 지킨다.

## 3. 보관·접근·노출 규칙

**두 원본 부분과 측정 출력 폴더는 모두 저장소 밖에 둔다.** 어떤 worktree 안에도 복사하지 않으며 symlink로 반입하지 않는다. Git에는 허용된 집계·지문·환경·판정만 둔다. train 공유용 자료에 check·check문서별결과가 섞이지 않았는지 먼저 확인한다.

### train — 구현용 개발 자료

- 원본 확인·첫 기준 측정 뒤 train만 구현 세션에 제공한다. 현재는 제공 전이다.
- train 문서별 결과에서 원인 유형별 구현 티켓을 만들어도 된다.
- 문서의 문장·사건명·값·정답 토큰을 규칙·설정·시험에 그대로 하드코딩하지 않는다. 문서 키SD-는 기존 하드코딩 점검의 평가자료 표식이다. 일반화한 양성3·대조3 이상의 새 공개 합성 예시를 사용한다.
- 탐지 변경의 공통 제출 점검표5항: 해당유형의 **train 전후 재현율·분모·SHA·동일조건**을 제출한다. train 수신·기준측정·제공 전에는N/A이고, 제공 뒤 적용한다. 시험 삭제/약화·기준선 하향·보호경로 수정은 별도 승인 없이 하지 않는다.

### check — 평가 전용

- 평가 세션만 원본·정답·문서별/항목별 상세를 보관한다. 구현 세션에 열람권이나 로컬 경로를 주지 않는다.
- 저장소·PR·티켓·통합 전달문에는 전체/유형별 집계만 쓴다. **check 문서별 결과로 구현 티켓을 만들지 않는다.** 비공개 실패 문장·값을 역으로 알려 보완시키지 않는다.
- 구현 측에 원본/정답/문서별결과가 노출되면 그 시점에서 해당 지문의 독립 평가 계열을 끊고 새 check를 만든다. 옛 기록은 노출 시점·범위를 표시해 보존한다. 지문을 유지한 채 몰래 정답을 바꾸지 않는다.
- 같은 check를 반복 평가한 집계도 적응적 과적합 위험이 있으므로 개발주기 단위로 해석하고, 새 봉인/고정벤치와 결과를 섞지 않는다.

## 5. 집계 도구와 재현

사용자가 전달한 dev_type_recall.py 참고 스크립트를 검토하고 같은기본집계의 평가측 외부도구를 준비했다. 공통점은 기존 scripts/eval_testset.py의 채점과 credit를 사용하며, 화면에는 집계만 출력한다는 것이다. 원문·문서별결과가 있는stdout/stderr/JSON/Markdown은 평가전용 출력폴더에만 남긴다.

보완점: 빈세트는0점으로성공시키지않고 중단, 새출력폴더와 각묶음 정확히1개의새JSON만 허용해 과거파일을선택하지않음, 입력/출력의모든worktree밖 보관과예상SHA/지문/400항목검증, 각묶음 새프로세스, 실행전후지문검사. 결합유형(`A / B`)은 유형별표에는 각유형으로세되 **전체/중점합계 분모에서는 원래결함행을1회만 센다.** 참고스크립트의분리유형분모합산이 결합유형에서 전체항목을부풀릴수있어 이를구분했다. 이번check에는 전체400/중점240을사용한다.

재현 형식(실제경로는평가전용영역에서설정):

```bash
LV_ALLOW_NETWORK=0 python <저장소밖>/dev_type_recall.py <저장소밖>/dev_20261016/check <저장소밖>/출력/check/새실행폴더 \
  --repo <clean운영SHAworktree> --role check \
  --expected-fingerprint 0c6479fbcad6c753 \
  --expected-sha b68cfeec2c5c168a3b9e6e2e92653ea6892521bf
```

train은별도경로·출력폴더와 `--role train --expected-fingerprint d058b04f03579336`을사용한다. 모델/네트워크는끈다. 도구파일도이번에는저장소밖평가artifact에보관하고 집계기에SHA256을남겼다. 같은도구로이후비교하며 의미를바꾸면새집계버전을명시한다.

도구검증은 이미측정한공개은퇴20261008·20261010 보고서를재집계해99항목/24.75점/재현율.250/오탐3(A3)을확인했다. pipeline을다시돌리지않았다. 추가공개합성 결합유형2행검사에서 전체분모2·재현율.5, 유형별다중라벨을각1회로계산함을확인했다. 이도구검증을 check 정답검증과혼동하지않는다.
