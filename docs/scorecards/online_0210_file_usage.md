# 0.21.0 온라인 시험 파일 저장·사용 안내

이 묶음에는 공개 합성 시험자료만 있습니다. 기존 case9 문서, 사용자 보고서, 정답지, Drive 인증정보는 포함하지 않았습니다. 명세 JSON은 평가 측 채점용이며 사용자가 웹 검증에 업로드할 파일이 아닙니다.

## 1. PC에 내려받아 압축 풀기

acas_021_remaining_testkit.zip을 PC의 문서 폴더 등 접근이 제한된 곳에 저장하고, `AegisLAW_021_test` 폴더에 압축을 풉니다. 경로는 예시이며 다른 폴더여도 됩니다. ZIP 자체를 Drive 참고자료 폴더나 검증 대상에 올리지 않습니다.

| 묶음 안 경로 | 저장/사용 위치 | 용도 |
|---|---|---|
| 01_inputs/input_*.docx | PC 보관 → AegisLAW 검증 대상 문서로 1개씩 업로드 | TK-180 입력 5종 |
| 02_drive_references/case9/*.pdf | Drive의 case9 시험 참고자료 경로 | 지지·무관 대조군 2개 |
| 02_drive_references/tk180/* | 격리된 TK-180 시험 Drive 참고자료 경로 | 기준자료 4형식·무관자료 1개 |
| 03_scoring_specs/*.json | PC에 그대로 보관 | 평가 측이 결과 채점에 사용, 웹/Drive에 업로드하지 않음 |
| 04_results/ | PC의 결과 저장 폴더 | 각 실행에서 내려받은 결과 JSON 11개 보관 |
| acas_021_execution_record.csv | PC에서 Excel 등으로 열어 작성 | 11개 실행 행이 미리 들어 있는 기록표 |
| RUN_PROCEDURE.md | PC에서 열어 읽기 | 시험 순서·기대 결과·진단 및 채점 절차 |
| package_manifest.json | PC에 보관 | 파일 무결성 확인용, 사용자가 입력할 필요 없음 |

**결과 JSON·실행 기록표·README·명세·ZIP을 Drive 참고자료 폴더에 넣지 마세요.** 시험 데이터와 결과가 검색 자료에 섞입니다.

## 2. 실행 기록표 사용

CSV를 Excel/LibreOffice Calc로 엽니다(UTF-8 BOM 포함). 쉼표 구분 파일입니다. Excel에서 변경 후 CSV UTF-8로 저장하거나 다른 이름의 XLSX로 저장해도 됩니다. 기존 표의 첫5열은 시험 계획이므로 그대로 두고 다음을 작성합니다.

- 실행 일시: 예) 2026-11-15 17:30 KST. 실제 실행한 시간을 적습니다.
- 실행 상태: 미실행 → 완료 또는 오류. 중단했거나 실패한 실행도 지우지 않습니다.
- 실제 결과 파일명: 내려받아 04_results에 저장한 파일 이름을 적습니다. 권장 이름대로 바꾸면 대조가 쉽습니다. 원래 다운로드 이름을 유지해도 이 열로 연결할 수 있습니다.
- 비고: 자료 형식 교체, Drive 동기화 미완료, 중단, 설정 변경 등을 적습니다.
- 배포 SHA: /api/health에서 확인할 수 있으면 적습니다. 어려우면 빈칸으로 두어도 됩니다. 보고서에서 평가 측이 확인합니다.
- 스냅샷/run_id: 직접 JSON을 열어 채울 필요 없습니다. 평가 측이 확인하므로 빈칸으로 둡니다.

모델 판정이나 합격 여부를 직접 기록할 필요는 없습니다. 보고서 원문을 평가 측이 채점합니다. 토큰/비밀번호/API 키/인증서 내용은 절대 적지 않습니다. 재시도는 기존 행을 삭제하지 말고 새 행을 복사해 시험ID에 -retry1 등을 붙입니다.

## 3. case9 참고자료와 반복 실행

1. `02_drive_references/case9`의 두 PDF만 현재 운영 검증 서비스가 읽는 Drive 참고자료 경로에 파일 이름 그대로 올립니다. 검증 대상 문서로 올리지 않습니다.
2. Drive 연결 계정에 읽기 권한이 있어야 합니다. 업로드 후 동기화/색인 완료와 참고자료 스냅샷을 확인합니다. 업로드만으로 대조군 시험이 완료되지는 않습니다.
3. 기존 case9 PDF 1개를 사용합니다(이 ZIP에는 없습니다). 기존 프로젝트의 사건 설정을 유지합니다. 표준 검토, 개인정보 가림 후 전송, 같은 라우팅을 유지합니다.
4. '다시 검증'으로 신규 실행을 3회 순차 수행합니다. 결과를 열어 다운로드만 3회 하는 것은 반복 시험이 아닙니다. 세 실행 사이에는 문서·Drive 자료·모델·설정을 바꾸지 않습니다.
5. 각 결과 JSON을 `04_results/case9_fixed_r1.json`, r2, r3으로 저장하고 기록표 C9-1~3행을 채웁니다. AI 판정이 달라도 실패 실행을 버리거나 결과를 골라내지 않습니다.

## 4. TK-180 입력과 참고자료를 구분해서 사용

이 시험은 기준 자료의 지시문 분류 제외와 입력 문서의 인젝션 탐지 유지가 동시에 되는지 확인합니다. 참고자료 속 지시형 문자열을 사용자가 실행하거나 따르는 시험이 아닙니다.

- 입력: `01_inputs`의 DOCX 5개. AegisLAW의 검증 대상 문서로 올립니다. 실행마다 포함 문서는 1개뿐입니다.
- 참고자료: `02_drive_references/tk180`의 5개. Drive의 TK-180 시험 전용 폴더에 둡니다. 검증 대상 문서로 올리지 않습니다.
- 전용 Drive 폴더를 만들고 서비스 계정에 읽기 공유합니다. 폴더만 만들어서는 서비스 검색 범위가 바뀌지 않습니다. 현재 설정 `LV_RAG_DRIVE_FOLDER_ID`가 그 폴더를 가리키도록 연결해야 합니다. 이 설정은 전역일 수 있으므로 운영 업무 중 임의로 바꾸지 말고 격리 시험 환경을 우선 사용합니다. 운영 변경이 필요하면 기존 값을 보존하고 영향 없는 시간에 설정/복원합니다.
- TXT/PDF/DOCX/XLSX 기준자료를 한꺼번에 올리지 않습니다. 한 실행에는 해당 기준자료 1형식 + 무관 TXT 1개만 검색 범위에 있어야 합니다. 다른 형식은 PC에 보관하거나 검색 범위 밖 Drive 폴더에 둡니다. 실제 운영 자료는 삭제하지 않습니다.

실행 기록표 TK180-1~5: 기준자료 TXT + 무관 TXT를 고정하고 normal, visible, metadata, hidden, encoded를 각각 단독 검증합니다. 결과 이름은 normal_txt.json, visible.json, metadata.json, hidden.json, encoded.json입니다.

TK180-6~8: 기준자료만 PDF → DOCX → XLSX로 교체합니다. 형식 교체마다 동기화/재추출을 확인합니다. 입력은 같은 input_normal.docx를 사용하며 normal_pdf.json, normal_docx.json, normal_xlsx.json으로 저장합니다.

파일 이름과 문서 내용은 편집하지 않습니다. 특히 metadata/hidden/encoded 입력을 열어 다시 저장하면 시험용 속성/숨김 내용이 바뀔 수 있으므로 내려받은 원본 그대로 업로드합니다.

## 5. 결과 전달

PC의 `04_results`에 저장한 JSON 11개와 작성한 실행 기록표를 이 대화에 첨부합니다. 한 번에 압축해도 됩니다. 결과가 일부만 있으면 완료된 실행부터 전달해도 되며 미실행 항목은 기록표에 남깁니다.

추가로 Drive 진단 결과 JSON, 실제 검증에 사용한 D_tables_brief.docx/hwpx/hwp 원본3개를 별도로 전달하면 Drive 미완료 및 HWPX 문단 경계를 조사할 수 있습니다. D 원본을 고쳐 저장하지 말고 기존 실행 파일 그대로 보존합니다.

대조군·공격 입력의 합격 기준과 정확한 실행표는 RUN_PROCEDURE.md에 있습니다. 사용자는 웹 실행/다운로드/실행 기록에 집중하고, 정답·건강 상태·반복 안정성 채점은 평가 측이 수행합니다.
