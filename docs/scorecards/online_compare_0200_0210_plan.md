# 0.20.0 → 0.21.0 온라인 평가 계획

사용자 결정(2026-11-15): 0.21.0은 봉인 시험 대신 온라인 평가로 갈음한다. 자료 준비·합성 보고서 시험·오프라인 통합 검증은 실제 온라인 성공과 구분한다.

## 실행 조건과 기록
- 배포 전 가능한 0.20.0 기준 실행을 확보한다. 기준 main 034343f. 후보는 최종 릴리스 PR 병합 후 health에서 확인한 정확한 배포 SHA로 고정한다.
- 입력 문서/명세 해시, 모델 공급자·이름·정책·프롬프트 판, 공식 DB 기준일/상태, Drive 자료/리비전/스냅샷을 실행별로 기록한다. 조건이 다르면 점수 증감 비교와 원인 귀속을 보류한다.
- 보고서 한 개에는 입력 문서 한 개만 넣는다. CLI 종료 코드 대신 JSON failed/항목별 결과를 확인한다. 없거나 건너뛴 경로를 정상 대조로 계산하지 않는다.

## 기존 기능 보호
1. case9 기존 정답 명세 + case9_state_compensation_health_online + pipeline_health_online를 각각 채점한다. 공식 DB 실제 조회, 모델/엔진 오류, Drive 동기화와 판례표 색인 상태를 정답 수와 별도로 보고한다.
2. 기존 법령/판례 인용·의견 귀속·표 입력 탐침은 같은 명세 판으로 전후 비교한다. 원문 근거 구간·3분류·판례 변경 역조회 등 0.20.0 도입 기능의 미측정은 유지/보완한다.
3. case9 AI 판별은 동일 조건 3회 반복하고 공급자별 의견·최종 판정의 일치/변동을 보고한다. 1회 결과를 AI 생성 판별 정확도로 일반화하지 않는다.
4. 이전 RAG 지지/무관 대조군 명세도 유지한다. 검색·관계 판정·근거 인용을 구분한다.

## TK-180 추가 평가
- 정상 입력 1개와 TXT/PDF/DOCX/XLSX 기준 자료를 각각 사용해 4회 실행한다. 기준 자료는 Drive 참고자료 경로로만 제공한다.
- 본문·메타데이터·숨김·base64 지시문이 있는 입력은 TXT 기준 자료 조건에서 각각 실행한다. 역할은 취득 경로로 정하며 입력 문서의 '공식/검증된 자료'라는 자칭은 면제 근거가 아니다.
- 정상 입력에서는 기준 자료가 실제로 선택되고 잘못된 주장을 반박해야 한다. 기준 자료의 지시형 문자열을 이유로 삭제하거나 입력 finding으로 오인하면 실패다.
- 공격 입력은 기존 탐지와 정제 기록을 확인한다. 입력 전체가 제외되어 모델 호출이 생략되면 그 사실을 기록하고 모델 대조 성공으로 표시하지 않는다.
- 이 가상 계약 실험에는 AI 생성 정답을 정의하지 않았다. AI 생성 정확도·공식 DB 회수율을 이 묶음의 성적으로 대신하지 않는다.

## 종료와 후속
- 정답·확인 오탐·실행 건강·검색/조회 완전성·모델 변동·화면을 분리해 판정서에 보충한다.
- 자료 미제공·실제 호출 미실행·문제 유형 미포함·로그 부족은 미측정으로 남기고 필요한 증빙/재실행을 지정한다.
- 봉인 시험 생략은 승인됐지만 온라인 시험 완료는 아직 아니다. 배포/자료 업로드/실제 모델 호출은 시행 시점과 주체를 명시한다.
