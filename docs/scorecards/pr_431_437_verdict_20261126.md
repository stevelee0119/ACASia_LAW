## 2. `#431` `TK-237` — 보완 요구

**CI:** 필수 11개 전수 통과(점수 하락 게이트·은퇴 세트 비교·CodeQL 새 경고 0·Docker OCR readiness·SQLite·PostgreSQL/Celery·Redis). 실행 `45709522745`·`45709522838`·`45709522903`.

**평가 측 탐침(재실행):** `packages/rag_engine/library.py`의 `_reconcile_unread_causes()`에 평가 측 합성 캐시 페이로드 6종을 넣었다.

| 입력 | 미완독 | 분해 합 | 기록된 사유 | 판단 |
|---|---|---|---|---|
| 사유 없는 레거시(`pages 178 / completed 176`) | 2 | 2 | `PARSE_FAILED: [1, 2]` | **결함 1** |
| 확인된 빈 쪽(`blank_pages [3,4]`) | 2 | **4** | `CONTENT_NO_TEXT [3,4]` + `PARSE_FAILED [1,2]` | **결함 2** |
| 설정 차단(`config_blocked_pages [5]`) | 1 | 1 | `PARSE_FAILED: [1]` | **결함 3** |
| 저품질 1쪽 | 1 | 1 | `OCR_LOW_QUALITY: [7]` | 정상 |
| 추출 실패 2쪽 | 2 | 2 | `PARSE_FAILED: [4, 9]` | 정상 |
| 완독 | 0 | 0 | 없음 | 정상 |

1. **결함 1 — 모르는 사유를 추정값으로 채운다.** 사유가 기록되지 않은 레거시 캐시의 미완독 2쪽을 `PARSE_FAILED`(재시도 대상)로 귀속하고 **쪽 번호를 1·2로 임의 배정**한다. 실제 미완독 쪽이 어디인지, 사유가 무엇인지 모르는 상태인데 관측값처럼 기록된다. 평가 원칙(측정하지 못한 것은 못 했다고 적는다)과 `TK-238` 2항(모르면 '미집계')에 어긋난다. → 레거시는 `UNKNOWN`(미상) 사유로 적고 쪽 번호를 꾸미지 말 것.
2. **결함 2 — 분해 합이 미완독 쪽수를 초과한다.** `TK-237` 수용 기준 1항(`sum(unread_pages_by_cause) == pages - completed_pages`) 위반이다. 확인된 빈 쪽을 집계에서 제외하면서 그만큼을 `PARSE_FAILED`로 또 채워 2쪽이 4쪽으로 늘어난다. 게다가 **확인된 빈 쪽이 재시도 대상 사유로 둔갑**한다(티켓: 빈 쪽 확인은 재시도 제외).
3. **결함 3 — `CONFIG_BLOCKED` 사유가 없다.** `_ALL_UNREAD_CAUSES`는 `BUDGET_EXHAUSTED`·`CONTENT_NO_TEXT`·`OCR_LOW_QUALITY`·`OCR_UNAVAILABLE`·`PARSE_FAILED`·`READ_TIMEOUT` 6종뿐이고 **설정 차단이 빠져 있다**. 그 결과 `config_blocked_pages`가 읽히지 않고 `PARSE_FAILED`(재시도 대상)로 귀속되어, 티켓 2항("설정 차단은 재시도 대상에서 제외")을 위반하고 매 동기화 재시도 소지를 만든다.

**철회:** 평가 측 1차 탐침에서 "레거시 1회 재평가가 미작동"으로 본 것은 **탐침의 호출 순서 오류**였다. 제품 순서는 올바르다(`library.py:734` 캐시 `prior`로 레거시 판정 → 재처리 → `:739`·`:840` 결과 `parsed`에 정합 → `:841-842` 플래그). 이 지적은 철회한다.

**수용 조건:** 결함 1~3 수정 + 수용 기준 1항 정합성 시험(세 경우 포함) + 배포 후 운영 Drive 16쪽 재측정.
